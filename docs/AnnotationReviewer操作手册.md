## 0.3 标准工作流程

1. 打开视频和对应来源，核对图片身份、帧数、坐标、类别与路径。
2. 有模型任务时完成 Detection，固定 raw 输入试验后处理，再明确载入结果。
3. 用数据表、条带和 trail 定位错误段；先辨认身份错误与位置错误。
4. 使用 Edit、Trajectory、Match 或 Tracking 修复。先检查预览，确认后提交。
5. 需要时完成 Camera 稳定和 Scale 标定，检查它们与原图坐标的关系。
6. 记录 Points、Events、主体身份及核验状态。
7. 检查 History、首尾交接和来源字段，保存结果；重新打开抽查。
8. 带标注视频作为独立输出，先用短片验证显示与编码，再完整导出。

## 0.4 共同约定

- 视频图片编号从 1 开始；区间包含两端。`100-110` 为 11 帧。
- 原图坐标左上为原点，X 向右、Y 向下；框 x/y 为中心，w/h 为尺寸。
- 屏幕缩放不改变原始坐标；Camera 与 Scale 是另外的坐标/度量转换。
- 显示、候选、预览、提交、磁盘保存是不同状态。
- 标签悬停显示解释，输入框悬停显示当前内容；按钮和复选框显示操作含义。
- 百分比匹配分数、模型置信度、几何残差和位置来源不是同一种指标。
- 插值、平滑、重分配和位置保持都是带假设的处理，不能仅因视觉平滑就视为更准确的真实运动。
- 原始视频、检测输出和人工审阅结果应分开保存。恢复快照用于恢复，不能代替正式结果。

## 1.1 使用范围与输入准备

Annotation Reviewer 用于查看视频与逐帧标注，修正身份、位置和轨迹，并记录片段事件和空间标定。视频、自动标注 SQLite、Tracker 人工轨迹、raw detection cache 是不同来源；打开某一项不表示其他项已经匹配或对齐。

准备文件时，应保留原视频和标注文件。为人工审阅结果使用单独文件名；通过 File 核对实际载入路径，不仅依据窗口中相似的文件名判断片段。

| 输入 | 用途 | 核对项目 |
| --- | --- | --- |
| 视频 | 提供逐帧图像 | 拍摄片段、分辨率、首尾画面、解码帧数 |
| 结果 SQLite（旧 CSV 可导入） | 保存框、类别、ID、元数据和编辑记录 | 帧号、视频对应关系、坐标单位 |
| `.trk` 或人工轨迹 CSV | Match 的人工身份与位置依据 | 原视频是否倒放、人工帧率、capture 对齐 |
| raw SQLite 缓存 | Detection 后处理重放 | 原视频路径、已提交帧范围、上游推理参数 |
| boutlist CSV | 成批组织片段和元数据 | 字段映射、路径、记录是否唯一 |

## 1.2 启动与窗口识别

### 1.2.1 源码运行

在项目根目录打开终端，使用安装了项目依赖的 Python 环境执行 `python -m app.launch`。Windows 可使用 `start_annotation_reviewer.bat`；它切换到项目根目录并优先调用 PATH 中的 `pythonw.exe`，没有该程序时调用 `python.exe`。调试启动错误时使用带控制台的 `python`。

该启动脚本设置有运行缓存路径 `PYTHONPYCACHEPREFIX`，支持相对路径，主进程和继承环境的 Python Worker 将字节码缓存集中写入当前项目的 `PYTHONPYCACHEPREFIX`，当前在目录外的 `.pycache/`。移动整个项目后从新位置运行脚本，缓存也随新项目位置生成，但已有的缓存目录 `__pycache__` 仍需手动删除。直接从终端启动并希望采用相同策略时，在项目根目录设置该环境变量后运行程序。

源码窗口标题包含进程 PID，例如 `Annotation Reviewer GUI [12540]`，可用于区分多个同时打开的实例。加载视频或 bout 后，标题增加显示文件/bout 信息；星号表示工作数据有尚未保存修改。

### 1.2.2 发布包运行

运行发布包中的主程序。检测任务由独立 DetectionWorker 执行；不要仅复制主 EXE 后丢弃其依赖目录、预设、媒体运行时和检测子程序。发布包根目录的 `presets_detection/` 是 GUI 与 Worker 共用的预设来源。

## 1.3 打开文件的操作规程

### 1.3.1 直接打开视频与标注

1. 使用底部 Open 菜单打开视频。
2. 检查首帧、末帧和当前帧总数；索引仍在建立时留意状态提示。
3. 打开对应标注 SQLite。出现导入处理选项时核对其来源和导入方式，再执行。
4. 在 File 核对视频和各标注来源路径，在 Current frame 核对框位置与画面。
5. 至少在开头、中间、末尾三个位置检查图像和标注对应关系。

`Auto open corresponding file` 会尝试在同一文件夹下和 boutlist 中寻找对应文件，匹配到多个相关文件时会提示选择。除了确定文件是否为所需要的文件或文件版本，在载入多个来源时，来源列表与框颜色/ID 都应检查。

### 1.3.2 从 Boutlist 打开

1. 先在 Display → Boutlist fields 配好列名映射。
2. 点击 Open Boutlist，选择记录。
3. 核对视频、检测文件和人工轨迹路径；没有的来源可保持为空。
4. 检查 Start、End、Capture、人工轨迹对齐和标尺摘要。
5. 对同一文件存在多个候选记录的情形，明确选择当前 bout；不要把另一行的元数据同步到当前片段。

字段格式、示例表格及同步规程见 [Boutlist 制作与使用](#13-boutlist-制作与使用)。

### 1.3.3 关闭或更换一个来源

File 的来源选择框用于指定待操作的来源，Select 更换来源，Close 移除当前会话中对应来源的数据；它不删除磁盘原文件。关闭 raw 缓存只解除缓存关联。更换视频或关闭会话前，先结束未提交编辑并处理未保存结果提示。

## 1.4 定位、播放与视图操作

| 操作 | 效果 | 对标注的影响 |
| --- | --- | --- |
| 输入帧号并执行 Goto | 定位指定图片编号 | 不修改位置 |
| 前/后一帧 | 暂停后逐帧查看 | 不生成中间标注 |
| 首/尾帧 | 定位视频边界 | 不改变分析 Start/End |
| 播放/暂停 | 连续显示或停止 | 不提交编辑 |
| Reverse | 反向播放 | 与 Tracking 的 Reverse 分别设置 |
| Loop | 在有效播放范围边界循环 | 不复制轨迹 |
| Speed | 设置播放倍速；也是 Auto Tracking 显示速度上限 | 不改变视频 FPS 或 CSV 帧号 |
| 拖动进度条 | 定位指定帧 | 进行中的 Auto Tracking 暂停并保留待提交点 |
| Ctrl + 滚轮 | 以指针附近为中心缩放 | 不改原图坐标 |
| 中键拖动 | 平移视图 | 不平移标注数据 |
| Zoom − / + / R | 缩小、放大、重置视图 | 只改变观察方式 |

悬停进度条或轨迹可以显示定位提示；悬停本身不应作为已切帧的依据。核对画面上的当前帧号。

### 1.4.1 时间戳缺口与图片编号

识别和标注按真实解码顺序连续编号，第一张图片为第 1 帧。容器时间戳在相邻图片间跳变，不会凭空插入标注帧。例如相邻图片时间戳相差 0.756 秒，只要解码图片连续，它们仍是相邻编号。

图片索引异步建立。暂停定位在目标图片尚未确认时保留已确认画面，避免旧图像配上新标注。`Frame mapping pending` 表示图片身份仍待核验；最终保存不能用估算时间替代正式图片身份。已有 CSV 不会因打开而被猜测重编号。

mpv_gl 使用播放器时间原点与图片索引相互映射。容器秒数、播放器秒数、连续图片编号是不同概念；不能直接用任意一项秒数乘 FPS 推断另一项。后续分析若采用帧差/FPS，应明确使用连续图片时间，而不是含时间戳间隔的采集时长。

## 1.5 保存标注与导出数据表

### 1.5.1 提交与保存的区别

Tracking 的 Finish、Trajectory 的 Apply、Scale 的 Apply 将本次操作提交到工作数据；它们不会直接完成 SQLite 保存。History 记录已提交操作；恢复快照用于中断恢复，也不替代正式输出。

### 1.5.2 保存规程

1. 完成当前编辑：Tracking 用 Finish/Cancel，Trajectory 用 Apply/Discard，Scale 用 Apply 或取消；结束 Continuous 编辑。
2. 检查关键帧、轨迹两端、身份交接和元数据。
3. 点击 Save（Ctrl+S）写回当前 SQLite，文件名保持原样，不追加日期时间。旧 CSV 首次正式保存时选择 SQLite 目标，默认文件名不带日期时间。
4. 保留阶段版本或导出旧格式时使用 Save as（Ctrl+Shift+S）。默认文件名带 `YYYYMMDD_HHMMSS` 后缀；格式可选 SQLite result 或 Legacy CSV。仅此操作使用核验窗口中的 `Export only the target segment (Start–End, inclusive)` 设置，Save 始终保存完整工作数据。
5. 在核验窗口逐项记录实际核验状态；未完成的项目可以不勾选，不应为了保存而虚报核验。Confirm 后等待后台成功提示；Back 会取消保存。CSV 仅作兼容导出，详见 1.5.5。
6. 若提示回写 boutlist，核对记录和字段后选择；这与保存标注 SQLite 是不同写入。
7. 重新打开输出，抽查关键帧与元数据。

### 1.5.3 SQLite 输出范围与内容

完整保存输出工作标注及其元数据。仅输出 Start–End 时包含两端，保留原视频帧号，例如 1000–1200 的输出仍从 frame=1000 开始；范围外工作数据不因此从会话删除。

数据区表格是查看和选择界面，Save / Save as 保存的是当前工作标注，不等于把正在高亮的表格单元格导出。工作表与 raw 原始数据分表保存，不将 raw 行混入工作标注。已载入的工程或当前同一视频的检测缓存随 SQLite 保存一并纳入结果库；需要后处理结果时先在 Detection 明确 Load result。

`info_points`、`info_events`、`scale_calibration` 等承载分析元数据；完整 Scale JSON 保存在结果 SQLite，boutlist 可按字段映射同时回写简短比例摘要和完整 JSON。不要仅保留 x/y 后删除身份和来源字段，再把文件当作完整审阅工程。

### 1.5.4 结果数据库与增量保存

每个视频使用一个自包含 SQLite 结果文件，同时保存 raw 原始检测、final 工作标注、元数据和操作记录。打开该文件可审阅 final，也可在 Detection 选择同一文件作为 raw 输入重新处理。另存或移动工程不需要带走额外 raw cache、结果 JSON 或 `_edit_log.txt`。旧 CSV 没有 raw 时仅转换已有内容，不重建未保存的原始检测；旧分离式结果若引用 raw，转换时须保留原 raw 文件直至成功嵌入。

| 表 | 保存内容 |
| --- | --- |
| `frames` / `raw_detections` | 按解码顺序记录全部 raw 帧（含空帧）及上游检测，不受人工修改影响 |
| `raw_metadata` | 上游模型参数、视频指纹、类别与 raw 完成状态 |
| `reviewed_detections` | 当前逐帧工作标注、来源字段及稳定行 UID，可直接 SQL 查询 |
| `raw_sources` | 库内 raw 的来源标识与来源元数据，不依赖外部缓存文件 |
| `manual_edits` | 每次保存新增、修改、删除行的前后内容与事务编号 |
| `save_transactions` | 保存时间、事务类型及增删改数量 |
| `events` | 有序事件记录 |
| `metadata` | 视频信息、Points、完整 Scale、Camera、参数和来源信息 |
| `history` | 可显示的操作历史 |
| `history_commands` | 命令类型、完整参数、时间、说明及撤销状态；复杂参数使用 JSON 类型编码 |

内存中的 DataFrame 和编辑/撤销行为不变。Save / Save as 冻结本次保存所需的数据，由后台线程以事务同步数据库；尚未执行保存的编辑不会提前写入正式结果。数据库不会额外生成 `_edit_log.txt` 或结果元数据 sidecar。SQLite 写入期间可能存在临时 `-wal`、`-shm` 文件，由 SQLite 管理；不要在写入期间只复制主文件作为完整备份。

普通编辑再次保存到当前文件时，按稳定 UID 仅冻结新增、修改行和删除 UID，不深拷贝或暂存整张工作表；事件、元数据、命令归档和历史与工作行在同一事务提交，失败时回滚。保存期间的新编辑保留为未保存状态。首次转换、另存新库、片段导出及部分批量修改/撤销仍可能需要全量快照和比较。另一个实例已更新文件时会拒绝覆盖其新版本。

完整命令归档用于溯源；重新打开文件后，既往 History / history_commands 保持只读，不重新注入当前会话撤销栈。当前会话内保存不清空其撤销能力；`.pkl` 恢复仍沿用原机制。

旧 CSV 可打开、追加或作为来源替换。导入后另存 `.sqlite` 完成转换；原 CSV 保留。仅导出分析片段时使用独立数据库并保留原帧号，不能覆盖当前载入的全量库。

### 1.5.5 旧版 CSV 兼容导出

Save as 的 Legacy CSV 输出 UTF-8 BOM 编码的逐帧结果表，保留公开的身份、类别、来源、置信度、审核、位置、人工绑定及额外字段。视频信息、Points、Events、Scale 和 Camera JSON 写在首行对应单元格；同时生成同名 `.metadata.json`，空表也能保留这些元数据，以及 `_edit_log.txt` 可读历史。移动 CSV 时一并保留两个附属文件；范围导出包含两端并保持原帧号。

CSV 不包含 raw 检测库、行级审计和完整 history_commands，不能代替 SQLite 工程。导出后当前工作文件路径和未保存状态保持原样，不把 boutlist 自动切换到 CSV。还需保留完整修改时执行 Save。CSV 可重新导入，但未知额外列中的复杂对象会变成 JSON 文本，旧 CSV 的类型推断也可能改变前导零或空值；需要精确类型与完整溯源时使用 SQLite。

## 1.6 带标注视频导出

### 1.6.1 参数

| 设置 | 含义 |
| --- | --- |
| Export Range | 包含两端的帧区间，支持 `1-2990`、`-2990`、`1-` |
| From Start to End | 使用 Points 的分析边界；取消后恢复手工范围 |
| FFmpeg / Browse | 指定具备所需编码器的 FFmpeg 程序 |
| Encoder | 视频编码器，如 libx264 或可用的硬件编码器 |
| Preset | 对应编码器的速度、压缩效率取舍 |
| Quality | 对应编码器的质量参数；不是检测置信度，不宜在不同编码器间直接比较数值 |
| Render workers | 导出 Overlay 的 CPU 工作并行度，不是 Detection 的推理并行度 |

### 1.6.2 导出规程与检查

1. 保存工作标注，设置希望显示的框、ID、trail、Axis、Scale/网格和 Camera 补偿。
2. 在 File 打开 Settings，先设一个短区间。
3. 执行 Export，在独立进度窗口查看完成或失败信息。
4. 检查输出分辨率、帧序、颜色、拖尾方向、文字和补偿画布。
5. 确认后再导出完整范围。

取消导出不撤销标注编辑，但取消生成的中间输出不能作为成功文件。视频编码器与 Overlay 绘制后端分别工作：使用硬件编码器不意味着框和轨迹已经由 GPU 绘制。

## 1.7 典型问题的检查顺序

- **框与图像似乎错位：** 先逐帧核对图片身份、视频与 CSV 配对及索引状态，再检查 Camera 坐标变换；不要先整体平移所有框。
- **打开后没有框：** 检查当前帧是否有数据、来源是否载入、显示/类别过滤和试验图层 View 是否正确。
- **另存后帧号没有从 1 开始：** 局部输出保留原视频帧号，这是预期行为。
- **导出比播放慢：** 导出需要解码、绘制和编码；速度不受播放器实时性保证。用短片段分别检查绘制与编码配置。

## 2.1 主界面分区

播放画布显示图像与 Overlay；底部控制区负责切帧、播放、倍速和缩放；进度条展示帧位置及范围条带。右侧操作区执行编辑，数据区显示当前帧、身份、连续段、人工轨迹、显示设置和历史。右上信息区汇总当前片段与对象信息。

当前帧、已选 ID、选中表格行、操作 Range、整条轨迹和分析 Start–End 不是同一范围。执行修改前，应同时核对操作区的 ID 与 Range。Display 控制可见性，并不删除隐藏的数据。

## 2.2 Current frame

该表列出当前帧的标注。点选行与画布中的框联动；在重叠框难以直接点选时，用表格确认类别、ID、中心和尺寸。Ctrl＋单击保留多选用途；Alt＋画布单击用于 Tracking，不能当作普通多选。

**规程：** 暂停视频 → 在画布或表格选择目标 → 核对 ID/类别 → 检查对应位置 → 转到需要的操作面板。多个框重叠时，不仅依赖框颜色判断身份。

## 2.3 IDs 与 Selected ID

IDs 用于查看当前数据中各身份的概况。Selected ID 聚焦选定身份及其连续出现段，帮助定位每段首尾和 gap。实际缺失帧会把连续段分开；同一个 ID 数值不保证整段都正确对应同一个真实目标。

| 操作 | 用途 |
| --- | --- |
| 选择 ID | 显示并审阅该身份的行与范围 |
| 段首/段尾 | 快速查看缺失前后的两个端点 |
| 前/后一个连续段 | 检查重现、断轨或身份变化 |
| 下一个 gap | 找到需要插值或重新追踪的区间 |
| 画布与表格联动 | 确认当前看到的是哪个来源和身份 |

**例：静止蜜蜂暂时漏检。** 从 Selected ID 定位消失段的末帧，记录画面位置；向后切帧检查同位置是否以新 ID 出现。必要时在 Edit → Box 使用 Over time 空间框选找到这一位置出现过的身份，再用 Edit → ID 合并。

## 2.4 Manual traj 与 Binding 表

人工轨迹使用轨迹名和人工采样点；自动标注使用数值 ID。二者经 Match 对齐后才处于可比较的帧坐标上。

Manual traj 中的出现范围可能包含低帧率采样造成的 resolution gap；实际人工采样缺失形成的 GAP 与之不同。Binding 表将身份关系按段组织。选择 Binding 行时，作用范围以该行实际帧集合为准；多选使用并集，不扩大成整条身份的所有帧。

通过表格行、时间轴条带和画布诊断层交叉核对：某个自动 ID 数值出现在 Binding 行中，不意味着其全部时间范围都已被绑定。完整流程见 [Match](#7-match-操作说明)。

## 2.5 进度条、条带与悬停

当前进度位置用于播放/切帧。黄色身份条带表示已选身份的出现范围，缺口应与表格中的连续段对应。

| 场景 | 条带用途 |
| --- | --- |
| Merge ID | Target 蓝色、Source 绿色，重叠位置红色，用于识别同帧冲突 |
| Tracking | 当前会话新增范围绿色；Delete 待删范围黑色；重叠待删部分红色，仅在 Tracking 页显示 |
| Trajectory | 标示本次编辑区间，便于确认 A/B 端点与当前帧 |
| Match | 将绑定段与人工轨迹出现范围对照，辅助定位段和表格行 |

轨迹点选开启时，指针附近最近的可选点显示约 10 px 圆环及 `class ID (frame)`。圆环使用 ID 颜色，文字使用该处实际 trail 颜色，进度条同步标示对应帧。点击定位到该帧，不直接改变轨迹坐标。

可选范围由 before/after picking 设置限制；trail 画出的长度与允许点选的时间范围是不同设置。某方向 trail 已关闭时，该方向不可依靠隐藏轨迹点选。

## 2.6 Box 与文字显示

| 设置 | 操作效果 |
| --- | --- |
| Box / Point | 矩形框或中心点的呈现方式；不改变存储的 W/H |
| 线宽、点径、填充、透明度 | 改变显示清晰度；过大可能遮挡目标 |
| IDs / Confidence | 显示身份或可用置信度；检测置信度不同于 Tracking 匹配 Score |
| While playing | 控制播放期间是否保留相应标签，便于平衡可读性与速度 |
| ID 字号、字重、轮廓 | 使文字适应明暗背景 |
| ID 颜色、统一颜色、避让颜色 | 区分身份或增强对比；颜色不是身份记录本身 |

Tracking 当前帧的待提交框带双对角线 `⊠`，用于区别于普通已提交框并显示中心。不能依据它在画面上已出现，就认定已完成 Finish 或磁盘保存。

## 2.7 Axis 与 Metric grid

Axis 提供显示坐标轴；原点设置可引用 Hive 或指定坐标。原点改变不等同于把 CSV 中全部对象移到新原点。

Metric grid 按 Scale 标定结果绘制物理间距网格。网格间距、外观和锚点影响呈现；Scale 类型决定像素空间中网格是否等距、是否收敛。未提供足够二维约束时，网格不能被解释为已测得完整平面透视关系。

**例：斜拍墙面。** 同为 1 cm 的网格间隔在图像上可能远处更窄、近处更宽。应先在 Scale 检查模型与约束，再用网格观察其合理性；不得为了让网格“看起来方正”而填写未知真实角度。

## 2.8 Trail before 与 Trail after

### 2.8.1 长度与对象范围

before 表示当前帧之前，after 表示之后。Frames 指显示帧数，All 使用可用的整个相应方向范围。Always trail IDs 可固定显示指定身份；Pin 将选中身份加入，Clear 移除相应固定显示项。固定显示只影响画面。

### 2.8.2 外观参数

| 参数 | 含义 |
| --- | --- |
| Simple trail | 使用统一外观，适合检查长段轮廓 |
| 渐变起止颜色 | 分别控制靠近当前帧与远端的颜色 |
| 起止 alpha | 靠近与远端透明度，0 透明、255 不透明 |
| 起止 width | 靠近与远端的显示线宽 |
| ID colors / unique colors | 使用身份颜色或统一自定义颜色 |
| far HSV | 对远端颜色作饱和度和亮度调整 |
| Style | 实线、虚线、点线及支持的波浪等样式；不改变实际坐标点 |

渐变可帮助判断运动方向与时间先后；它不是速度数值图。看到一条连接线不能证明中间每帧都有真实检测，仍需查看实际行和来源字段。

### 2.8.3 实例：定位短暂串 ID

1. 暂停并选中目标，开启适当长度的 before/after trail。
2. 沿异常突刺悬停，读取对应帧号并点击定位。
3. 在异常帧前后逐帧检查图像，判断是位置错误还是身份交换。
4. 位置错误用 Tracking/Trajectory，身份交换用 Swap 或 Match 修复。
5. 修复后播放前后交接段，并核对实际框和轨迹来源。

## 2.9 审阅顺序与验收

优先确认视频与标注同步，再检查身份，再检查位置和几何。对每条关键轨迹依次检查起点、连续段、gap、交叉/遮挡、终点。显示隐藏、颜色一致、线条平滑都不能代替数据正确性检查。

最后确认：选中范围与执行范围一致；缺失段已说明或补齐；身份没有同帧重复；插值与人工估计仍保留来源；需核验的状态已按实际情况记录。

# 3 Detection 操作说明

[返回总目录](#0-引言)

## 3.1 目的与启动检查

Detection 使用模型产生逐帧候选，再按所选模式保存原始检测或执行稳定身份后处理。开始前核对视频、模型、类别、输出目录和设备。Tracking 模板匹配与此模型推理为不同功能。

## 3.2 控制区

Detection 分成两个子选项卡：

- **Control**：输出目录、模式、Settings、Batch、Choose raw、Start/Pause/Stop、Load、进度，以及设备、half、批大小、管线、等待时间、Workers 和 Follow progress。
- **Inference**：只放模型信息和 YOLO 参数。Model 下方显示模型家族、训练尺寸及 Training info 按钮。读取在独立进程中完成，不进行推理。只加载可信的 .pt 文件；其他格式或不存在的元数据会显示不可用，不编造。

输入框禁止滚轮改值；选项标签悬停显示英文解释，输入框悬停显示当前内容。界面设置保存到项目沿用的 settings.ini。运行中的任务不热切换参数。

## 3.3 先区分两类参数

### 3.3.1 Inference：参数变化与重新推理

- **Conf floor**：YOLO 上游置信度门槛。降低可保留更多候选，也可能增加误检及计算量。
- **IoU**：YOLO 上游 NMS 阈值，不是后处理的匹配 IoU 阈值。
- **Image size**：推理尺寸，使用 32 的倍数。
- **Max detections**：每帧上游输出数量上限。密集画面需自行确认是否足够。
- **Augment**：测试时增强，默认 False；支持情况依赖模型，可能更慢。
- **NMS**：Auto (None) 保留模型默认；True 使用普通 NMS；False 使用原生无 NMS 检测头，需要模型支持。无 NMS 模式下 IoU 灰显。旧版 Ultralytics 内部通过 end2end 转换，不能把其仅供导出的 nms 参数当作推理开关。
- **Agnostic NMS**：默认 False；普通 NMS 中表示跨类别抑制，支持的端到端检测头中对应跨类别输出选择。
- **rect=True** 固定。Image size 在编辑完成时近似到最近的 32 倍数，中点向上；特殊模型若步长更大仍可能由后端进一步补齐。
- 模型、推理管线及设备等同属上游设置。

Training info 展示权重保存日期、有效的 checkpoint epoch、训练日志最后 epoch、可读取的累计耗时和训练参数。checkpoint epoch 可能被清理；训练日志可能比 best 权重训练得更晚，二者不会混称。耗时按日志的累计秒数字段计算，不能读取则不显示；不以训练 epoch 设定值虚构已完成训练时长。

已有 raw 缓存不会因为修改这些值而改变。回放恢复缓存记录的上游信息，不调用 YOLO。新参数会写入新 raw 的元数据。

### 3.3.2 Postprocess settings：可直接用 raw 试验

这些参数只影响自定义稳定 ID、恢复、位置生成及最终清理，不需要重新跑 YOLO。但被上游阈值/NMS 丢弃的检测无法从 raw 中找回来。

## 3.4 三种运行模式

| 模式 | 用途 | 输出 |
| --- | --- | --- |
| Raw only | 先完成昂贵的推理，以后再调后处理 | 一个 SQLite 工程，含 raw 与元数据，尚无 final 工作行 |
| Raw + Postprocess | 推理并同时生成初版后处理结果 | 一个 SQLite 工程，含 raw、final、参数与来源 |
| Replay | 使用已有 raw 重新生成结果 | 新结果及 sidecar；原 raw 只读 |

单视频和 Batch 都支持三种模式。批量任务在各自实际启动时读取设置，已运行任务不会改参数。暂停/停止会提交已完成的缓存帧；未完成的尾部不是完整视频。

Raw 是 YOLO/tracker 已输出的检测，保存在自定义后处理之前；不是网络未阈值化张量。旧 CSV 已筛掉一些检测且可能含插值行，不能充当完整 raw。旧 CSV 仍可导入审阅，正式结果保存为 SQLite。

Follow progress 用于跟随识别帧。识别中的框是临时结果；结果库运行时批量保存临时后处理行；结束时事务写回全片清理后的数据，以 metadata 中的 state 判断是否完整。速率 `0.45x` 表示每秒约处理 0.45 秒视频，暂停时间不计入活跃处理时长。

正常检测完成时，空白审阅会话可以自动载入结果；已有标注仍需确认。Load 保留用于正式载入。不要把只读预览当成已经写入审阅数据。


## 3.5 双置信度规程

Inference 中的 **Conf floor** 是保留候选框的低阈值；**Conf main** 是正常匹配及创建身份的高阈值。在 Postprocess settings 表格中开启 **Dual confidence** 后，高低阈值之间的观测只辅助已确认身份；关闭时 Conf main 灰显，按 Conf floor 单阈值处理。

主检测先完成所有关联，再用低置信观测补充仍未匹配的身份。当前实现要求 raw ID 相同、类别一致、距离和尺寸合理、无明显邻蜂或重复检测竞争。低置信框不创建新 ID；它们是真实观测，不是插值，保留观测坐标和原置信度。诊断路径显示 `low_conf_support`。允许补充短缺口仍受 Gap recovery 控制；回填估计位置另外受插值开关控制。

**Low Conf Max Seconds** 限制自最后一次主检测之后，连续仅靠低置信观测支撑身份的时长，默认 1 秒。超过后停止低置信延续，不无限拖住旧 ID；出现主检测后重新计时。这是保守试验起点，不是已验证的最优阈值。已有的 Low Conf Hints 只是重连评分线索，不能替代 Dual confidence。

调整 Conf main 可直接回放。降低 Conf floor 只能利用 raw 缓存中已存在的候选；YOLO 或其跟踪器已经丢弃的框不能凭回放恢复，需要重新推理。回放可按已有缓存中保存的配置重现相应分流行为。GUI 编辑会话采用以下开关语义：关闭时使用单阈值；Apply 后保存 `confidence_policy=dual_stream_v1`。不会重写旧 sidecar、CSV 或替换当前选择的场景预设。


## 3.6 单视频操作 protocol

1. 在 Inference 选择模型，查看 Training info 和类别；确认 Conf floor、Conf main、IoU、Image size、Max detections、Augment 与 NMS。
2. 在 Control 选择设备、half、批大小、管线和输出目录。
3. 先用短视频或一次试运行核对目标尺度、类别、候选数量及实际设备状态。
4. 选择 Raw only 或 Raw + Postprocess 后 Start；需要暂缓时 Pause，终止时 Stop。
5. 完成后核对结果与 sidecar。已有审阅数据时，通过 Load 的确认流程载入结果。
6. 调整后处理参数时，使用相同 raw 回放以隔离上游变化；详见后处理测试说明。

GPU 是否实际使用，以 worker 的设备探测与运行信息为准。half 受设备、模型和运行时支持限制；批量和管线影响吞吐及内存，不能保证更大数值更快。CPU Workers 不等于多个独立 GPU。缓存回放不重新执行模型，改变模型参数不会重算已有 raw。

## 3.7 Batch

打开 Batch，Add videos 添加输入；Replay 时选择对应 raw 缓存。设置统一输出目录或 Output beside video，指定并发上限或 Auto，再 Start processing。Delay 将所选待运行项目移到队尾，Pause/Stop 控制所选任务；没有选中项时作用于对应全队列。各任务实际开始时读取设置，已经运行的任务不热切换参数。

并发会叠加显存、内存和磁盘需求；先用少量视频验证。单个任务失败不应被当作完整检测结果；检查每条任务的状态和输出目录。Removal 从列表移除项目，不代表删除原始视频。

## 3.8 结果解释

稳定 ID 是后处理关联结果，raw ID 是上游跟踪身份。数值相等不能保证两个不同试验里的 ID 对应同一目标。观测位置、短期 hold、回填插值和人工修改应按来源字段区分，不能只看框是否平滑。完整后处理参数保存在配置快照中，便于相同输入下复核。

## 3.9 Control 参数逐项解释

| 参数 | 用途 | 调整后检查 |
| --- | --- | --- |
| Device | 选择请求的运行设备；auto 由后端解析 | 实际探测设备与显存，不只看选择文字 |
| half | 使用设备/模型支持的半精度推理 | 输出是否正常、显存及吞吐是否改善 |
| Batch size | 一次模型批量处理的帧数 | 吞吐、显存峰值和单帧等待 |
| Pipeline | 选择推理/整合管线 | 当前模式是否支持所选并行参数 |
| Batch wait | 部分批次最长等待秒数；0 等批满或视频结束 | 小批次延迟与吞吐 |
| Workers | 支持管线的并行预测工作数；进程管线可各加载一份模型 | 多模型显存和 CPU 竞争 |
| Follow progress | 播放画面跟随识别进度 | 是否仍方便检查关键区间 |
| Output directory | 当前检测结果位置 | 空间、写权限和实际新建运行目录 |

Batch 的并发任务数与单任务 Workers/Batch size 是不同维度。两层同时增大可能显著增加显存，不宜以“设备占用未满”为唯一依据。

## 3.10 Start、Pause、Stop 与批量选择

Start 启动当前设置对应的任务；Pause 暂停活动任务，保留其进程和资源；Stop 终止当前运行。停止后再次启动通常建立新运行，不等于在原缓存尾端无条件续写。

批量窗口选中项目后，Start/Pause/Stop 优先作用于所选项目；无选择时按全队列执行。Start 可把所选待运行任务排到前面，Delay 将所选待运行项排到后面。移除正在运行的项会先停止，移除队列条目不删除磁盘输出。

## 3.11 完整实例：保留候选后再调关联

1. 选定可信模型，在 Inference 配好 Conf floor、NMS 与尺寸。
2. 以 Raw only 完成一次推理，确认缓存覆盖范围。
3. Choose raw 载入这一缓存，打开 Settings。
4. 固定上游不变，比较不同 Conf main、身份恢复和位置生成开关。
5. 用同一原始观测跨 Trial 比较，满意后 Full replay。
6. 核对全片结果再 Load，进入人工审阅并 Save as。

**两阈值数值例：** Conf floor=0.10、Conf main=0.40，且启用 Dual confidence。0.70 的主观测可参与正常关联；0.25 的保留观测只能在约束满足时支撑已有身份；0.08 若在上游已丢弃，则不会出现在缓存中。把 Conf main 改为 0.30 可以重放；要找回 0.08 候选则需要降低上游阈值后重新推理。

## 3.12 验收项目

检查视频与缓存身份、实际设备、上游参数快照、缓存是否完整、输出位置和 raw/stable ID 区别。对密集目标、遮挡、快速位移及类别冲突分别抽查。模型检测置信度不是身份正确率；更长稳定 ID 或更平滑轨迹也不能直接证明后处理更准确。

## 4.1 输入与状态边界

输入为同一视频的 raw 缓存；局部试验重放候选并重新建立身份状态。它不修改已审阅 SQLite，也不重新运行 YOLO。设置窗口可与播放器同时操作。进入试验前处理未提交编辑；试验图层为只读检查，正式标注编辑应返回审阅图层。

## 4.2 标准试验规程

1. 打开视频，在 Control 点击 **Choose raw**，选择同一视频的缓存。
2. 把播放器停在想观察的时间，点击 **Settings**。
3. 在 **Before (s)** / **After (s)** 输入当前锚点前后要看的秒数，默认各 30 秒。播放不会自动改变锚点；点击 **Center here** 才改为当前帧。
4. 修改表格 **Current** 列。有效修改停止 500 毫秒后自动计算；也可点 **Update**。
5. 播放器顶部一行 **Updating preview…** 表示正在更新。计算期间仍显示旧结果；新请求会取消旧请求，迟到结果不会覆盖最新请求。
6. 完成后，原播放器直接显示新结果，不需要再点 Load。逐帧或循环查看，继续修改 Current。
7. 满意时点击 **Apply / Close** 保存参数；需要正式结果时先做 **Full replay**。

预览计算存在延迟：目标密集、区间较长或首次解码时仍可能等待。应以 Showing 列及完成状态确认画面对应的参数。失败或停止时保留旧结果，并在窗口状态栏说明。

## 4.3 表格与暂存方案

表格四列分别是：

- **Parameter**：参数项目，悬停看作用。
- **Current**：当前草稿，可编辑；自动预览使用这一列。
- **Reference**：可编辑的参考副本；与 Current 不同的值用浅黄色标出，不改写其来源文件或 Trial。
- **Showing**：画面正在使用的结果配置，只读；与 Current 不同的值标浅红。计算中保留旧画面时，此列仍显示旧结果参数。Raw / Off 没有后处理配置，显示破折号。

布尔只读值使用 √ / 空白。数字去掉多余末尾零；表格不显示选中单元格的强调边。

Preset / Trial 下拉框可选择预设文件或暂存 Trial，复制到 Reference。**选择来源、编辑 Reference 都不修改 Current**；点击 **Use reference** 才复制到 Current 并更新预览。选择另一个来源会重置 Reference 临时副本；想保留一组效果，先 Use reference 完成预览，再 Keep trial。完整配置中未在表格暴露的参数会保留，不会因编辑几个可见参数而丢失。

**View** 控制播放器看什么：

- **Current**：最近完成的当前试验结果；计算中可能是上一版。
- **Trial 1…5**：点击 Keep trial 保存的结果和参数。切换 Trial 同时在 Reference 列展示它的参数，但不覆盖 Current。
- **Raw**：上游框和 raw ID，不是后处理稳定 ID。
- **Off**：关闭试验图层，返回原审阅图层；不卸载 raw。

**Keep trial** 只能暂存已经完成且未过期的 Current，最多五组；第六组挤出最旧一组。Trial 仅在当前视频会话中保留，不是长期工程存档。建议在换视频前用 **Save JSON** 导出想保留的参数。

**Open JSON** 把完整参数快照复制到草稿；**Save JSON** 导出当前完整参数，不运行算法，也不载入/覆盖标注。保存文件是显式操作，之后点 Cancel 不会删除该文件。

## 4.4 Apply 与 关闭窗口

- **Apply / Close**：提交 Current、前后秒数、循环等选项到 settings.ini，并保留预览。
- **Cancel / 关闭窗口 / Esc**：丢弃这一轮草稿及区间修改，取消未完成请求，恢复打开窗口前的设置和预览。
- 已明确执行 Full replay/Save JSON 生成的独立文件不会被取消操作删除。
- 只有正式 **Load result** 才将结果载入审阅数据；未保存标注的保护仍生效。

设置窗口是非模态，可以开着它播放、定位视频。自动预览不修改已审阅 SQLite。

## 4.5 单只观察、恢复标记和事件

点击试验图层中的真实检测框：

- 显示简短英文摘要，包括 stable ID、raw ID、观测/估计属性、检测序号及记录到的关联/拒绝原因。
- 聚焦对应的上游观测 `(frame, det_index)`，只显示该观测在当前方案中所属轨迹；后端仍计算所有目标，不以单只输入改变竞争关系。
- 换 Trial 时重新通过该观测寻找对应轨迹，不把不同方案里数值相同的 stable ID 当作同一只。
- **Previous event / Next event** 跳到聚焦轨迹记录的前后关联事件；**Clear focus** 恢复显示全部框。

若某方案压掉了锚点观测，可能没有可对应轨迹，此时可 Clear focus 后重新点框。估计框没有可靠原始观测锚点。

标签 **R** 标记发生跨缺失帧恢复的那一帧；**~** 表示估计位置而非真实检测。R 只说明执行了恢复，不保证恢复正确。普通相邻帧关联无需每帧特别标记。Raw 图层仍显示 raw ID；点击时可附带 Current 对同一个原始检测的诊断，并明确标注 Candidate diagnostics 及 stale 状态，不把 raw ID 当成稳定 ID。

局部画面没有框时，先确认当前帧处于窗口显示的 Frames 范围，再确认是否启用了聚焦，不要立即认定为漏检。

## 4.6 身份连续性与几何位置控制

框坐标变化和 ID 切换是两个不同问题。

| 参数 | 作用与代价 |
| --- | --- |
| Preserve observed boxes | 真实观测框保持上游坐标，禁用会移动/缩放观测框的兼容调整；不能消除 YOLO 本身抖动 |
| Gap recovery | 所有跨缺失帧身份恢复的总开关；关闭仍保留相邻帧关联，但更容易断轨 |
| Position hold | 缺失时是否短暂输出占位框；与身份记忆分开 |
| Gap interpolation | 恢复后是否回填估计框；与恢复身份分开 |
| Clear raw aliases | 换 raw ID 后释放旧映射，避免残留归属参与后续竞争 |
| Guard missing owners | 防止缺失目标仅靠旧框压掉新观测 |
| Guard raw continuation | raw ID 没变也检查几何和身份竞争；更严格可能断轨 |
| Guard gap assignment | 对缺失恢复做歧义检查，不额外收紧普通相邻帧匹配 |
| Conservative assignment | 对所有关联使用严格检查，可能增加断轨；不是前四项保护的必要总开关 |
| Overlap ID reuse | 允许仅基于重叠路径复用身份，有串 ID 风险 |

General relink 只是一个恢复路径。关闭它后，raw ID 延续、短间隔匹配、drop、静止、遮挡、全局路径仍可能恢复身份。要禁止全部跨缺失恢复，用 Gap recovery。

DORMANT_STATIC_SECONDS、HORNET_IDENTITY_MEMORY_SECONDS 控制记忆多久；MAX_LOST_SECONDS、HORNET_POSITION_HOLD_SECONDS 控制占位多久。插值上限另外由 MAX_INTERP_SECONDS、MAX_DROP_INTERP_SECONDS 及相关开关控制。

建议先固定上游和其他参数，只比较 Preserve observed boxes，再分别观察恢复开关和歧义检查的影响。不要同时收紧所有阈值；错误续接减少时也要观察断轨和真实跌落恢复损失。保留原始坐标不等于已经解决身份交换。

## 4.7 预设与完整参数快照

- **General.json / General**：通用基础关联，关闭墙面物种规则和补位置类操作，不假设目标都属于蜜蜂/胡蜂；类别名称来自模型或 raw 元数据。
- **bee_hornet_revised.json / Bee / Hornet wall**：保留墙面场景原有类别保护及恢复规则，保持观测坐标，释放旧归属并增加独立保护；保留短位置 hold，默认不做恢复后的回填插值。

这些是可试验的起点，不是所有视频的最优参数保证。

程序从根目录 presets_detection 文件夹读取 JSON 的 preset 字段作为名称，并读取默认标志；不在代码里规定场景名。旧 Default 标识由文件内兼容别名识别。已保存的完整旧参数快照按其记录值恢复，不会因为同名预设文件更新而悄悄改算法。采用文件预设时，在 Preset / Trial 选择来源，再点击 Use reference 和 Apply / Close。

settings.ini 保存的是参数和选择，不是 Python 算法。预设为数据文件，不执行任意 Python 代码。

## 4.8 局部试验、全片结果和文件安全

局部试验会加入至少 15 秒前置上下文，身份记忆更长时相应增加；末尾增加 2 秒。仅显示所选区间。有限上下文不能保证 stable ID 编号和最终清理与全片一致。

**Full replay** 从缓存起点计算到最后已提交帧并执行最终清理，自动显示结果，同时生成独立结果 SQLite。缓存不完整时只处理已有范围，不补造缺失帧，也不自动重新跑 YOLO。

选择 `实验5/csv` 为输出目录时，试验结果写入同级 `实验5/postprocess_lab`。局部试验保存临时 preview.sqlite；全片结果保存一个自包含 SQLite 工程，包含 raw、final、试验预览与诊断表，metadata 保存配置与 provenance，不另存 result.json。可重复使用的 features.sqlite 属于试验工作缓存，不是最终结果文件。原视频、boutlist、原 raw、既有审阅 SQLite 保持不变。

常驻回放进程复用 raw 输入和与关联参数无关的图像特征。每次试验都重置身份状态；不会复用旧参数算出的轨迹。解码缓存有限容量，不能保证长窗口即时完成。

最终审阅或导出前，请用 Full replay 并自行检查身份连续性。仅看框平滑、ID 总数减少，不能证明关联正确。


## 4.9 参数分组与验证

模型的 Conf floor 决定 raw 包含的候选下限。Conf main 和 Dual confidence 决定回放如何使用已有候选；Low Conf Max Seconds 限制仅靠低置信度观测的连续支撑时间。前者变低时通常需要新推理，后者可在缓存包含相应观测时直接回放。

表格显示模块开关和主要参数，英文参数说明读取当前预设 JSON 的 `tips` 字典。相应内容为空、缺失、格式不正确或读取失败时显示 `--`；修改预设文件后重新打开参数窗口读取。输入控件悬停仍只显示当前值。未显示的配置项仍保存在完整参数快照中。改变参数前记录 Current；用 Keep trial 留住已完成结果，按同一个原始观测对比不同试验。

**例：静止蜜蜂短时遮挡。** 固定 raw，先比较 Gap recovery 开关。恢复身份与生成占位框分开：需要保留身份但不猜测位置时，可保留恢复及身份记忆而关闭 Position hold 和 Gap interpolation。查看恢复处 R 标记和源观测，确认没有接到邻近蜜蜂。

**例：低置信度尾部。** 开启 Dual confidence 后，高阈值检测建立身份，处于两阈值之间的观测仅在类别、raw ID、几何及竞争条件允许时支撑已有身份；不会凭低置信点创建无限持续的新轨迹。超过 Low Conf Max Seconds 时停止这种延续，主检测出现后重新计时。

局部窗口中的 ID 编号不作为全片身份编号依据。最终参数必须 Full replay 后核对全片结果，再正式 Load result、审阅和保存。

## 4.10 模块开关补充说明

| 开关 | 作用及解释 |
| --- | --- |
| Dual confidence | 主、低置信观测分流；低置信观测不独立建立新身份 |
| Species rules | 使用蜜蜂/胡蜂等场景规则；通用场景应核对类别含义 |
| Drop relink | 针对跌落运动线索的恢复路径 |
| General relink | 普通重现关联路径；关闭不等于关闭其他恢复路径 |
| Duplicate suppression | 抑制重复候选，需检查近邻真实个体是否被误抑制 |
| Hornet occlusion | 胡蜂遮挡相关保护和恢复规则 |
| Dormant static relink | 利用长期静止历史重连短暂消失目标 |
| Capped interpolation | 按插值时间上限限制估计跨度 |
| Separate identity memory | 区分身份可恢复时间和输出占位位置的时间 |
| ROI similarity | 使用局部图像相似度辅助身份关联，增加图像处理工作 |
| Low conf hints | 用低置信线索辅助评分，区别于 Dual confidence 的直接支撑路径 |
| Global relink | 对多个待恢复目标进行全局竞争匹配 |
| Post ignore | 执行相应后处理排除规则 |
| Ghost rollback | 回退短促、与宿主高度重叠的疑似幽灵轨迹；需检查真实短轨迹 |

其余保护、位置保持、插值与观测保真开关见本册“身份连续性与几何位置控制”。开关之间存在前提关系：总恢复已关闭时，某个具体恢复路径打开也不能凭此跨缺失接续。

## 4.11 可见主要数值参数

| 参数 | 单位/控制内容 | 调大时主要影响 |
| --- | --- | --- |
| MAIN_DET_CONF_THRESHOLD | 0–1 主检测阈值 | 主观测更少，低置信支撑占比可能增加 |
| LOW_DET_CONF_THRESHOLD | 0–1 可用低阈值，必须不高于主阈值 | 排除更多低分候选 |
| LOW_CONF_MAX_SECONDS | 秒，低置信单独支撑上限 | 允许更长的低分延续 |
| MAX_LOST_SECONDS | 秒，普通丢失/占位相关窗口 | 更长保留，需检查拖影 |
| RETRIEVAL_WINDOW_SECONDS | 秒，检索重现候选窗口 | 更多历史候选和错误续接机会 |
| DORMANT_STATIC_SECONDS | 秒，静止身份记忆 | 保留更久，不等于每帧输出框 |
| HORNET_IDENTITY_MEMORY_SECONDS | 秒，胡蜂身份记忆 | 更长缺失后仍可能关联 |
| HORNET_POSITION_HOLD_SECONDS | 秒，胡蜂位置保持 | 增加估计占位，不提高图像实测量 |
| MAX_INTERP_SECONDS | 秒，普通补间跨度上限 | 更长缺口可产生估计行 |
| MAX_DROP_INTERP_SECONDS | 秒，跌落补间跨度上限 | 允许更长跌落桥接 |
| STATIC_MAX_DISPLACEMENT_FACTOR | 相对目标尺度的静止判据 | 更宽松地归为静止历史 |
| STATIC_RELINK_DIST_FACTOR | 相对尺度的静止重连距离 | 扩大候选范围，邻蜂歧义增加 |
| STABLE_MATCH_DIST_FACTOR | 相对尺度的稳定关联距离 | 接受更大位移 |
| STABLE_MATCH_IOU_MIN | 最小重叠约束 | 更严格要求重叠，快速目标可能断轨 |
| MATCH_COST_GATE | 关联代价门限 | 按当前代价定义放宽接受范围 |
| ASSIGNMENT_AMBIGUITY_MARGIN | 候选竞争差异要求 | 更严格地拒绝不明确对应 |
| ADJACENT_RESIDUAL_FACTOR | 相邻关联几何残差容许比例 | 容许更大残差，需检查串号 |

时间参数按当前视频 FPS 转换为帧相关窗口，实际边界还受模块开关、其他几何/类别门限和已确认状态限制。单个参数不是“漏检容忍度”的总开关。

完整 JSON 含有更多未在表格暴露的高级参数。编辑可见项不会丢失它们；更改高级值时应保留完整快照，并按同样的局部预览与全片重放流程验证。

## 4.12 对照实验实例

### 4.12.1 区分几何抖动与身份跳变

先固定所有关联门限，只比较 Preserve observed boxes。若抖动仍跟随 raw 框，问题主要来自上游几何；再收紧重连门限不能修复像素位置。若位置稳定但 ID 交换，应检查竞争和缺失恢复诊断。

### 4.12.2 静止蜂被另一只经过

保留一份 Current 为 Trial；分别比较 Guard missing owners、Clear raw aliases 和 Guard gap assignment。点击同一原始观测跟踪目标，检查原静止身份是否在旧位置压掉新观测、旧 raw 映射是否残留，以及恢复处 R 是否接错。比较结束后 Full replay 验证全片。

### 4.12.3 空缓存尾部

raw 只提交到第 8000 帧时，Full replay 只能处理已有范围。预览窗口越过尾部没有框并不代表模型在后半段全部漏检，应先检查缓存完成状态，再决定重新推理或仅分析已完成片段。

## 4.13 预设中的算法流程

每个预设 JSON 的 `pipeline` 描述三个执行序列：

| 序列 | 默认顺序 | 作用 |
| --- | --- | --- |
| frame | prepare → camera_motion → association → low_confidence → observed_rows → lost_tracks → publish | 每帧的候选准备、运动估计、身份关联、低置信延续、结果行、丢失维护和发布 |
| relink | hornet_resume → general_relink → drop_relink → static_relink | 未分配候选的恢复策略优先级；首个成功策略终止本次搜索 |
| finalize | trim_terminal → ghost_rollback → post_ignore → dedupe → first_last → sort | 全段末尾的尾部清理、回滚、后处理、去重、首尾标志与排序 |

frame 与 finalize 具有数据依赖，不能任意重排；缺失、重复、未知阶段或违反依赖时，加载配置会报错。relink 可以调整策略顺序，但仍受相应模块开关和分数/几何门限约束。所有算法共享当前视频的身份记忆。

**例：** general_relink 与 drop_relink 都能提出候选时，前者排在前面会优先采用前者；交换顺序可能改变身份恢复结果。应在相同 raw 缓存上进行对照测试，核查实际输出再选择配置。现有预设保持原先的计算顺序。

## 5.1 范围与共同输入

本册说明 Box、ID、Interpolate、Swap。Trajectory、Scale、Points/Events 各有独立分册。Edit 顶部的 ID、Range、x/y/w/h 为操作输入；它们与当前画面选择相关，但输入本身不立即改写标注。

ID 可输入指定身份；All IDs 将范围扩展到全部身份。Range 使用视频帧号，支持单帧、闭区间及逗号分隔多个区间，例如 `120-150,180,200-230`；All frames 指全部有效帧。批量操作前先检查这两个开关，避免把本意的一帧修正应用到整个视频。

x/y 为框中心、w/h 为尺寸，单位是原图像素。仅改变显示缩放或平移不会改写这些值。Link selection 控制一般选择与相关身份/范围的联动；显式输入后应以最终显示的 ID/Range 核对操作范围。

## 5.2 Box：按空间范围选择

### 5.2.1 选择规则

| 设置 | 规则 |
| --- | --- |
| Center | 框中心落入皮筋框时选中 |
| Contained | 整个标注框包含在皮筋框内时选中 |
| Intersects | 标注框与皮筋框相交时选中 |
| Accumulate | 将新结果加入已有选择，而不是替换 |
| Over time | 在时间范围内查找进入此空间区域的标注，不只看当前帧 |

点击 Select 后在画布拖出矩形。范围选择只筛选对象和帧，不修改框坐标。密集目标应优先使用较小区域，并检查结果表；区域中不同时间出现的目标不一定是同一个体。

### 5.2.2 实例：静止蜜蜂消失后换 ID

1. 找到蜜蜂最后存在的帧，确认其位置。
2. 在 Box 选择 Center，勾选 Over time，在该位置画一个小范围；必要时限制 Range 到消失前后。
3. 在 IDs/Selected ID 查看选出的旧、新身份及连续段。
4. 跳到旧身份尾帧和新身份首帧，检查目标是否确为同一只。
5. 进入 ID，将旧身份作为 Target，新身份作为 Source；确认后 Merge。
6. 需要填补消失段时启用 Interpolate between，再逐帧检查中间区域是否仍合理。

## 5.3 Box：Change position

### 5.3.1 四种几何模式

| 模式 | 交互 | 保持的量 |
| --- | --- | --- |
| X/Y | 指定新中心或移动位置 | W/H |
| W/H | 调整框尺寸 | 中心位置 |
| X/Y/W/H | 拖动中心/边缘进行综合调整 | 未操作部分按交互约束保持 |
| Draw | 在画布重新画出目标框 | 用新矩形确定中心和尺寸 |

先选择 ID 和 Range，再点击 Change 进入相应模式。检查画布的交互框及顶部几何输入，确认新位置后执行 Apply。框的中心位置使用原图坐标；Camera 稳定视图会经过显示与原图之间的转换。

### 5.3.2 Continuous、Auto next 与退出

Continuous 未勾选时，一次成功修改后退出编辑模式。勾选时可连续修改；Auto next 只在 Continuous 有效时用于成功操作后切到下一帧。

在编辑模式中，未设置所需位置时点击 Apply 会退出，不生成空几何修改。ESC 退出交互。编辑中切换 Continuous 的勾选状态也结束当前编辑模式。结束时应核对实际已应用的点；退出交互不应被当作撤销已经完成的操作。

Continuous 会话中使用轻量局部撤销，可逐步退回本次位置指定；会话结束后的 History 操作按该会话的提交边界管理。输入框正在编辑文字时，Ctrl＋Z 优先属于文字编辑，不宜用来判断轨迹撤销状态。

### 5.3.3 Confirm 与类别修改

Confirm 为三态控件，控制 Change position 与 Delete 执行前是否弹出确认窗口：勾选时两种操作均需确认，中间态仅删除需要确认，未勾选时两种操作均不弹出确认窗口。它不设置标注行的人工确认状态。

选择 Change class 的类别后点击相邻 Change，将类别应用于目标范围。Delete 删除作用范围内的标注；它不删除视频和磁盘原始文件，也不负责删除 Tracking 尚未提交的整个区间。

## 5.4 ID：合并与改号

### 5.4.1 Merge ID

Target 是保留的身份，Source 是并入的身份。Select 用于画面点选身份对，Clear 清空 Source，Clear all 清空这组身份输入。时间轴的蓝色、绿色条带分别对应 Target 和 Source，红色表示同时存在的帧。

Merge 的主要工作是统一身份。它不会自动判断两个同帧框究竟哪个对应真实目标，也不能用来掩盖两个同时存在的不同个体。出现冲突时先检查相关帧，必要时缩小范围、删除重复框或使用 Swap。

Interpolate between 用于补齐相应身份段之间的空档。插值根据边界几何产生中间框，不会再次读取图像寻找目标。

### 5.4.2 Change entire 与 Change range

在 Change ID 输入目标编号。Change entire 用于整条所选身份改号；Change range 只对指定范围改号，可把一段从原身份拆出。目标编号已存在时应处理重叠冲突，不把“输入成功”等同于“每帧唯一”。

Duplicate ID 的 Find 用于检查同帧同 ID 的重复行。先定位重复帧，再根据图像判断保留哪一个。相同 ID 在不同帧出现是正常轨迹，不属于重复冲突。

**例：ID 25 的后半段串到另一只蜂。** 将串号开始到结束的范围设入 Range，使用 Change range 分离这段，再与实际身份核对；如果两条轨迹在同一时刻互换，使用 Swap 更直接。

## 5.5 Interpolate：两端几何与补间

### 5.5.1 控件与计算

A/B 各包含 frame、id、x、y、w、h。Selected as A/B 将当前选中框的几何和帧号写入对应端点；也可以修改字段。A/B 时间顺序可倒置，执行时按实际帧号排序。

在同一段内，以帧位置比例对中心和尺寸作线性插值。例如第 100 帧中心 (100, 50)，第 110 帧中心 (120, 70)，第 105 帧估计为 (110, 60)。该模型表示两端之间按时间线性变化，不保证真实轨迹为直线。

### 5.5.2 实际执行范围

1. 两端 ID 不同时，会先询问是否把 B 的身份合并到 A；拒绝则不继续该插值。
2. 存在内部 gap 时，使用已有几何分段补缺，不把整段可靠观测简单压成 A/B 一条直线。
3. 选择范围伸出已知首尾时，利用最近几何及显式端点字段构造外侧边界。外推式补点应人工检查。
4. 区间已经完整、没有可补 gap 时，会询问是否用 A/B 替换该区间；这是重建区间，不是只补缺失。
5. 没有可用几何或不足两个有效端点时，不能完成插值。

### 5.5.3 实例一：短漏检段

目标在 200–220 帧存在，221–225 缺失，226 帧重新出现且身份已确认。

1. 从 Selected ID 定位 220，Selected as A。
2. 定位 226，Selected as B。
3. 核对类别、尺寸及中间是否遮挡/急转。
4. 点击 Interpolate interval，检查 221–225 的结果。
5. 结果来源属于插值；不要把这五帧计为模型实际检测成功。

### 5.5.4 实例二：完全没有标注的区间

1. 为目标确定一个新 ID。
2. 使用 Change position 的添加流程或 Tracking，在 100、110、125 等关键帧指定框。
3. 确认这些关键帧使用同一 ID。
4. 用 A/B 覆盖目标区间执行插值，让已有关键帧作为分段边界。
5. 在快速转弯、遮挡前后增加关键帧再检查；不要跨过不可判断的长遮挡直接假定直线。

### 5.5.5 实例三：位置错误但每帧都有框

选择错误段前后两个可靠端点，执行插值时确认替换区间。这样可以消除一段错误位置，但也会覆盖该区间原有运动细节；有弯曲路径时优先使用 Trajectory Edit/Draw。

## 5.6 Swap：交换两条身份

Swap 表包含 Begin/End 的 frame、ID A、ID B。Selected as Begin/End 从当前选择提取信息。执行 Swap A ↔ B 时交换指定区间的身份归属，保留框在图像中的几何位置。

**规程：** 找到两只目标身份互换的第一帧 → 设置 Begin → 找到需要交换区间的最后一帧 → 设置 End → 核对 A/B → 执行 → 播放区间两端。

**例：交叉后 1000–1040 帧 A/B 互换。** 交换这一段后，A 沿自己的真实目标连续，B 同理。区间外不应再交换一次；范围过长会把已经恢复正确的部分重新改错。

## 5.7 验收与保存

依次核对身份唯一性、作用范围、位置尺寸、两端交接及来源标记。用 History 撤销已提交的不正确操作；完成后 Save as。插值、合并、改号和交换的目的不同，应按错误类型选择，不以最终曲线是否平滑作为唯一验收标准。

# 6 Trajectory 操作说明

[返回总目录](#0-引言)

## 6.1 公共轨迹工具：范围与预览

### 6.1.1 入口与模式

入口位于 `Edit → Trajectory`，在 Swap 与 Scale 子页之间。模式顺序为 `Edit`、`Draw`、`Smooth`、`Redistribute`、`Transform`。

| 模式 | 改变内容 | 典型用途 |
| --- | --- | --- |
| Edit | 通过锚点和手柄改变局部形状 | 修复急转弯、调整个别曲线段 |
| Draw | 用鼠标笔画重新定义选定段路径 | 原路径大段偏离、需要重画弯曲路线 |
| Smooth | 按局部算法减小位置抖动 | 去除毛刺、平滑连续小幅噪声 |
| Redistribute | 沿当前路径改变各帧的位置分配 | 施加匀速、加减速或弯道减速假设 |
| Transform | 对中心坐标进行整体几何变换 | 整段平移、缩放、旋转 |

### 6.1.2 选择身份和帧段

1. 选中要编辑的目标 ID；此操作不合并其他 ID。
2. `Set` 按钮按下时，定位到起点并点击 `A:`，再定位到终点并点击 `B:`；也可直接输入两端帧号。
3. `Set` 按钮释放时，点击 `A:` 或 `B:` 跳转到已存端点，不改写输入值。
4. 查看蓝色范围条带，点击 `Preview` 建立预览。

A、B 均包括在范围内且不区分先后。A = 300、B = 200 等同选择 200–300。初始字段为空；没有指定两端时不能建立局部范围预览。右键单击 **Set 按钮**，或勾选 Edit 公共区的 **All frames**，可使用整个选定 ID；All frames 优先于 A/B 数值。

范围至少包含两个已有位置才能建立预览。扩大范围到空白帧不会自动创建首尾外侧位置。改变当前选中 ID 时，应重新核对端点，避免沿用上一目标的范围。

### 6.1.3 预览、实时计算与提交

Edit、Draw 使用 Preview 开始；Smooth、Redistribute、Transform 可在进入模式或改变参数时自动生成预览，也可按 Preview 重算。参数变化短暂合并后在后台计算，计算期间 Apply 不可用。

灰线表示原轨迹，橙线及逐帧小点表示预览。状态栏和面板悬停信息给出帧数、控制点数及位移统计。最大/RMS 位移是与本次预览原始输入的几何差，不是定位误差的实测估计。

- `Apply`：把结果写入工作数据，并作为一次 History 编辑。
- `Discard`：丢弃当前预览，保留此前尚未提交的 Tracking 点。
- 画面 Enter：应用曲线预览。
- 画面 Esc：丢弃曲线预览。
- Ctrl + Z / Ctrl + Y：在当前预览内逐步撤销/重做。

曲线预览存在时，Tracking Finish、保存等要求提交的操作被阻止，必须先 Apply 或 Discard。画面右键仍走 Tracking Finish 入口，不能替代曲线 Apply。

Edit 预览期间范围和曲线类型锁定；需 Discard 或 Apply 后重新选择。其他模式改变 A/B 会舍弃尚未应用的当前预览，并按新范围计算。切换模式可以继续利用当前预览形状，但应检查是否符合预期；同一种参数反复调整以本轮拟合前的基准计算，不把每次重算简单累加。

### 6.1.4 帧数、尺寸与边界

除 Edit 的 Fill gaps 外，轨迹工具保持原有帧号集合，不自动生成所有缺失帧。普通编辑保留原 ID、类别和各帧 W/H；Transform 缩放也只缩放中心路径，不同比例放大标注框。

提交时框按原视频边界约束。靠近边缘，最终中心可能因原 W/H 需要完整放入图像而被调整。预览拖到原图外并不表示可以在扩展空白区域保存标注。

已有 Tracking 待提交点参与预览时，Apply 先把该 Tracking 会话提交，再提交曲线修改，因此 History 中是两项编辑。一次全局 Undo 只撤销曲线修改，下一次才撤销先前追踪段。

## 6.2 轨迹形状编辑 Edit

### 6.2.1 参数与控制点

| 控件 | 作用 |
| --- | --- |
| `Bezier / Polyline` | 选择相邻锚点间使用三次 Bézier 曲线或折线 |
| Anchor 下拉框，条目如 `F2301` | 选择对应帧的控制锚点 |
| `Corner` | 两侧方向手柄独立，允许尖角或方向不连续 |
| `Smooth` | 拖动一侧手柄时另一侧保持反向共线，保留另一侧原长度 |
| `Lock` | 锁定所选锚点，保护其位置及控制操作 |
| `Keep timing` | 依据相邻控制锚点之间的帧序分配曲线参数 |
| `Project ordered` | 将原点拟合到编辑曲线上，同时约束帧序不倒退 |
| `Fill gaps` | 在建立预览时填充已有位置之间缺失的帧 |
| `Add` | 在当前视频帧位置增加控制锚点，不额外新增视频帧记录 |
| `Remove` | 删除所选内部控制锚点；不删除该帧标注记录 |

### 6.2.2 局部曲线修改规程

1. 在可靠的两端之间选定范围，选择 Edit 及 Bezier。
2. 点击 Preview。初始预览保留原逐帧位置，不把整段替换成首尾直线。
3. 在要改变方向的位置拖动已有方形锚点，或直接拖动曲线上的中间位置建立该帧锚点。
4. 选择该锚点，调整两侧圆形手柄，控制进入和离开的切线方向及弯曲程度。
5. 急弯用 Corner 分别控制两侧；连续圆滑转弯可用 Smooth。
6. 对需要保持的可靠位置勾选 Lock。
7. 逐帧检查橙色预览点是否贴合目标经过位置，再 Apply。

一次拖动是一次局部撤销步骤。端点不能 Remove，但未锁定时可以显式拖动；删除控制点不等于删除那一帧的标注。需要删除标注用 Tracking Delete。

### 6.2.3 曲线与时间分配原理

相邻锚点 `P₀`、`P₃` 及其外向、内向手柄 `P₁`、`P₂` 定义曲线：

```text
B(t) = (1 − t)³P₀ + 3(1 − t)²tP₁ + 3(1 − t)t²P₂ + t³P₃
```

Keep timing 把相邻锚点间的帧位置映射到曲线参数 t；t 等间隔不保证弧长等间隔，因此不保证目标匀速。Project ordered 更接近把已有点投影到新形状，同时约束顺序，但可能使部分相邻点接近或重合，不能视为速度保持。

**示例：** 100–120 帧轨迹被误连成直线，实际在 110 帧向下急转。可在 110 帧 Add 或直接拖动中间位置，把锚点拉到实际转弯处，用 Corner 调整两侧切线。100–110、110–120 分别形成曲线，其他未涉及段不按新曲线重写。

### 6.2.4 缺帧与 Fill gaps

不勾选 Fill gaps 时，默认保留缺帧，不以自动补点方式跨越没有标注的区间。若需要推定已有两点之间的漏标帧，必须在 Preview 前勾选 Fill gaps。

填充先在相邻已有位置之间按帧比例插值 `x/y/w/h`，再允许进一步编辑形状。仅填充已有位置夹住的内部空档，不在最早或最晚已有点外侧延伸。新增记录标为 `curve_fill`，与自动识别成功不同。

**示例：** 只有 100、110、120 帧的三个手工点。勾选 Fill gaps 后可生成 101–109、111–119 的估计位置，再调整曲线。把 From 改为 90 不会自动推算 90–99，因为该段缺少前端已有位置。

## 6.3 鼠标重绘 Draw

### 6.3.1 标准规程

1. 选中 ID 和要重画的帧段，选择 Draw。
2. 检查 `Keep endpoints` 与 `Tolerance px`，点击 Preview。
3. 在视频区域按住左键，沿希望的空间路径画出一笔。
4. 松开左键，等待后台生成逐帧预览。
5. 检查两端衔接及各帧分配；不合适时 Ctrl + Z 撤回一笔或重新绘制。
6. 必要时切到 Redistribute 调整沿路径的点分配；最后 Apply。

中键拖动及 Ctrl + 滚轮保留画面平移、缩放操作。绘制时切帧、移出画布或隐藏画布会中止尚未完成的笔画；应完成一笔后再导航。

### 6.3.2 参数与效果

| 参数 | 初始值 | 效果 |
| --- | --- | --- |
| `Keep endpoints` | 勾选 | 将新路径两端接回原段首尾位置，并保持首尾逐帧位置 |
| `Tolerance px` | 1，允许 0–100 | 简化鼠标笔画的几何容限；增大会减少细小曲折，也可能削弱真实小转弯 |

一笔重绘作用于整个所选段，不根据笔画是否只覆盖其中一小部分自动缩小范围。局部错误应先缩小 A/B。输入笔画方向与时间方向相反时，程序根据端点距离选择更合适的方向。

鼠标移动速度不作为目标运动速度。程序按原轨迹的相对累计弧长，把原帧位置映射到新笔画；原路径几乎没有长度时按顺序分配。锁定点保留，因此它们与新路径不一致时，局部可能出现折返或突变，需要检查。

Draw 不补齐缺帧，但一笔路径可覆盖所选范围内的已有点；有大段缺失时，不应把重绘连线当作缺失时段已经获得观测。

**示例：** 目标绕过障碍，原识别却把两侧连成直线。选择绕行前后范围，保留端点后画出 U 形路线。预览会把原帧数映射到 U 形路径，而不是按鼠标画 U 形时的快慢生成速度曲线。

## 6.4 轨迹平滑 Smooth

### 6.4.1 规程与实时预览

选中 ID 和局部范围后切到 Smooth。修改算法或参数会自动预览，连续输入约 180 ms 合并后后台计算；Preview 也可手动触发重算。Apply 才写入结果。

同一轮参数调整以该轮拟合前轨迹为基准，避免每改一个数值就再叠加一次平滑。若先进行了手工曲线修改，后续平滑可基于修改后的预览。Discard 返回该预览开始前的工作位置。

### 6.4.2 算法

| Algorithm | 原理 | 主要参数 | 适用效果与限制 |
| --- | --- | --- | --- |
| `Median` | 在局部窗口分别取 x、y 中值 | Window | 去除孤立突跳；可能削弱短促但真实的运动 |
| `Savitzky-Golay` | 对滑动窗口拟合低阶多项式 | Window、Order | 平滑连续噪声并保留一定局部趋势；不是保证位置正确的预测器 |
| `Smoothing spline` | 在数据贴合与曲线平滑之间使用正则化平衡 | Strength | 连续平滑；较大值抑制更多曲折，少于五点的小段保留 |
| `Simplify controls` | 以几何容限简化路径，再作有序投影 | Tolerance | 减少几何细碎变化；减少控制结构，不减少逐帧记录数量 |

### 6.4.3 参数

| 控件 | 初始值与范围 | 含义 |
| --- | --- | --- |
| `Window` | 7，允许 3–501 | 局部窗口帧数；计算时限制为段内可用的有效奇数 |
| `Order` | 2，允许 1–5 | Savitzky-Golay 多项式阶数，实际不超过窗口允许值 |
| `Strength` | 1，允许 0–10000 | 样条正则化力度；0 保留输入，增大趋于更平滑；不是百分数 |
| `Tolerance` | 1，允许 0–10000 | 简化及明显转弯判断使用的像素容限 |
| `Max px` | 10，允许 0–10000 | 每点最大允许位移；0 表示不允许改变位置，不表示取消上限 |
| `Keep corners` | 勾选 | 保护明显转弯点；错误尖刺也可能被当作转弯保护 |
| `Stabilized` | 不勾选 | 先进入 Camera 补偿坐标平滑，再映回每帧原图坐标 |

不适用当前算法的参数不参与该算法的核心计算。例如 Median 不由 Strength 控制平滑力度，改变 Strength 后不能据此要求 Median 结果改变。

### 6.4.4 保护规则与稳定坐标

Smooth 不增加帧，不跨实际缺帧进行连续平滑。每个连续段端点、Lock 点以及启用 Keep corners 时识别的明显转弯受到保护。

Stabilized 要求开启 Camera compensation 且每帧变换可用。它先移除相机运动的显示坐标成分，在稳定坐标中平滑，然后映回原图。Max px 在此时以稳定坐标计；状态中相对原轨迹的位移统计仍以映回后的源坐标结果计算。

**示例：** 蜜蜂基本静止，但相机轻晃。直接对源坐标强平滑可能把真实相机位移当作标记噪声；先建立可靠 Camera 补偿并选 Stabilized，可在稳定参考系中处理剩余抖动。

**去单点毛刺示例：** 某点偏离邻域 8 px，使用 Median、Window = 5、Max px = 10。若 Keep corners 保护了该尖刺，先检查其是否真实转向，再决定关闭该项。不能只为获得光滑线条而删除可辨的真实转弯。

## 6.5 沿轨迹重新分配 Redistribute

### 6.5.1 目的与共同约束

Redistribute 保持当前路径，改变“哪一帧位于路径的哪个位置”。它与 Smooth 的差别是：Smooth 主要改变几何形状，Redistribute 主要改变沿路径的运动进度。

保留原帧号集合、时间顺序、段端点及锁定点；缺帧两侧分别处理。锁定点同时构成分配区间的边界。各模式依据连续帧序计算，不以容器时间戳缺口拉长某一段。

路径采用当前预览逐点路径作为几何依据，因此应先用 Edit、Draw 或 Smooth 修正明显错误形状，再决定是否施加速度分配模型。

### 6.5.2 参数与实时预览

| 控件 | 初始值与范围 | 适用模式 |
| --- | --- | --- |
| `Preset` | Uniform speed | 四种分配模型 |
| `Influence %` | 50，0–100 | 所有模式，控制原分配与模型分配的融合 |
| `Acceleration %` | 0，−100–100 | Constant acceleration |
| `Turns %` | 50，0–100 | Curvature-aware，控制弯道减速影响 |
| `Transition %` | 50，0–100 | Ease in/out、Curvature-aware |
| `Ends` | Keep，可选 Stop | Ease in/out、Curvature-aware |

参数区分两行显示；模式不使用的字段不可用。改变参数自动预览，Apply 后提交，Ctrl + Z 可在提交前逐步撤销。

### 6.5.3 Influence 的数学含义

记原点在路径上的累计距离为 `s原`，所选模型给出的累计距离为 `s模型`，`a = Influence / 100`：

`s新 = (1 − a) × s原 + a × s模型`

程序在路径上取 `s新` 对应的位置，不直接对二维坐标作线性平均。这样中间力度仍沿路径移动，不会把弯道两侧平均成穿过内侧的直线。

- 0%：逐点保留原位置。
- 100%：完全采用模型分配。
- 50%：原进度与模型进度各占一半。

### 6.5.4 Uniform speed

按帧进度在路径弧长上均匀分布。对于连续帧段，100% Influence 时每相邻帧经过相同路径长度。

**示例：** 五个连续帧沿直线路径的原位置为 0、10、20、60、100 px。Uniform speed、Influence = 100% 后为 0、25、50、75、100；50% 后为 0、17.5、35、67.5、100。

在弯曲路径上，相邻点间的直线距离可能略短于沿路径距离，因此不能只用连接线长度严格判断弧长是否等距。

### 6.5.5 Constant acceleration

对沿路径的切向进度施加恒定加速度。设归一化帧进度 `u` 从 0 到 1，路径长度为 `L`，`b = Acceleration / 100`：

`s模型 / L = (1 − b)u + bu²`

- b = 0：匀速。
- b = +1：从静止开始加速。
- b = −1：逐渐减速到静止。
- 中间值：较弱的加速或减速。

**示例：** 五个连续帧、路径长 100 px，Acceleration = +100%、Influence = 100% 时，位置进度为 0、6.25、25、56.25、100 px。点在起点附近更密，表示起始速度较小。

这里恒定的是沿路径的切向加速度。曲线路径中速度方向也在变化，因此不保证 x/y 二阶导数恒定。该模式不能同时在段首和段尾都从静止平滑过渡；需要两端起停使用 Ease in/out。

### 6.5.6 Ease in/out

根据**段内时间位置**平滑起步和收尾，中部连接较稳定速度段。Transition 决定两端速度过渡所占的比例；数值越大，起步和收尾影响越长。实现中的单端过渡长度约占总时段 5%–50%。

`Ends = Stop` 要求两端模型速度为零；`Keep` 使用原路径端点附近的估计速度作为边界参考，并进行限制和整体归一化。Keep 不应理解为无条件精确保留任意原始端点速度。

**示例：** 目标在一段路线起点停留后起飞，终点又逐渐停下，可选 Ease in/out、Ends = Stop。中间即使有弯道，本模式也不会只因该处弯曲就额外减速；减速主要发生在帧段两端。

### 6.5.7 Curvature-aware

根据**路径的弯曲位置与程度**降低局部模型速度，并在直段与弯段间平滑过渡。相同时间步下，弯道附近分配更多、更密的点，直段分配更疏。

- Turns 增大：急弯对分配的影响增强。
- Transition 增大：更强地限制直段与弯段之间的速度突变，使减速、加速过渡扩展。
- Ends = Stop：要求两端模型速度为零。
- Ends = Keep：不强制两端停止；此模式不据此精确复制原轨迹端点速度。

算法从路径估计平滑曲率，构建随曲率降低的速度上限，再从前后两个方向限制加速度变化并按总帧时长归一化。它是几何驱动的分配模型，不识别昆虫动力学参数。

**示例：** 一条中间急转、两侧较直的轨迹，适合观察 Curvature-aware 的预览。即使急弯位于整段的 70% 处，密集点也会出现在弯道附近；Ease in/out 则主要根据起止时间减速，不能替代这一行为。

### 6.5.8 模式选择对照

| 需要的分配假设 | 选择 | 不适合直接推出的结论 |
| --- | --- | --- |
| 整段沿路径速度一致 | Uniform speed | 不证明目标实际匀速 |
| 单方向加速或减速 | Constant acceleration | 不证明转弯时二维加速度恒定 |
| 起点和终点平滑起停 | Ease in/out | 不保证弯道自动减速 |
| 急弯慢、直段快，并平滑衔接 | Curvature-aware | 不证明存在恒定功率或特定生物力学机制 |

四种模式改变的是人工选定的运动假设，不恢复缺失的实测速度。用于后续速度、加速度或行为统计前，应保留来源并区分观测与人工重分配结果。

## 6.6 轨迹整体变换 Transform

### 6.6.1 参数与规程

1. 选中 ID 和整个或局部帧段，选择 Transform。
2. 检查默认中心；初次进入时为该段路径包围盒中心。
3. 输入 X/Y offset，或设置 Scale、Rotate。需要指定旋转中心时使用 Center X/Y 或 `Pick center` 后在视频中点击。
4. 检查实时预览及两端与范围外轨迹的衔接。
5. Apply 提交，或 Discard 丢弃。

| 控件 | 单位与初始含义 |
| --- | --- |
| `X offset / Y offset` | 源图像素；正值分别向右、向下 |
| `Center X / Center Y` | 缩放与旋转中心的源图坐标 |
| `Scale %` | 100 为原大小；允许 0.01–100000 |
| `Rotate °` | 0 为不旋转；正值在原图中逆时针 |
| `Pick center` | 下一次视频内点击设置中心 |
| `Reset` | 偏移和角度归零，Scale 恢复 100；保留中心 |

变换顺序是：以中心缩放、旋转，再应用 XY 偏移。同一轮参数相对该轮变换前轨迹计算，反复改输入不累加同一变换。Lock 点保留；范围外记录不变。

### 6.6.2 实际效果

**平移示例：** 整段标注偏右 8 px、偏上 3 px，设置 X offset = −8、Y offset = +3。所有未锁定的选定帧中心按该偏移移动，框 W/H 不变。

**缩放示例：** Center 为 `(500, 300)`，点 `(520, 300)` 在 Scale = 150% 后变为 `(530, 300)`；这是路径距中心放大，不是把框宽高放大到 150%。

**旋转示例：** 同一中心，点 `(520, 300)` 逆时针旋转 90° 后约为 `(500, 280)`。源图 y 向下，因此逆时针转到中心上方。

Transform 不自动在范围外创建平滑衔接。局部整体平移可能在两端产生跳变，需要扩大过渡范围或使用 Edit 检查接点。

## 7.1 功能目的与数据关系

Match 将 Tracker 人工轨迹与自动检测结果对齐，计算候选身份关系，允许逐帧或逐段确认、拒绝、解除绑定和忽略，最后形成可继续编辑的审阅轨迹。

人工轨迹提供连续身份和大致空间范围，但可能有点击误差、时延和少量异常点。自动框通常能提供更细致的逐帧几何，但可能断轨、串号或漏检。将二者匹配合并可以实现信息互补，从而提升标注质量。Match 功能使用两类信息，不把任意一类的每个点都视为绝对正确。

自动检测 CSV 中的轨迹来自 YOLO/跟踪流程，通常有 `track_id`、`x/y/w/h`、`class` 等字段。手工轨迹来自 Tracker 的 `.trk` 文件或已经转换过的 `manual_track_file` CSV，通常只有点坐标、轨迹名、角色、类别和帧号。`Match` 功能的目标是把二者放到同一个视频帧坐标轴上，并建立“某段手工轨迹对应哪个自动检测 ID”的绑定关系。

核心分成三步：

1. 对齐：确定手工轨迹在视频中的帧位置和 x/y 偏移。
2. 预览匹配：根据距离和路径连续性自动给出手工点到自动框的候选绑定。
3. 确认应用：把绑定关系写入当前工作 CSV，必要时用手工点位置修正自动轨迹位置。

| 数据层 | 含义 | 是否等于最终审阅结果 |
| --- | --- | --- |
| 人工原始点 | `.trk` 或人工 CSV 中的采样 | 否，尚需时间/空间对齐 |
| 对齐后的人工点 | 映射到视频帧轴和原图像素坐标的点 | 否 |
| 自动源框 | 自动标注来源中的框，具有来源身份 | 否 |
| Candidate | 算法提出的对应关系 | 否，仍需审阅 |
| Bind 结果 | 人工确认的对应关系及其生成的工作行 | 已进入工作数据，仍需保存 |
| Finalize 状态 | 指定人工轨迹已完成审阅 | 不等于磁盘保存 |

Match 与 Tracking 的模板搜索不同，也与 Edit → ID 的直接改号不同。数值相同的 ID 不应跨视频、跨结果方案直接视为同一个体。

## 7.2 打开人工轨迹

### 7.2.1 从 Boutlist 导入

先配置 boutlist 列映射，再打开记录。程序可读取人工轨迹路径、Tracker capture 帧、视频 capture 帧、Tracker 帧率、起止范围、倒放标志及偏移等信息。核对读取到的字段，再检查画面上的人工点。

### 7.2.2 单独导入

1. 打开对应视频和自动标注。
2. 打开 `.trk` 或人工轨迹 CSV。
3. 在 timing 对话框核对人工帧轴参数和比例信息。
4. 导入后检查人工轨迹名、类别、范围和初始位置。
5. 先完成对齐，再计算 Match；不要用扩大匹配容差代替对齐。

## 7.3 Alignment：时间与空间对齐

### 7.3.1 参数表

| 界面项目 | 含义与单位 |
| --- | --- |
| Start-End range in trk | 参与处理的 Tracker 原始帧范围；不是视频 Range |
| Fps of trk | 人工轨迹所用视频的帧率，用于按时间比例把手工帧映射到视频帧 |
| reversed | 人工轨迹来自倒放视频时反向映射帧轴，如 Tracker 使用的是倒放视频标注，则需要勾选此选项 |
| Calibration frame (capture) in trk | 人工时间轴中的事件参考帧，用作时间轴的对齐锚点，一般使用捕获帧 |
| align to video | 同一事件在当前视频中的对应帧 |
| Frame offset | 在基础映射上增加的视频帧偏移，向前为正 |
| x/y offset | 人工点在原图坐标中的像素偏移，X 向右为正、Y 向下为正 |
| Auto set offset | 按当前 timing 信息重新准备人工数据并估计对齐，可能改写现有偏移（frame/x/y offset），改写前会弹窗确认 |
| Preview points | 使用当前偏移刷新人工点预览，不等于生成最终绑定 |
| Sync from / Sync to | 从所选 boutlist 记录读取或向其回写相关对齐字段 |

### 7.3.2 推荐操作规程

1. 找到视频与人工轨迹共同可识别的参考事件，分别填入两条帧轴的对应帧。
2. 核对 FPS、reversed 和 Tracker 范围。
3. 需要重读/重算时执行 Auto set offset，注意确认提示。
4. 在视频开头、中间、结尾检查人工点是否与目标同步。
5. 仅整体偏移时修改 Frame offset 或 x/y offset，执行 Preview points。
6. 快速运动段也能对齐后，再运行 Match。

**例：手工轨迹整体落后 3 帧。** 人工点沿目标轨迹运动，但相同位置总比图像晚 3 帧。将 Frame offset 相对当前值减 3（输入 `-3`），点击 Preview points 后观察多个位置。

**例：时间对齐误差随时间增长。** 检查帧率 FPS 是否相同，不能用固定 offset 应对比例错误。

**例：人工点偏右 12 px、偏上 4 px。** 将 x offset 相对当前值减 12（输入 `-12`），y offset 加 4（输入 `4`），再 Preview points。这一操作的效果是全部人工点左移 12、下移 4；原自动框位置没有被这一步整体平移。

## 7.4 Match 与候选预览

Match 根据对齐人工点、自动框的空间邻近、类别和路径连续性组织候选。人工点在框内说明空间相容，但重叠目标仍可能身份不同。候选分数或较小距离不能替代逐段核验。

Match 是可选中按钮：按下后计算并显示匹配，再次按下关闭匹配显示，保留已明确作出的绑定决定。关闭时 Bind、Reject、Unbind、Ignore 等入口不可用；重新开启并取得有效预览后再操作。修改上游自动框或对齐参数后，应检查候选是否过期并重新计算相关段。

建议先看整体对应，再集中检查以下位置：目标交叉、遮挡前后、自动 ID 改号、低置信度尾部、人工轨迹缺口和视频边缘。

## 7.5 Involved ID、Range 与表格选择

Range 使用视频帧号，例如 `300-360`，包含两端；可用逗号组合多个区间。人工轨迹名和自动 ID 在 Involved 中各自具有身份作用，不能把人工名称当作自动整数 ID。

Binding 表选中行提供该行涉及的身份及其**实际帧集合**。多选使用这些集合的并集，不因 Link selection 扩大为整条人工轨迹或整个自动身份范围。自行修改 Involved 字段后，执行前重新核对范围。

| 区间类型 | 解释 |
| --- | --- |
| 连续人工采样段 | 原始人工采样按其时间轴连续存在 |
| resolution gap | 人工帧率低于视频帧率导致的映射空帧，不一定是实际漏标 |
| GAP | 原始人工采样本身缺失的区间，切开真实连续段 |
| Before / After | 位于相应人工数据首尾之外的区间，不能假定有人工点 |

含 resolution gap 的范围可用圆括号标识，例如 `(2-10)`。它表示低频采样关系，不代表每个视频帧都存在真实人工点击。执行绑定时按程序给出的有效帧与处理结果检查，不能把各种 gap 都视为同一种插值需求。

## 7.6 Bind、Reject、Unbind、Ignore

### 7.6.1 Bind

Bind 接受指定范围的身份关系，生成最终工作行并记录其自动来源消费关系。它并非只改画面颜色。类别不符、来源被其他身份占用或快照已失效时，可能发生冲突、跳过或拒绝；检查结果提示中的实际成功范围。

**例：300–360 应对应自动 ID 25，却候选到 ID 33。** 选择人工轨迹和正确的自动身份，明确 Range 为 `300-360`，执行 Bind，再检查该段及两端。不能只在当前帧点一下正确框，就假定整段已完成切换。

### 7.6.2 Reject

Reject 排除当前候选对应关系。对已确认帧，先解除该确认结果；对候选帧，拒绝相应候选。它表达“这项对应关系不正确”，并不等于接受人工点位置，也不等于删除所有自动源框。拒绝后继续寻找正确候选或明确选择其他处理方式。

### 7.6.3 Unbind

Unbind 的结果取决于操作前的帧状态，应先查看 Binding 表：

| 操作前状态 | 执行结果 |
| --- | --- |
| 已确认的绑定 | 解除确认结果，恢复被消费的来源并允许重新审阅候选 |
| 尚未确认的自动候选，且有可靠人工几何 | 清除自动对应，以人工位置建立 Manual-only 最终结果 |
| 尚未确认的 Manual-only 行，且有可靠人工几何 | 确认该人工位置为 Manual-only 最终结果 |
| 真正 GAP，且没有可靠人工几何 | 不凭空生成位置，相应帧跳过 |

因此，Unbind 不总是“撤回一次操作”；需要完全撤销刚才修改时使用 Undo。更改自动来源归属前，对已确认段先 Unbind 可避免同一来源重复用于另一轨迹。若该最终行后来又被其他工具修改，注意冲突确认提示；恢复来源可能同时撤回后续几何修改。

**例：500–520 帧胡蜂漏检，人工轨迹仍可靠。** 选择该段未确认的 Manual-only 行并执行 Unbind，以人工位置确认这段，再检查 499/500 和 520/521 的交接。不要用 Ignore 代替人工补点，也不要对已经确认的同一段反复按 Unbind。

### 7.6.4 Ignore

Ignore 明确指定某段不参与当前人工轨迹的匹配/合并。它与“尚未审阅”不同。适用于人工点明显跑出目标、没有可靠依据的段或明确排除范围；不应仅因算法暂时匹配失败就忽略全部缺失段。

所选范围全部处于忽略状态时，按钮显示 Restore；点击后恢复该段参与审阅。范围包含不同状态时仍显示 Ignore。恢复参与并不等于确认其中所有候选。

## 7.7 最终位置来源与尺寸

### 7.7.1 Position when conflicting

| 选项 | 两类位置均有效时的结果 |
| --- | --- |
| Detected | 使用有效自动源框中心 |
| Mix | 使用自动中心与人工点的算术中点 |
| Manual | 使用对齐人工点中心 |

例如自动中心 (100, 80)、人工点 (110, 86)：三者分别得到 (100, 80)、(105, 83)、(110, 86)。Mix 是明确的折中规则；不会仅因为人工点落在自动框内，就自动改成 Detected。它也不是对整个轨迹做最优平滑拟合。

有有效自动源时沿用其框尺寸。只有人工位置时需要尺寸回退，优先参考附近最终框，再使用类别统计或默认尺寸；这类尺寸不属于该帧图像实测。

在 Binding 表选中段后，选择 Position when conflicting 会更新所选段的位置策略；Transition 输入完成后同样更新策略并记录一次可撤销修改。多个所选段按各自帧集合处理。没有选中段时，不会因为改变下拉框而对全片批量改位置；后续 Bind 仍需检查其作用范围。

### 7.7.2 manual_fill 与真实检测缺失

`manual_fill` 表示人工点可作为补充，但没有可接受的自动源框。常见于遮挡、漏检和画面边缘。长缺失段使用人工位置并不恢复遮挡期间真实形状；后续分析应保留位置来源。

**例：胡蜂人工点掠过蜜蜂框。** 先查类别和原胡蜂来源。原胡蜂框仍存在时选择它；不能把近邻蜜蜂框消费掉。原胡蜂检测缺失时使用人工依据并检查交接，而不是强行绑定最近自动框。

## 7.8 Transition：来源交接

Transition 指定本次生成的连续相邻行中，位置来源类型切换处的过渡长度；初始值 3 帧，0 禁用。它不跨越实际缺帧，也不把整个自动轨迹统一平滑。

从 Detected 转向人工/Mix 时，以最后自动点为锚，后续最多 N 帧逐渐接近新来源目标；反向交接以首次自动点为锚，调整此前最多 N 帧。遇到缺帧或新的来源边界时，过渡范围受限。

**数值例：** N=3，最后自动 X=100，接下来的人工目标 X 都为 120，向人工交接的前三点为 105、110、115，随后到 120。自动段本身保留自动位置。

若一方隔几帧出现一次且位置差异很大，短过渡可能反复发生。此时应明确选择更可靠的来源段，或到 Trajectory 做有预览的几何修正；增加 Transition 不能保证消除所有反复跳变。

## 7.9 Binding 表与时间轴核对

同时核对三处：

1. 画布：人工点、自动源诊断框与最终工作框是否对应同一目标。
2. 表格：人工名称、自动来源、实际 ranges、审阅状态和位置策略是否正确。
3. 时间轴：绑定段是否覆盖预期区间，是否越过真实 GAP 或侵入另一目标的存在范围。

原来源诊断与最终框可能同时可见，这是检查来源的工具，不应据此重复删除正常来源。隐藏诊断层再检查最终工作结果，但保存前仍需回到表格确认来源关系。

## 7.10 Finalize、Reopen 与保存

### 7.10.1 完成审阅规程

1. 选择待完成的人工轨迹。
2. 处理未决候选、冲突、缺失段及明显异常几何。
3. 检查审阅诊断列出的阻塞事项，并定位解决。
4. 执行 Finalize；它记录该轨迹完成审阅，不直接写盘。
5. 播放检查关键区间，再 Save as。

需要继续修改已完成轨迹时用 Reopen。Alignment 被所有人工轨迹共用；修改对齐前需要重新打开所有已 Finalize 的人工轨迹。已保存结果中的绑定来源与审阅状态应用于后续检查；不要通过删除元数据把冲突隐藏掉。

### 7.10.2 完整示例：一条人工胡蜂轨迹对应多个自动 ID

1. 完成时间/空间对齐，运行 Match。
2. 自动 ID 18 对应前段、25 对应遮挡后段；在 Binding 表分别核对。
3. 对可靠段 Bind，明显错配段 Reject，再选正确来源。
4. 自动缺失但人工可靠的短段使用人工依据，检查尺寸回退和 Transition。
5. 人工也无可靠数据的真实 GAP 不强行当作检测成功。
6. 核查最终身份连续性、同帧唯一性与来源消费冲突。
7. Finalize 后保存，重新打开结果检查两次身份交接。

## 7.11 结果解释边界

绑定表示身份审阅决定，平滑表示几何处理，二者不能互相替代。连续人工身份并不保证精确中心；自动框中心较准确也不保证身份正确。下游统计应区分实测、人工位置、混合位置和补间，并结合审阅状态选择分析范围。

### 7.11.1 如何查验匹配是否可靠

建议同时检查三类信息：

1. 视频画面：手工点、自动框、高亮绑定符号是否空间一致。
2. Manual traj 表：每帧手工点对应的 `matched_auto_id`、`match_status`、距离等字段。
3. 进度条/段显示：绑定段是否覆盖了期望范围，是否跨过了不应跨过的 gap。

推荐原则：

- 有 gap 时不要盲目整段绑定。
- 自动匹配距离明显变大时，优先人工检查。
- 胡蜂和蜜蜂类别不一致时，不要直接合并，除非确认是自动分类错误。

# 8 Tracking 操作说明

## 8.1 用途与功能边界

Tracking 用于为一个指定目标建立、延续或修正逐帧位置记录。目标身份由 `Track ID` 指定；自动追踪在该身份下寻找目标外观，不负责在多个个体之间重新判定身份。

| 功能 | 输入依据 | 输出 | 适用任务 |
| --- | --- | --- | --- |
| 人工标记 | 当前帧中的人工指定位置及框尺寸 | 当前 ID 的单帧框 | 漏检补点、遮挡段修正、建立稀疏关键位置 |
| 模板自动追踪 | 一个或多个图像模板、搜索范围、评分条件 | 逐帧接受的目标框及匹配信息 | 连续外观可辨的目标追踪 |
| `Mouse guided` | 图像模板及持续移动的鼠标搜索中心 | 通过相同评分条件的目标框 | 快速移动、预测不稳定但仍可辨认的目标 |
| `Assist` | 人工或自动生成的初始框、局部图像 | 受边界约束的框细化结果 | 改善框大小及局部中心位置 |
| `Edit → Trajectory` | 已有目标轨迹及选定帧段 | 预览后提交的轨迹坐标 | 局部曲线纠正、重绘、平滑、点分配及整体变换 |
| Camera Anchor 追踪 | 选定背景锚点及其图像模板 | Camera 锚点的逐帧观测 | 为既有相机运动补偿提供位置观测 |

Tracking、Detection 和 Match 的职责不同：Detection 从视频中检测目标并生成检测轨迹；Tracking 在指定 ID 下补充或修正位置；Match 处理导入手工轨迹与检测轨迹之间的对齐、匹配和绑定。Tracking 的 `Overwrite` 不执行跨 ID 合并，也不融合两条不同身份的轨迹。

本说明覆盖 Tracking 的全部操作入口，以及与其直接衔接的公共 Trajectory、Camera Anchor 追踪、轨迹显示和保存行为。Scale 标尺校准、Match 身份融合、Points/Events 事件记录的完整规程分别属于相应模块说明。

## 8.2 坐标、帧号与数据状态

### 8.2.1 坐标定义

标注使用原始视频图像的像素坐标：左上方向为坐标原点方向，`x` 向右增大，`y` 向下增大。`x/y` 表示框中心，`w/h` 表示轴对齐框的宽度和高度，单位均为原视频像素。

显示缩放、平移、Camera compensation 和 Expanded motion canvas 只改变画面显示与交互坐标的映射。鼠标点击先映射回原视频坐标，再生成标注；自动匹配始终读取原始视频图像。扩展画布中没有原始视频图像的空白位置不能用于新增标记或截取模板。

框必须位于原图范围内。靠近边缘时，程序会调整中心或限制尺寸，使框适应图像边界。因此，边缘处最终框中心可能与点击位置略有不同。Camera Anchor 存储的是点位置，按源图边界限制，不以物体框尺寸确定边界。

**示例：** 原视频宽度为 1920 px，显示窗口将图像缩小到一半。屏幕上移动 10 px 对应的原视频位移约为 20 px；`Offset X = 10` 仍表示原视频中的 10 px，不表示屏幕上的 10 px。

### 8.2.2 连续解码帧号

`frame` 从 1 开始，按实际解码图片的先后顺序连续编号。容器时间戳出现间隔时，不按“时间戳差 × FPS”插入虚拟画面，也不复制画面来补齐该间隔。

随机定位使用视频图片索引寻找解码起点，并核对解码结果。遇到无法可靠使用的时间戳时，以从起点顺序解码计数作为回退。首次定位可能需要建立索引；等待时保留最后一张已确认画面，不以未经确认的图片代表请求帧。

**示例：** 第 1000 张与第 1001 张解码图片的时间戳相差 0.8 s，二者仍标为 `frame = 1000` 和 `frame = 1001`。Tracking 在两张实际图片之间追踪，不生成额外的重复记录。

连续帧号能统一识别、标注和定位所指向的图片，但不证明拍摄过程未丢失真实画面。按 `(frame₂ − frame₁) / FPS` 计算的时长采用连续图片和标称帧率的时间模型；涉及真实拍摄时间的分析，应另行确认时间戳缺口是否仅为封装问题。载入的旧 CSV 保持原帧号，不凭缺口猜测重编号，也不自动核验其坐标。索引尚未完成时，本次会话的新编辑记录所对应图片的身份；索引完成后，程序把这些编辑、模板、预览及相应撤销记录映射到已核验的连续帧号。若图片身份无法唯一确定，保留编辑并暂停最终输出，显示 `Frame mapping pending`。

### 8.2.3 四种数据状态

| 状态 | 含义 | 进入正式 History | 写入普通结果 SQLite |
| --- | --- | --- | --- |
| 匹配候选 | 当前算法找到的位置，可能未通过阈值 | 否 | 否 |
| Tracking 待提交点 | 人工标记、接受的自动点或待执行的删除 | 尚未作为整段命令提交 | 保存前先提交会话 |
| Trajectory 预览 | 曲线编辑、拟合或变换后的候选轨迹 | 否 | 必须先 `Apply` 或 `Discard` |
| 已提交工作数据 | 已执行 `Finish` 或 `Apply` 的编辑结果 | 是 | 执行保存后写入 |

`Finish` 表示提交到当前工作数据及 History，不等于保存到磁盘。`Cancel` 只撤回尚未提交的会话，不能取消已经提交到 History 的修改；已提交修改使用 History 的 Undo。

| `Scale ±%` | 未启用，范围值 20，允许 0–75% | 相对模板基准尺寸搜索缩小与放大 |

| `Decode ahead` | 默认启用，可保存偏好 | 预解码后续一帧，将解码与当前帧匹配重叠执行 |
| `Match workers` | 默认 4，允许 1–16，可保存偏好 | 并行评估独立模板的 CPU 工作线程数；1 为串行 |

模板框初始尺寸为 19 × 19 px，搜索框初始尺寸为 90 × 90 px；二者主要通过画面调整。它们与人工 `Box W/H` 是不同参数。

### 8.3.5 参数何时生效

| 修改类型 | 生效方式 |
| --- | --- |
| 人工 W/H、Auto next | 用于随后人工点及其切帧，不回写此前所有点 |
| Score、Margin、Evolution、Tether、Stop、匹配权重 | 由后续匹配请求使用；已经接受的点不因改值重新判定 |
| Search、Mouse guided、Reverse、Rotate/Scale 开关及范围 | 修改时暂停，检查后重新运行 |
| Template/Search 可视化区域 | 暂停后调整；模板区域会重新取样，搜索区域只改变搜索配置 |
| Offset X/Y、Mark offset | 暂停并更新活动模板偏移；条件满足时更新当前帧框 |
| 模板启用、删除 | 暂停并改变后续参与匹配的模板集合 |
| Show trail、显示样式 | 只改变显示，不重算匹配或改写位置 |

运行中的匹配请求持有发出时的参数。某些数值修改不会自动中断已经开始的请求，因此需要严格比较两套设置时，应先 Pause，再调整并运行。Score/Margin 颜色可按新阈值立即重判最近一次显示值，但不会据此撤回此前接受的记录。

## 8.4 标准操作规程

### 8.4.1 规程 A：建立新的自动轨迹

**前提：** 已打开视频，当前画面已完成定位；需要新增一条独立目标轨迹。

1. 打开 `Tracking → Track Motion`，点击 `New`，检查 `Track ID` 与 `Class`。
2. 定位到目标清晰、身份可确认、背景干扰较少的一帧。
3. 点击 `Add Template`，再点击识别特征中心。也可直接在视频内 Alt + Shift + 左键单击。
4. 等待模板状态变为可用。在 `Templates` 检查截取内容；回到 `Track Motion`。
5. 点击 `Template area`，调整青色框，使其包含可稳定识别的特征。避免截入过多无关背景。
6. 点击 `Search area`，调整黄色框，使下一帧目标可能位置位于框内，并为模板完整放入留出空间。
7. 若最终标注位置与特征中心不同，使用 `Mark offset` 设置目标中心。
8. 首次运行使用 `Search = Predict`、`Stop due to = Poor match`，保留 Score、Margin 的初始阈值；根据目标情况决定是否启用 Assist。
9. 点击 `Run Auto`。观察框是否覆盖同一个体，同时检查 Score、Margin、Rate 和状态行。
10. 暂停后检查当前点、轨迹及时间轴覆盖范围。对错误点采用人工接管或局部重新追踪。
11. 点击 `Finish`，将本次追踪提交为一次 History 编辑。
12. 使用程序的保存入口保存结果 SQLite，并完成保存流程中的检查项目。

**结果：** 模板来源帧产生一个待提交框；后续只有同时满足接受条件的匹配才生成自动点。没有识别成功的帧不会因视频经过该帧而自动拥有标注。

### 8.4.2 规程 B：续接已有 ID

1. 定位到该 ID 已有可靠框的帧并选中该框。
2. 检查 Tracking 自动填入的 ID、类别、人工框尺寸。
3. 按 `Use ID` 或开始标记，在已有 ID 对话框中确认继续使用。
4. 从可靠帧建立模板并调整搜索范围。
5. 向缺失方向运行。向视频较早帧补充时勾选 `Reverse`。
6. 遇到已有同 ID 位置时，按本次任务决定保留、暂停检查或允许覆盖。
7. 检查续接处的位置、身份及框大小，随后 `Finish` 并保存。

**结果：** 新点延续相同 ID。除本次明确编辑的帧外，已有记录保持原状；不会自动把另一 ID 改名或合并进来。

### 8.4.3 规程 C：仅人工补充一段

1. 选择已有框复用身份，或用 `New` 建立 ID。
2. 选择 `Fixed box`，设置 `Box W/H`；需要沿用历史大小时选择 `Previous box`。
3. 检查 `Auto next` 和 `Reverse`。逐帧点击通常启用 `Auto next`；只标少量关键帧时可关闭。
4. 无模板时点击 `Start`，进入持续人工标记状态。
5. 在每一帧点击目标位置。先核对当前帧已显示，再指定下一点。
6. 错误点使用 Ctrl + Z、当前帧 Delete 或重新点击修正。
7. 在画面上按 Enter、右键，或点击 `Finish` 提交。

**结果：** 每次点击写入当前帧同一 ID 的一个位置。人工点不自动建立新模板，不自动连接没有标记的中间帧。

### 8.4.4 规程 D：在其他工作过程中临时修正

1. 选中要修正的目标框，核对当前帧及目标身份。
2. 按住 Alt，在视频内左键点击正确位置。
3. 需要修正连续几帧时继续保持 Alt，并结合 `Auto next` 逐帧点击。
4. 松开 Alt。

**结果：** 若开始操作前没有 Tracking 会话，本次临时点修改自动提交为一次 History 编辑，主功能页保持原位置。若原本已有 Tracking 会话，松开 Alt 不提交整段，按人工接管规则恢复或保持暂停。

## 8.5 身份、类别与会话管理

### 8.5.1 Track ID 的确认规则

`Track ID` 接受非负十进制整数。负数、字母、带小数点的输入不作为有效 ID；最大值为 9007199254740991。`001` 与 `1` 表示同一个数字身份，显示补零不构成新身份。

输入后按 Enter 或点击 `Use ID` 进行检查，开始会话时也会检查。若该 ID 已存在：

- 选择 Yes：继续使用该身份。人工标记可替换重叠帧的位置；Auto 按 Overwrite 规则处理。
- 选择 No：清空 `Track ID` 输入框，等待输入其他 ID。

这项确认只确认“使用哪个身份”，不等于允许 Auto 无条件覆盖该身份的全部已有位置。已有 ID 确认和 Auto 覆盖确认是两项不同操作。

### 8.5.2 选择联动与类别

没有活动会话时，选中当前帧的已有框会填入其 ID、Class 和 W/H。开始会话后，ID 与类别控件锁定；会话内点击其他对象不会将当前追踪身份自动换成另一个 ID。

`Class` 可输入自定义名称，写入时去除首尾空白并转为小写。类别作用于本会话写入的记录；继续追踪同一 ID 不会自动重写该 ID 所有未编辑帧的类别。

**示例：** ID 123 的已有数据为 `hornet`。在正确框上选中 ID 123 后续接，新增点使用 `hornet`。若手动把本次 Class 改为其他名称，只有本次写入或替换的点按新类别记录，不能将此操作当作全轨迹更改类别。

### 8.5.3 会话边界

| 操作 | 对会话的作用 |
| --- | --- |
| `Pause`、拖进度条、跳帧 | 暂停，保留待提交点及模板；使旧后台请求失效 |
| 切换三个 Tracking 子页 | 暂停并退出当前选模板或人工点击状态，保留会话 |
| 切到主面板 `Edit` | 暂停并保留会话，允许进一步使用公共轨迹工具 |
| Camera Anchor 会话中切回 `Camera` | 暂停并保留锚点会话 |
| 切到其他会触发离开提交的主面板 | 先执行会话提交；未处理的曲线预览会阻止提交 |
| 开始播放、保存或执行要求提交的其他编辑 | 先完成 Tracking 提交；曲线预览需先 `Apply / Discard` |
| `Finish` | 提交整个会话、清空本会话模板库、解除身份锁定 |
| `Cancel` | 丢弃整个会话、清空模板库、恢复会话前的选择状态 |

需要确定保留或舍弃一段结果时，应显式使用 `Finish` 或 `Cancel`，不要依赖切换面板的间接行为。恢复快照与普通 SQLite 保存是不同机制，不能用“正在等待恢复快照”代替结果保存。

### 8.5.4 状态按钮

| 按钮文字 | 当前含义 | 再次点击 |
| --- | --- | --- |
| `Start` | 无模板，人工标记尚未运行或已暂停 | 开始人工标记 |
| `Pause` | 人工标记或 Auto 正在运行，按钮呈选中状态 | 暂停当前运行方式 |
| `Run Auto` | 有模板，准备运行 | 从当前追踪起点继续自动匹配 |
| `Resume Auto` | 有模板，Auto 经暂停或人工介入后等待继续 | 从当前修正位置继续 |

按钮文字表示运行状态，不代表数据是否已保存。暂停时待提交结果仍然存在。

## 8.6 人工标记与自动追踪接管

### 8.6.1 人工框尺寸

`Fixed box` 使用人工 W/H 作为初始框尺寸。`Previous box` 查找当前追踪方向上已经经过的最近位置，采用该位置的框大小；正向对应较早帧，倒向对应较晚帧。找不到可用历史尺寸时使用输入的 W/H。

这两项控制人工点的初始框。Auto 的初始输出尺寸来自获胜模板及其旋转、缩放外接范围，不受人工 W/H 直接限制。Assist 可进一步细化人工或自动初始框。

**示例：** 手工 W/H 为 9 × 9 px，而自动模板为 19 × 19 px。普通人工点先生成 9 × 9 框；无姿态变换、无 Assist 的自动匹配生成约 19 × 19 框，不能以 W/H = 9 推断自动框也为 9 × 9。

### 8.6.2 Auto next 与方向

启用 `Auto next` 后，人工指定位置完成后按 `Reverse` 决定的方向切换一帧。关闭时留在当前帧，可以重复修正位置。

在低分失败后的人工重试中，无论重试成功还是失败，启用 Auto next 都会请求显示下一帧，视频首尾除外。若重试仍失败，下一帧保持暂停；若下一帧存在同 ID 且未允许覆盖，保留相应冲突暂停，不因此绕过覆盖确认。

人工自动切帧后，若当前显示帧尚未有新点且与预测器状态相邻，Resume Auto 会先处理当前帧，避免直接跳过它。

### 8.6.3 Alt 临时接管

Alt 必须与视频内的左键点击组合使用。只按 Alt 不进入标记状态，不切换功能页，不生成跟随光标的框。

| 接管前状态 | Alt + 左键点击 | 松开 Alt |
| --- | --- | --- |
| 没有 Tracking 会话 | 开始临时人工会话并立即修正本次点击所在帧 | 提交本次临时会话为一次 History 编辑 |
| 已有人工会话 | 在原会话中修正当前帧 | 保留原会话，不提交整段 |
| Auto 正在运行 | 使在途结果失效并人工接管，保留模板和既有点 | 无未解决失败时恢复 Auto；有失败则保持暂停 |
| Auto 已暂停，包括低分暂停 | 在原会话中修正并按条件重试 | 保持暂停；需要 `Resume Auto` 才继续 |
| Camera Anchor 会话 | 暂停并提示使用 `Correct` | 不把点击写成物体轨迹 |
| Trajectory 预览活动 | 先处理预览 | `Apply / Discard` 后才能进入物体人工接管 |

接管正在运行的 Auto 时，人工 W/H 优先填入刚经过的相邻帧框尺寸；没有相邻点时使用当前可用框。人工修正会更新识别中心及运动预测起点，避免继续沿修正前的错误预测前进。

松开 Alt 时，如一次 Auto next 解码或人工重试尚在处理，会等待该操作结束再提交或恢复。窗口失去焦点时结束临时接管，但不自动恢复 Auto。

Alt 临时接管期间按 Esc，只撤回这次接管产生的修改；原先已有的待提交轨迹保留。无既有会话时，Esc 丢弃本次临时会话。普通非临时会话中 Esc 执行 Cancel。

### 8.6.4 失败帧的人工校正与重试

低分暂停时，画面显示该次候选模板框与搜索框。候选框只说明算法尝试的位置，不说明该帧已通过识别。

人工指定位置后，程序先记录人工点，再保留模板库并以修正位置为依据重试同一帧。重试候选必须满足：

1. Score 达到阈值。
2. Margin 达到阈值。
3. 候选最终中心与人工中心的横向差不大于 `max(3 px, 人工框宽度 / 2)`。
4. 纵向差不大于 `max(3 px, 人工框高度 / 2)`。

通过时，可用匹配结果细化该人工点；过远或低分时保留人工点。该次细化并入原人工操作的局部撤销步骤。

**示例：** 人工框为 10 × 8 px，允许的候选中心差分别为 5 px、4 px。候选分数虽高，但横向距离为 20 px，则不接受为人工修正后的目标，避免点击目标后又跳到相邻个体。

持续人工状态中的失败重试通过后可恢复 Auto；Alt 接管还要遵守上表的松键规则。尤其是接管前已经暂停时，即使本帧重试通过，松开 Alt 后也不自动将暂停状态改为运行。

### 8.6.5 人工标记与新增模板的区别

普通左键人工标记或 Alt + 左键只指定位置，保留已有模板，不新增外观样本。需要让自动匹配适应新的外观时，必须使用 `Add Template` 或 Alt + Shift + 左键。

## 8.7 模板建立与模板库管理

### 8.7.1 建立模板的实际动作

`Add Template` 进入选模板状态，下一次视频内点击立即截取模板；该帧同时产生来源为 `manual_box` 的待提交框。调整 `Template area` 后释放鼠标也会从当前帧重新截取模板，并更新该帧的待提交框。

Alt + Shift + 左键在视频内完成同样的取样，并跳到 `Tracking → Track Motion`。只按 Alt + Shift、在视频外点击，均不进入模板选择流程。模板建立后必须手动点击 `Run Auto`；组合键不会自行开始连续识别。

模板数量不设固定前置要求：一个有效模板即可运行。模板来自不同帧时加入库中；同一帧再次取样会替换该来源帧的模板，不保留同帧多个模板。

### 8.7.2 取样原则

模板宜包含目标上可辨、在后续若干帧保持一致的纹理或轮廓。模板过小可能缺少区分不同位置的信息；过大可能把大量变化背景引入相似度计算。

| 图像条件 | 取样处理 | 预期效果 |
| --- | --- | --- |
| 目标上有稳定头部或胸部纹理 | 取该特征，必要时设置 Mark offset | 识别特征与最终标注中心分离 |
| 光照发生明显变化 | 在新光照下补充一份模板 | 用新外观竞争匹配，不依赖旧样本逐帧演化 |
| 背景随位置明显变化 | 减少背景比例，并在代表位置补样 | 降低背景纹理主导评分的机会 |
| 遮挡或严重模糊 | 在清晰帧取样，遮挡段人工修正 | 避免把遮挡物当作新目标外观 |
| 区域近乎纯色 | 扩大到有结构的特征或更换位置 | 增加可定位信息 |

亮度变化极小的模板缺少有效定位证据，可能被保存到库中但无法产生有效匹配候选。模板存在不等于模板适合当前帧。

### 8.7.3 多模板的选择机制

每个启用模板独立评估候选，程序从可用结果中选择最佳匹配。不是先把所有模板平均成一张图，也不是要求每个模板同时通过。

同一空间位置由多个模板同时匹配到，不自动算作多个竞争目标；不同位置的高分结果可降低 Margin。增加模板能够覆盖不同外观，也会增加计算量和错误候选的机会。

**示例：** 模板 A 对亮处目标评分高，模板 B 对暗处目标评分高。目标进入暗处后可以由 B 获胜，A 保持原有样本；无需人为切换“当前 ID”。若 A 同时在另一只昆虫上得到接近 B 的高分，Margin 可能不足并暂停，需检查模板或缩小搜索区。

### 8.7.4 预览、启用与删除

列表单击只改变预览，不等于只使用这份模板，也不一定改变当前活动模板。预览显示原始截取图像，不显示每一步 Evolution 后的演化图像。

要操作某模板的来源位置及偏移，可双击其列表行：程序暂停、选择该模板并定位到来源帧。要限制匹配只用它，应再使用列表复选框或 `Use selected only`。

模板复选框、启用操作和删除操作会暂停 Auto。全部模板停用时不能运行 Auto；需要至少启用一份。删除全部模板后，已有标注仍保留，状态按钮回到人工方式所用的 `Start`。

停用适合暂时排除旧光照、旧姿态样本；删除适合不再需要的样本。先检查预览再删除。局部 Ctrl + Z 针对点操作，不作为模板库管理的撤销入口。

**管理示例：** 库中有 F100、F500、F900 三个模板，只选中 F500 后按 Use selected only，只有 F500 参与后续匹配；按 Enable all 恢复三者。Remove selected 则从库中移除选中样本，不删除第 500 帧的位置记录。Use selected only 之前应确认已有选中行；没有选中项时会停用全部模板。

### 8.7.5 模板的生命周期

模板保留在当前追踪会话中，暂停、普通导航、人工接管和 Tracking 子页切换不会清空模板库。`Finish`、`Cancel` 及触发会话结束的动作会清空模板库。

普通标注 SQLite 保存位置和相关评分字段，不保存模板图像及可继续演化的模板库。重新打开结果后需要重新取模板再自动追踪。

## 8.8 模板区域、搜索区域与搜索方式

### 8.8.1 两个区域的含义

| 区域 | 颜色 | 定义 | 改动后果 |
| --- | --- | --- | --- |
| `Template area` | 青色 | 用来描述目标外观的图像区域 | 重新截取当前帧图像，并影响自动输出框的基准尺寸 |
| `Search area` | 黄色 | 本帧允许寻找模板的局部区域 | 改变可搜索位置与计算量，不修改模板图像 |

两个工具固定使用 XYWH：拖动框内移动，拖动控制点改变大小。开始 Auto 会退出区域调整状态。修改搜索区后应检查其是否覆盖下一帧可能位置，而不只是包围当前目标。

搜索区必须包含完整候选模板。画面边缘会限制有效搜索范围；启用旋转或缩放时，还要容纳变换后的模板外接范围。搜索区过小会漏掉目标，过大会增加候选与处理耗时。

**示例：** 目标单帧可能水平移动 20 px，模板宽 19 px。将搜索框仅设为 20 px 宽，不能提供两侧各 20 px 的中心移动范围；还须计入模板自身宽度。

### 8.8.2 搜索中心

| `Search` | 中心依据 | 适用条件 | 边界行为 |
| --- | --- | --- | --- |
| `Predict` | 已接受位置建立的 Kalman 匀速预测 | 位移具有一定连续性 | 急转、停顿或长期拒绝后可能偏离，需要扩展搜索区或人工重定位 |
| `Follow` | 最近一次接受的识别位置 | 位移较小、速度不稳定 | 不向前外推速度；目标必须落在以旧位置为中心的范围内 |
| `Fixed` | 固定绝对中心 | 固定活动区、接近静止目标 | 目标离开范围后不自动跟随 |
| `Cursor` | 视频中的鼠标位置 | 人工知道目标所在区域 | 与 Mouse guided 联动，须按住左键引导 |

移动 Search 框，在 Predict、Follow、Cursor 下设置相对中心偏移；Fixed 使用固定绝对中心。人工校正会把识别中心重置到修正结果，并清零原有搜索偏移，后续范围应重新检查。

运动预测以识别特征中心为依据。设置 Mark offset 后，最终标注中心可与该中心不同；人工指定的是最终目标位置，程序据偏移反求识别中心。

### 8.8.3 Mouse guided 规程

1. 建立可用模板。
2. 启用 `Mouse guided`，Search 同步为 `Cursor`。
3. 退出 Template area、Search area 或 Mark offset 等显式编辑工具。
4. 将光标放在目标附近，按住左键。
5. 随画面变化移动光标，维持目标位于黄色搜索区域内。
6. 松开左键或移出视频，追踪立即暂停；再次按住可继续。

Mouse guided 只引导搜索区域，不把每次鼠标位置直接当作标注中心。接受条件仍由 Score 和 Margin 决定。需要直接指定位置时使用 Alt + 左键。

取消 Mouse guided 时，Cursor 搜索回到 Predict；从 Search 主动选择 Cursor 也会启用 Mouse guided。仅点击 Run Auto 而没有按住左键时，程序提示等待鼠标引导。

### 8.8.4 倒序追踪

勾选 `Reverse` 后，从当前帧向第 1 帧运行。切换方向会暂停并使在途结果失效，模板与待提交点保留。Auto next、Previous box 和已有点冲突判断使用同一方向。

**示例：** 第 600 帧目标清晰，第 500–599 帧尚未标注。可在 600 帧建立模板，勾选 Reverse，向前补到 500 帧。到达第 1 帧自动停止；仍需 Finish 提交。Rate 显示正倍速，不以负号表达倒序。

## 8.9 匹配评分与停止条件

### 8.9.1 Score 的组成

程序先使用亮度及梯度相关响应寻找局部候选，再对候选计算以下五项特征，按 Match weights 合成分数。不同位置中分数最高者为最佳候选。

| 特征 | 原理 | 调整权重的典型影响 |
| --- | --- | --- |
| Luma | 灰度图样的归一化相关，负相关按 0 处理 | 增大后更重视明暗纹理是否对齐 |
| Gradient | 梯度强度图样的归一化相关 | 增大后更重视纹理变化与轮廓附近的强弱结构 |
| Color | 比较模板与候选区域的平均颜色差 | 有稳定色差时有帮助；平均颜色相近不代表同一个体 |
| Edge | 比较边缘像素的交集与并集 | 增大后更重视边缘重叠；模糊可能削弱该项 |
| Motion | 候选靠近本次搜索中心时得到更高先验值 | 有助于抑制远处竞争位置；预测错误时也可能偏好错误区域 |

五个输入作为相对权重归一化，合计不必恰好等于 100。某项为 0 时，该项不进入最终加权分数；全部设为 0 会失去有效评分依据，应避免。候选生成阶段仍使用亮度和梯度，不能把 Color = 100 理解为不经过结构候选筛选的全区域颜色查找。

**权重示例：** 若提高 Gradient 而降低 Color，轮廓结构相似但整体颜色略变的候选可能更有优势；若提高 Color，平均颜色不同的背景候选影响可能下降，但同色邻近昆虫仍可能竞争。提高 Motion 会更偏向搜索中心附近，目标急转离开预测中心时反而可能不利。比较某项影响时，宜一次只调整一项并核对同一帧；不能保证所有画面都随同一权重增加而更准确。

Score 是本程序的加权匹配指标，不是“目标身份正确的概率”，也不是 YOLO confidence。相同数值在不同模板、搜索范围和权重下不一定具有相同可靠性。

### 8.9.2 Margin 的定义

设最佳候选分数为 `S₁`，另一空间位置的竞争分数为 `S₂`：

`Margin = S₁ − S₂`

邻近像素构成的同一响应峰、同位置的不同模板或姿态，不直接作为另一目标计入竞争分数。Margin 用于区分“最佳位置是否明显优于其他位置”。

界面以百分数显示，但 Margin 表示两个分数的差。例如 85% − 81% = 4 个百分点；Margin 阈值 6% 在这里表示差至少为 0.06，不表示差值除以 85%。

### 8.9.3 接受条件与颜色

匹配位置必须同时满足：

`Score ≥ Score 阈值`，并且 `Margin ≥ Margin 阈值`。

等于阈值可通过。Score 和 Margin 分别按各自条件显示绿色或红色。

| 最佳分数 | 竞争分数 | Margin | 阈值 72% / 6% 下的结果 | 原因 |
| --- | --- | --- | --- | --- |
| 85% | 74% | 11% | 接受 | 两项均通过 |
| 85% | 81% | 4% | 拒绝 | 外观分高，但不同位置之间歧义较大 |
| 68% | 40% | 28% | 拒绝 | 位置虽相对突出，外观相似度仍不足 |
| 72% | 66% | 6% | 接受 | 两项均恰好达到阈值 |

显示值描述最近一次尝试匹配的结果。暂停后跳到其他帧、进行普通人工标记或只调整显示，不会自动为当前帧重新评分；不能把保留的绿色数值当作当前帧已经重新通过识别。

### 8.9.4 Stop due to

| 选项 | 暂停条件 | 未通过接受条件时是否写入自动点 |
| --- | --- | --- |
| `Poor match` | 没有候选，或 Score / Margin 任一未达阈值 | 否 |
| `No match` | 没有候选，或最佳 Score 不超过 20% | 否；高于 20% 但仍未达接受阈值时继续尝试后续帧 |
| `Never` | 不因普通匹配拒绝而暂停 | 否；继续尝试后续帧 |

停止策略只决定拒绝后是否继续运行，不改变接受标准。`Never` 不表示把每帧最高分位置全部写入，也不表示遇到视频结束、解码错误或已有点冲突后仍继续。

**示例：** Score 阈值为 72%、Margin 阈值为 6%，某帧得到 Score 65%、Margin 10%。Poor match 暂停；No match 和 Never 可以继续尝试下一帧，但这一帧不新增自动标注。

### 8.9.5 阈值调整顺序

发现连续拒绝时，应依次检查身份、画面帧、模板内容、搜索覆盖和候选位置，再判断是否调整阈值。仅降低阈值可能使错误目标通过。

- Score 低、Margin 高：优先检查外观变化、模板尺寸或模糊。
- Score 高、Margin 低：优先检查相似目标、背景纹理、过大的搜索区或不再适用的模板。
- 两项都低：先人工重新定位并检查模板。
- Score、Margin 都高而目标错误：说明图像相似性不足以确认身份，需要人工约束或更换识别特征。

## 8.10 模板演化与原始模板约束

### 8.10.1 Evolution 与 Tether

每份模板包含原始取样图像和供后续匹配使用的演化图像。只有接受匹配时，获胜模板才更新；其他模板不因这一帧一起改变。拒绝的候选不演化模板。

记：`T₀` 为原始模板，`T` 为本次匹配使用的演化模板，`P` 为接受位置的图像，`E = Evolution / 100`，`H = Tether / 100`：

```text
先演化：T′ = (1 − E) × T + E × P
再约束：Tnext = (1 − H) × T′ + H × T₀
```

图像混合按像素计算，整数图像会有舍入。启用旋转或缩放时，先把接受位置图像反变换到模板基准坐标，再进行混合。

| 设置 | 行为 | 适用理解 |
| --- | --- | --- |
| Evolution = 0，Tether = 0 | 演化图像保持不变 | 完全固定外观 |
| Evolution = 0，Tether > 0 | 不引入新匹配图像，已有演化结果逐步回归原图 | 不等于冻结此前已经演化的模板 |
| Evolution 增大 | 更快吸收新外观 | 可跟随变化，也更易把一次错误吸收进模板 |
| Tether 增大 | 更强地保留原始模板影响 | 抑制漂移，但可能不易适应明显光照变化 |
| Tether = 100 | 每次更新后恢复原始模板 | 后续匹配使用原始外观 |
| Evolution = 100，Tether = 0 | 以最近接受位置图像替换演化模板 | 对连续变化响应快，对错误接受敏感 |

**示例：** Evolution = 5%、Tether = 10% 时，更新结果约由 85.5% 的旧演化模板、4.5% 的本次匹配图像和 10% 的原始模板组成。5% 不是“拿上一帧位置与当前帧位置平均”，也不是轨迹坐标平滑力度。

### 8.10.2 演化与多模板的关系

逐步亮度变化可由演化适应；出现明显新姿态、新遮挡关系或背景变化时，可补充代表性模板。模板库是多份独立外观样本，Tether 约束各自回到自己的原始图像，不会把不同模板互相混合。

沿原追踪方向退回可靠位置重新运行时，程序可以恢复模板库的原始外观，并从当前可靠点重建预测起点，避免直接沿用错误段后方的演化状态。该行为不恢复已经被删除的模板，也不替代对错误标注的覆盖或删除。

## 8.11 旋转、缩放与标记偏移

### 8.11.1 Rotate 与 Scale

启用 `Rotate ±°` 后，搜索相对模板基准外观的正负旋转；启用 `Scale ±%` 后，搜索相对模板基准尺寸的缩放。二者可分别或同时启用。

**示例：** Rotate ±30°、Scale ±20% 表示围绕该模板搜索约 −30° 至 +30°、0.8 至 1.2 倍的外观。下一帧仍相对该模板基准搜索，不把 1.2 倍逐帧累乘。

算法使用由粗到细的离散姿态候选：粗角度间距不大于约 10°，粗尺度间距不大于约 0.1，再细化最佳姿态附近。输出角度和比例是模板匹配近似值，不是连续精密姿态测量。

变换产生的无效填充区不作为评分依据。搜索框容不下的姿态候选会被跳过。范围越大、同时启用的变化越多，计算量越高。

改变开关或范围会暂停 Auto。应先调整 Search area，再继续运行。替换或新建模板重新定义该样本的角度零点和基准尺寸。

### 8.11.2 输出框与姿态

标注仍使用轴对齐 `x/y/w/h`。旋转后的模板以轴对齐外接框表示，因此框可能比目标本体宽；这不表示保存了旋转矩形。相应匹配角度和比例另记为 `match_rotation_deg` 与 `match_scale`。

正角度表示原图中的逆时针外观变化。该值相对模板，不等于稳定后的绝对身体朝向，也不扣除真实目标形变、遮挡和相机投影的影响。

### 8.11.3 Mark offset 的含义

识别中心与标注中心可以不同。模板可放在头部、纹理斑块等清晰特征上，最终位置则落在身体中心或其他约定点。

操作规程：

1. 在当前帧完成模板取样或接受匹配。
2. 点击 `Mark offset`。
3. 在视频中点击最终希望记录的目标中心。
4. 检查最终框的位置，再运行 Auto。

若当前显示帧不是引擎已取样或已识别的帧，程序要求先在该帧设置模板，不从不对应的旧识别位置计算偏移。

也可在 Match weights 输入 Offset X/Y。数值对应当前活动模板；修改前可在 Templates 双击所需样本。不同模板各自保存偏移，不会因修改一个模板自动重写所有模板。

### 8.11.4 偏移变换原理

设模板基准偏移为 `(dx, dy)`，识别尺度为 `s`，角度为 `θ`，识别中心为 `(xr, yr)`。原图 y 轴向下时：

```text
Δx = s × (cosθ × dx + sinθ × dy)
Δy = s × (−sinθ × dx + cosθ × dy)
标注中心 = (xr + Δx, yr + Δy)
```

**示例：** 识别特征中心为 `(100, 80)`，最终身体中心位于其下方 12 px，偏移为 `(0, 12)`。无旋转、尺度为 1 时记录约 `(100, 92)`；尺度变为 1.2 时偏移变为 14.4 px；逆时针旋转 90° 时，该基准向下偏移转向原图右侧。

修改偏移会影响该模板的后续结果；当引擎位置与当前帧一致时，也更新当前帧待提交框。它不是对整条已生成轨迹执行平移。整段平移使用 Trajectory 的 Transform。

偏移改变框中心，不独立规定最终框尺寸。Auto 的初始框仍取自匹配模板的外接范围；需要更贴合身体轮廓时使用适当模板尺寸、Assist 或其他框编辑操作。

## 8.12 框细化 Assist

### 8.12.1 共同行为

Assist 对人工标记和接受的自动标记均可用。位置先立即形成初始框，之后后台尝试细化；细化失败时保留初始框，不删除该点。

所有细化结果都必须通过局部边界检查：

- 保持初始指定位置在框内；人工点击位于图像边缘时，还检查真实点击位置。
- 横向中心变化不超过 `max(2 px, 初始宽度 / 2)`，纵向不超过 `max(2 px, 初始高度 / 2)`。
- 宽度不超过 `max(8 px, 初始宽度 × 2)`，高度不超过 `max(8 px, 初始高度 × 2)`。
- 坐标有效、尺寸为正，并能限制到视频边界内。

**示例：** 初始框 10 × 8 px，允许的宽高上限为 20 × 16 px，中心各轴偏移上限为 5 px、4 px。模型检出一个 60 × 40 px 的邻近大区域时，不会用它替换初始框。

### 8.12.2 None

不进行图像细化，保留人工或模板匹配的初始框。适合框大小有固定定义、目标图像较模糊或需要严格控制标记范围的任务。

### 8.12.3 Edge

在初始中心附近分析颜色相近区域，结合边缘阻断寻找包含中心的连通区域，以其包围范围生成候选框。过小、过大、无可靠连通区域或未通过共同边界检查时保留初始框。

Edge 不识别 `bee`、`hornet` 等语义类别。在目标与背景颜色接近、纹理断裂或边缘模糊时，结果可能被拒绝；无需为保留原框的行为重复点击。

### 8.12.4 YOLO

使用 Detection 中配置的模型、Device、Half 等设置，通过外部 DetectionWorker 对局部 ROI 推理。模型按需加载并复用；不要求先对整个视频完成 Detection。

操作规程：

1. 在开始 Tracking 会话前，到 Detection 选择有效模型及运行设备。
2. 确认目标类别与模型类别名称一致，名称比较忽略大小写。
3. 回到 Tracking，将 `Assist` 设为 `YOLO`。
4. 进行人工点选或 Auto。观察初始框及随后返回的细化结果。
5. 状态提示模型不存在、类别不存在、设备错误或推理失败时，修正配置；已有初始框保留。

局部候选先限定为同类别，并在包含初始点的候选中优先选择中心较近者；最终仍必须满足共同边界检查。ROI 推理使用自身的局部配置，不能假定所有全视频 Detection 参数都逐项作用于 Assist。模板匹配的 Score 阈值也不控制 YOLO 置信度。

YOLO 支持运行环境可用的设备；选择 auto 时按检测环境的可用设备选择，CUDA 可用时可以使用 GPU。半精度只在支持的设备上生效。模板自动追踪本身仍使用 CPU/OpenCV，启用 GPU YOLO Assist 不会把模板匹配也变为 GPU 算法。

### 8.12.5 异步与时效性

细化不等待用户下一次点击，也不保证每个快速产生的点都完成 YOLO 处理。队列保留一个在途请求和最新等待请求，较旧的等待工作可被替换，避免延迟不断累积。

同帧重新标记、暂停、导航、切换 Assist、Finish 或 Cancel 后，失效结果不能再覆盖新的位置或已结束的会话。被接受的细化合并进其原始点操作的局部撤销记录，不额外增加一条点操作。

全视频 Detection 运行时，ROI 辅助暂不可用，人工初始框仍可记录；全视频检测结束后可重新准备辅助模型。更换模型、设备或精度后，下一次辅助请求会按新配置准备 worker。

外部独立 DetectionWorker 必须支持 ROI 服务接口。旧的独立 worker 不支持时，状态行提示问题并保留初始框；不能据此推断原始人工标记失败。

## 8.13 覆盖、删除、撤销与重做

### 8.13.1 同帧同 ID 的处理

人工或自动编辑某一帧后，该帧该 ID 保留一个最终位置。反复点击同帧更新位置，不叠加多个本 ID 框。原数据若有同 ID 重复行，在编辑该帧时被整理为本次位置；未编辑帧不因开始会话而整体去重。

其他 ID 不被替换。位置与另一只昆虫重叠也不自动合并身份。Undo 可恢复编辑前该帧的原记录，包括原来存在的重复行。

### 8.13.2 Overwrite 的两层许可

未勾选 Overwrite 时，Auto 在处理方向上的已有同 ID 点之前暂停，已有点包括已提交和本会话待提交点。再次点击 Run Auto / Resume Auto，会询问是否允许本轮连续运行覆盖。选择 Yes 后，本轮可跨越已有位置；暂停即结束这次临时许可。

勾选 Overwrite 后，Auto 可直接重新识别并替换已有点，不再因该冲突询问。覆盖是使用当前模板和预测重新识别，不是跳到原错误坐标继续沿用。

人工直接指定是明确的单帧修正，不受 Auto 的覆盖确认约束。Overwrite 不表示重新分配 ID，也不表示接受低分结果。

**示例：** 2000–2200 帧已串到相邻昆虫。回到 1999 帧可靠位置，必要时人工修正起点并重新取模板，启用 Overwrite 后重追。接受的新结果逐帧替换旧点。若某帧新匹配被拒绝，该帧不会因此自动清除旧错误点；需要删除错误范围时使用 Delete。

### 8.13.3 单点删除

在活动 Tracking 会话中，画面焦点下按 Delete，删除当前帧本 ID 的位置。删除对象可以是待提交点或会话开始前的已有点；其他帧及其他 ID 不变。空帧上按 Delete 不创建删除记录。

输入框获得焦点时，Delete 保留文本编辑功能。Trajectory Edit 预览中的 Delete 用于删除所选控制锚点，与 Tracking 单帧点删除不同。

### 8.13.4 范围删除

1. 在 `Track Motion` 点击 `Delete`。
2. 在 `Delete track range` 窗口的 `Frames` 输入帧或帧段，例如 `100-140, 200, 260-275`。
3. 拖动视频进度条核对起止位置，同时检查删除预览条带。
4. 点击窗口中的 `Delete` 确认。
5. 检查结果；必要时 Ctrl + Z 撤回本次范围删除。
6. `Finish` 后与同一会话的其他点修改一起提交。

范围包含两端，限制在视频有效帧内；留空使用当前帧。`140-100` 按 100–140 处理，`-140` 表示从视频首帧到 140，`200-` 表示从 200 到末帧。多个范围用英文逗号分隔。无效范围不能确认。窗口为非模态，打开时可以继续导航。关闭窗口而不确认不执行删除；已进入的 Tracking 会话仍需按实际需要 Finish 或 Cancel。

一个范围删除作为一次局部操作撤销。删除的是当前目标的记录，不删除视频画面，也不删除模板库；之后可重新识别这些帧。

### 8.13.5 提交前与提交后的撤销

| 时机 | Ctrl + Z / Ctrl + Y 的作用 | 不包含的内容 |
| --- | --- | --- |
| Tracking 未提交 | 逐次撤销/重做点操作；范围删除为一步；自动点通常一帧一步 | 不撤销模板启用、删除等库管理动作，不恢复整套 UI 参数 |
| Alt 临时接管 | 点操作仍在局部栈中；Esc 撤回本次接管 | 不清空接管前的会话 |
| Trajectory 预览 | 撤销/重做一次拖动、一笔重绘或一次预览修改 | 尚未写入全局 History |
| Finish 后 | 整个 Tracking 会话作为一次全局 History 编辑 | 不再逐帧拆开该会话撤销 |
| Trajectory Apply 后 | 整次曲线修改作为一次全局 History 编辑 | 不逐个控制柄撤销 |

局部撤销以受影响点的差量记录，不为每一帧写入完整 History。撤销点操作会暂停 Auto，并可定位到被撤销操作的帧；继续追踪前应检查当前起点。

`Pending` 是本会话当前持有的待提交位置和删除数量，不是鼠标点击次数或撤销步骤数。同一帧重复修改会增加局部操作，但通常仍只计一个待提交位置。

## 8.14 画面标记、轨迹与时间轴

### 8.14.1 当前帧框与候选框

当前帧尚未提交的标注框带有两条与框线同色、同粗细的交叉对角线，即 `⊠`。交点表示框中心，便于区别待提交框和普通已有框。

青色 Template area、黄色 Search area 用于取样、调整或诊断失败。低分时显示的候选框不等于已接受的标注框。切换到其他帧后，应以当前帧的状态和待提交框为准，不以最近一次评分推断该帧结果。

### 8.14.2 Show trail 与 Display

`Show trail` 与 `Display → Trail before` 是同一开关的两个入口。当前 Track ID 保持选中，已有点和待提交点合并显示，并沿用 Display 的帧范围、All/Simple、线型、颜色、透明度和宽度设置。

Trail before 的渐变轨迹按帧号显示当前帧之前的部分，不因 Reverse 自动改为“刚刚经过的方向”；Simple 可显示整条可用路径。Tracking 的待提交轨迹层使用 Trail before 配置，倒序追踪时查看本次待提交全段可使用 Simple。提交后的轨迹还可按 Trail after 配置查看当前帧之后的部分。

显示中的颜色、渐变、线宽和轨迹外观处理不改变 CSV 坐标。只有 Trajectory 的 Apply 等编辑操作才改变数据位置。隐藏 trail 也不删除标注。

### 8.14.3 时间轴条带

| 条带 | 含义 | 显示范围 |
| --- | --- | --- |
| 黄色 | 当前所选 ID 的出现范围 | 沿用选中 ID 的原有显示 |
| 绿色 | 本 Tracking 会话新增或替换的待提交位置 | Tracking 主面板，位于 Merge Target 对应层 |
| 黑色 | Delete 窗口正在指定的范围 | Tracking 主面板，位于 Merge Source 对应层 |
| 红色 | 删除范围与实际已有/待提交点的交集 | Tracking 删除预览的重叠层 |
| 蓝色 | Trajectory 当前选择的帧段 | `Edit → Trajectory`，位于 Target 对应层 |
| 悬停标记 | 画面中正在悬停的轨迹点帧号 | 与轨迹悬停联动 |

Delete 确认后，删除范围窗口关闭，黑色、红色预览不再表示一项仍待确认的操作。绿色条带表示有待提交结果，不表示所有经过帧均已成功识别。

### 8.14.4 公共轨迹点选

`Edit → Trajectory → Pick trail` 默认启用，可在不同主面板中使用；需要对应轨迹已显示。

鼠标靠近轨迹点时，显示直径为 10 屏幕像素的圆环，圆环用该 ID 的颜色；旁边显示 `class ID (frame)`，例如 `hornet 123 (2301)`。文字使用悬停位置的 trail 颜色，随 Simple 或渐变设置变化。进度条同时标示该帧。

单击跳到最近轨迹点对应帧。空间位置接近或轨迹交叉时，结合当前帧优先选择时间更接近的位置；需要精确选择另一趟经过时，可先把当前帧移到该时间附近。

显式框编辑、标尺控制点、Camera Anchor、Tracking 人工标记及 Trajectory 预览具有各自的点击用途，不被普通 Pick trail 抢占。Alt + 左键仍用于人工标记，Ctrl + 左键保留原有多选功能。

## 8.15 运行速度与绘制设置

### 8.15.1 Speed 与 Rate

底部 `Speed` 控件限制 Auto 和 Mouse guided 的实际显示切帧速度上限。若视频标称 25 FPS，Speed = 1 时最多按约每秒 25 帧的节奏推进；Speed = 2 时上限约为每秒 50 帧。

Rate 根据最近约 2 s 的实际帧进度与标称 FPS 显示倍速。只有结果确实等待限速时，才追加类似 `0.99x (limit 1x)` 的内容；识别本身未到上限时不显示 limit。刚开始、暂停或重新定位附近的短时 Rate 不代表稳定吞吐量。

识别慢于上限时逐帧继续，不跳过图片来凑播放倍速。匹配失败但停止策略允许继续的帧仍会被尝试，只是不生成有效自动点。

### 8.15.2 Decode ahead 与 Match workers

Decode ahead 提前解码随后一张图片，同时匹配当前帧。它不提前接受未来结果，也不让模板演化跨越帧顺序。暂停或人工修正后，过期预解码、匹配结果失效。

Match workers 在多个启用模板之间并行评估。模板独立评分可以并行，但预测器更新、获胜模板演化和逐帧写入必须按追踪顺序执行。只有一个模板时，增加此数值不会把相邻多帧同时独立追踪。

比较性能时，应使用同一段视频、相同模板、搜索范围和姿态设置，分别测试 1、2、4 等工作线程。Rate 已达 Speed 上限时，界面倍速无法直接反映额外计算能力，应结合 Rate 悬停中的 `Decode wait` 和 `match` 耗时判断。

### 8.15.3 性能调整次序

1. 检查是否已被 Speed 限速。
2. 停用过时或无关模板。
3. 缩小到足以覆盖运动的搜索范围。
4. 只在确有外观旋转或尺度变化时启用相应搜索，并限制范围。
5. 比较 Decode ahead 与 Match workers 的实际耗时。
6. 在长轨迹显示中使用合适的 Trail before/after 帧窗口；需要时启用 OpenGL 渐变 shader。
7. 区分模板匹配、YOLO Assist、解码及绘制开销，不以总 CPU 占用率单独判断瓶颈。

倒序通常需要更多随机定位，可能慢于正向顺序解码。首次建立视频索引也可能暂时增加定位等待。

### 8.15.4 Overlay renderer 与 Gradient shader

入口：`Display → Overlay renderer → Gradient shader`。

shader 是在图形设备上执行的绘制程序。这里用于根据轨迹点与当前帧的时间关系计算渐变颜色、透明度和线宽，不用于识别目标。

| 绘制条件 | 行为 |
| --- | --- |
| OpenGL，启用 Gradient shader 且可用 | 播放、Tracking 待提交 trail 和 OpenGL 视频导出共享渐变绘制路径 |
| 关闭 Gradient shader | 使用原有轨迹绘制路径 |
| Qt raster | 使用 Qt 绘制，不执行该 OpenGL shader |
| wave 波浪线样式 | 使用已有支持该样式的路径，状态说明回退 |
| shader 编译或配置不可用 | 显示回退原因，并使用已有绘制路径继续显示 |

Template/Search 框、控制手柄、曲线预览和悬停圆环等少量交互元素保留 Qt 绘制。标注框及轨迹使用已有 Qt/OpenGL 标注后端。启用 Gradient shader 不需要 CUDA，也不启用 GPU 模板匹配。

播放及导出中轨迹的颜色、透明度和线宽取决于相同显示配置。预览后端可选 Auto、OpenGL、Qt raster；导出后端可选 Auto、OpenGL、CPU。导出使用 OpenGL 路径时可使用 shader，CPU 路径不使用该 shader。导出的轨迹图形不改变原标注 SQLite。

Gradient shader 自身失败后的回退，与整个 OpenGL 标注后端不可用时的处理不同。前者可回到原有 OpenGL 绘制方式；后者按 Overlay renderer 的后端回退流程处理，可能要求确认改用 Qt raster。

## 8.17 保存、恢复与数据字段

### 8.17.1 保存规程

1. 暂停追踪，检查当前帧、首尾及关键转弯处。
2. 处理所有 Trajectory 预览，选择 Apply 或 Discard。
3. 点击 Finish；确认不再存在待提交会话。
4. 在 History 检查本次编辑范围与身份。
5. 使用程序保存入口写入 CSV。按保存对话框完成核验及路径确认。
6. 需要验证文件时重新打开保存结果，抽查首尾、失败修正处和覆盖段。

仅点击 Pause 不完成步骤 3；仅点击 Finish 不完成步骤 5。保存入口可以先提交待提交 Tracking，但不替代对曲线预览的明确决定。

恢复快照用于意外中断恢复，可以包含待提交位置副本；它不提前把每一个局部操作写入普通 History。不能假定恢复文件或结果 SQLite 能重新建立当时的图像模板及所有运行状态。

### 8.17.2 位置来源

| `position_source` | 含义 |
| --- | --- |
| `manual_point` | 人工指定的点生成位置 |
| `manual_box` | 模板取样、模板区域或偏移等人工确定的框 |
| `template_track` | 普通 Auto 接受的模板匹配位置 |
| `guided_track` | Mouse guided 接受的匹配位置 |
| `edge_assist` | Edge 接受后的细化位置 |
| `yolo_assist` | YOLO 接受后的细化位置 |
| `curve_edit` | 已有位置经轨迹编辑、平滑、重绘、分配或变换修改 |
| `curve_fill` | 曲线工具补充的原本缺失帧位置 |

来源表示最终修改类别，不等于完整的所有处理步骤日志。多个 Trajectory 模式均写为 curve_edit；如分析需要具体算法与参数，应另保留处理记录和编辑前数据。人工失败重试通过时也可能保留人工来源并附有匹配分数，不能仅凭一个字段反推所有交互过程。

### 8.17.3 匹配与辅助字段

| 字段 | 含义与单位 |
| --- | --- |
| `frame` | 从 1 开始的实际解码顺序帧号 |
| `track_id`、`class` | 目标数字身份及类别 |
| `x / y / w / h` | 最终框中心及尺寸，源图像素 |
| `best_score` | 最佳模板匹配分数，保存为 0–1 数值，不是界面百分数字符串 |
| `second_score` | 竞争空间位置的分数 |
| `margin` | best_score − second_score |
| `template_frame` | 本次获胜模板的来源帧 |
| `recognition_x / recognition_y` | 应用 Mark offset 前的识别特征中心 |
| `match_rotation_deg` | 相对模板基准的旋转角度，度 |
| `match_scale` | 相对模板基准的尺度倍率，1 表示不缩放 |
| `assist_confidence` | YOLO 辅助的检测置信度，不等同于模板 Score |

字段只在相应操作产生信息时有意义；人工重写会清除不再适用的匹配数据。最终 x/y 可能包含 Mark offset 和 Assist 调整，而 recognition_x/y 描述识别阶段的位置，二者不同不一定是错误。

已有数据的其他字段按编辑规则保留。Tracking 的位置来源应优先查看 position_source 及 History，不能只用原有 `detected` 或 `confidence` 推断当前位置完全来自哪种算法。

## 8.18 典型应用流程

### 8.18.1 场景一：短段漏检，身份明确且仍可见

**条件：** ID 123 在 1000–1050 帧缺失，前后都是同一只胡蜂。

**操作：**

1. 在 999 帧选中可靠 ID 123 框，确认续用该 ID。
2. 以清晰特征建立模板，向前运行到缺失段。
3. 若遇到快速运动而失败，用 Alt + 左键修正并按松键规则继续。
4. 接近 1051 帧已有位置时，未启用 Overwrite 会因冲突暂停。
5. 比较新段末端与原有 1051 帧位置，确认身份及连续性后 Finish。

**效果：** 补充同一 ID 的缺失位置，保留后方可靠已有段。匹配失败且未人工标记的帧仍为空。

### 8.18.2 场景二：整段未标注，只有几个关键位置容易确定

**条件：** 目标可人工确认，但大部分帧模糊，无法稳定自动识别。

**操作：**

1. New 建立身份，关闭 Auto next。
2. 在 100、110、120 帧分别人工指定可靠中心并提交。
3. 在 Edit → Trajectory 选择该 ID、范围 100–120。
4. 选择 Edit、勾选 Fill gaps、Preview。
5. 如实际路线弯曲，在中间帧增加或拖动锚点，并调整手柄。
6. 逐帧检查预览后 Apply，保存。

**效果与原理：** 关键位置之间生成逐帧补间，新增帧标为 curve_fill。结果是由人工位置和曲线约束估计的轨迹，不是每帧模板都识别成功。相同工作目标也可通过 Edit 的 Change position 与 Interpolate 组合实现；本规程使用 Tracking 人工关键位置与 Trajectory 补帧完成。

### 8.18.3 场景三：自动串到邻近个体后重新追踪

**条件：** 同 ID 在 2000–2300 帧错误跟随另一只昆虫。

**操作：**

1. Pause，回到 1999 帧或更早的可靠位置。
2. 人工核实身份，必要时修正起点。
3. 删除不合适的模板或补充可靠模板。
4. 若错误段任何旧点都不应保留，先用 Delete 删除 2000–2300；否则勾选 Overwrite 逐帧替换。
5. 重新运行，检查失败帧并补充人工点。
6. 确认后 Finish。

**效果：** 覆盖仅替换新接受的位置；先删除则避免重追失败帧继续保留旧错误记录。操作均可在提交前逐步撤销，提交后整段撤销。

### 8.18.4 场景四：光照变化与多模板

**条件：** 同一目标从亮处进入阴影，旧模板 Score 持续降低。

**操作：** 在身份明确的阴影帧添加新模板，保留亮处模板供回到亮区时使用。观察两者在不同位置是否产生竞争；不再需要亮处样本时停用。分别检查两个样本的 Mark offset 是否指向同一解剖位置。

**效果：** 同一 ID 根据外观由不同模板获胜。增加模板不增加同帧位置数量，也不消除所有身份歧义。

### 8.18.5 场景五：以头部识别、以身体中心标注

**操作：** 用头部特征取模板，Mark offset 点击身体中心；需要姿态变化时启用适度 Rotate/Scale；Assist 以偏移后框为依据细化。添加另一帧模板时重新核查该样本偏移。

**效果：** 图像匹配依据头部，最终 x/y 表示身体约定位置。偏移随估计姿态变换，但目标身体变形或相对头部运动并不能由一个固定偏移向量完整表达。

### 8.18.6 场景六：急转弯被错误拉直

**操作：** Pick trail 定位错误段，在 Set 模式下用 A/B 记录可靠两端。少量局部错误用 Edit 拖出转弯锚点；整段走向错误用 Draw 画出实际路径。先确认形状，再按需要使用 Redistribute，Apply。

**效果：** 中间帧重新落在编辑路径上。若没有 Fill gaps，不新增原来不存在的帧记录；若采用 Redistribute，速度分配会随模型改变。

### 8.18.7 场景七：近乎静止的蜜蜂轨迹带有毛刺

**操作：** 先逐帧确认尖刺不是实际运动。选择局部 Smooth，先以较小 Window、有限 Max px 预览 Median 或 Savitzky-Golay；必要时调整 Keep corners。若整个位置有一致偏移，先或后使用 Transform 单独纠正整体偏移。

**效果：** 平滑处理随机局部变化，Transform 处理系统性偏移。二者作用不同，不宜用过强平滑弥补错误的整体位置。

### 8.18.8 场景八：静止个体消失后以新 ID 重现

**条件：** 蜜蜂基本未移动，检测框短暂消失后以不同 ID 出现。

**处理边界：** 首先核实是否为同一个体，使用 Edit 的 ID 合并及插值流程统一身份；可利用 over-time 区域选择与 Selected ID 出现段定位前后范围。Tracking 不能仅通过输入旧 ID 自动把新 ID 的既有框全部合并过来。

统一身份后，可以用同一 ID 从缺失段一端正向或反向补追；若只可确认两端而无法识别中间，应采用明确的插值或 Fill gaps，并保留估计来源。

# 9 Scale 操作说明

[返回总目录](#0-引言)

## 9.1 目的与测量前提

Scale 建立图像像素与真实厘米之间的度量关系。近似正视平面可使用统一 px/cm；斜拍、透视变化或局部比例不同的场景需要多段长度和可能的真实角度约束。

Scale 与实验原点、Camera 稳定分开：Scale 决定距离度量；Hive/Axis 决定显示或实验坐标的参考原点；Camera 用背景锚点消除帧间相机运动。设置其中一个不自动完成另外两个。

标定对象应与目标运动处于相同或近似相同的测量平面。平面标定不能消除目标离开平面的视差。没有真实长度信息时，画出线条只提供几何方向，不提供厘米单位。

## 9.2 界面与状态

入口为 Edit → Scale。标定线主要在 Scale 与 Camera 页显示；切到其他页隐藏标定线不会删除数据。

| 控件 | 行为 |
| --- | --- |
| Scale (px/cm) | 非编辑时显示摘要；统一尺度显示单值，变化尺度可显示范围 |
| Changes / Apply | 开始一次标定事务；再次 Apply 将全部修改作为一项 History 操作提交 |
| Add bar | 在事务中新增无默认真实长度的标定线 |
| Condition | 显示数值条件；悬停可看拟合与交叉验证诊断 |
| Scale metric | 显示绝对长度是否存在及 affine/homography 约束秩 |
| Inputs / Need | 汇总线、长度、角度数量及仍需补充的约束 |

编辑时的结果为预览；Apply 后进入工作数据，Save as 后写盘。ESC 取消未提交的标定事务。取消不会删除进入编辑前已经保存的标定。

## 9.3 统一尺度输入规程

1. 确认整个测量区域的透视差异可以忽略。
2. 点击 Changes，在 Scale 框输入正的 px/cm。
3. 点击 Apply。
4. 开启 Axis/Metric grid 检查已知距离，再保存。

例如已知 5 cm 长度在图像中为 150 px，则尺度为 30 px/cm；60 px 的位移对应 2 cm。输入是 px/cm，不是 cm/px。输入一个数值会采用统一尺度表达，不能用一个平均数替代原有可变标定后仍期待局部修正保持不变。

## 9.4 标定线和长度编辑规程

### 9.4.1 新建与定位

1. 点击 Changes，再 Add bar。
2. 新线初始出现在画面中，尚无真实长度。
3. 点击端点选中，再指定正确位置；根据画布交互提示移动到尺子或已知标记上。
4. 另一端同样定位。放大图像有助于精确选点。
5. 在线段上右键加入中间点，用于表示可测的分段。

标定线按直线几何管理。中间点用于在线上分段，不应把一条弯曲物体轮廓当作单条直线标尺。移动端点后检查中间点和分段是否仍对应真实标记。

### 9.4.2 输入长度

左击线段打开画面内长度框，填写该段的实际厘米数，用 ✓ 或 Enter 确认。只有已确认的长度参与度量求解。

新增后续线段时，输入框可能根据当前标定给出建议长度。这是已有模型的估算，不是新的独立实测证据；应按实际已知长度核对后再确认。留空并确认可移除该段长度约束，保留其几何。

### 9.4.3 中间点与删除

右键线段加入点；右键点可选中，已选点再次执行相应删除交互会删除该点。删除后检查邻接段长度定义，不能假定原有长度仍对应相同两端。需要删除或重建一条线时，应核对随之失效的角度约束。

## 9.5 真实角度约束

按住 Ctrl 选择两条线，可打开角度编辑。画面内显示图像夹角与 `Real` 输入，分支按钮用于选择相应夹角方向。输入大于 0、小于 180 度的真实平面角度，再确认；留空清除这对线的角度约束。

**图像夹角不等于真实角度。** 斜拍的直角可能在图像中表现为锐角或钝角；反过来，两条图像近似垂直的线也不能据此认定真实垂直。仅在实际几何已知时填 90°。

**例：矩形标板。** 已知两边真实垂直，可以将各边作为线，分别记录实际边长，再添加 90°。若只是墙面上任意两条划痕，且真实夹角未知，则保留无角度约束。

## 9.6 五类标定模型

### 9.6.1 Uniform：统一比例

用一个比例描述所有位置和方向。厘米距离约为像素距离除以 px/cm，适合近似正视、尺度变化较小的区域。它不能修正方向性拉伸或透视收敛。

### 9.6.2 Projective 1D：单方向射影比例

单条线具有足够的分段长度信息时，可以刻画沿线方向的比例变化。远近不同位置的等长真实段在图像中可能长度不同。该模型只由一维证据支持，不能据此声称完整二维平面变换已经确定。

### 9.6.3 Local field：局部尺度场

多条线可提供不同位置的局部比例；二维约束不足时，程序使用局部尺度近似。它有助于描述空间变化，但不等价于具有完整角度关系的二维仿射/射影坐标系。离标尺很远处的外推应谨慎解释。

### 9.6.4 Affine：二维仿射度量

足够独立的长度和角度约束可以确定二维度量中的方向差异。仿射度量有 3 个独立分量；约束秩达到 3 才表示这部分信息充分。多条同方向长度往往重复提供相似信息，不等于自动满足三个独立约束。

### 9.6.5 Homography：二维平面射影度量

在不同位置和方向具有足够信息时，可拟合平面射影度量，处理透视带来的位置相关变化。度量判定使用 5 个独立约束方向；输入集中、近乎平行或共点过多时，即使数量足够也可能数值条件差。

模型选择优先使用足以解释数据的较简单模型。约束秩、数值条件和拟合结果共同影响选择；L、T、十字、矩形等线条外观不是模型类型。

## 9.7 Rank、Condition 与诊断

| 指标 | 正确解释 |
| --- | --- |
| Abs | 是否有绝对厘米长度依据 |
| Affine r/3 | 对仿射度量的独立约束秩，不是线条计数 |
| Homography r/5 | 对射影度量的独立约束秩 |
| Condition | 当前约束几何的稳定程度 |
| Fit RMS / Max residual | 对已输入长度或角度的拟合误差 |
| CV length error | 可计算时的留出长度检验；无冗余时可能为 N/A |

最少约束恰好拟合时，RMS 为零不表示测量没有误差。增加分布良好、方向不同的独立实测段，可用于检查外推和误差。不要反复输入由当前模型估算的建议长度来制造“冗余验证”。

Need 提示用于选择下一项有用输入，但不能代替判断某个真实长度/角度是否确实已知。

## 9.8 单值、范围和完整输出

`scale_px_per_cm` 始终是便于快速查看的代表性比例摘要。可变模型显示 `[min,max]` 时，表示局部尺度变化；它不是两项可直接输入的上下界设置。

完整 `scale_calibration` 保存标定类型、线点、已知长度、角度约束及相应模型数据，供恢复和下游度量使用。输出 CSV 保留完整 JSON；boutlist 的 `scale_px_per_cm` 与 `scale_calibration` 映射独立启用，可同时保存比例摘要和完整 JSON；清空相应列名可禁用该项回写。

对可变标定，后续分析若只把所有像素距离除以摘要比例，会丢失局部/方向性修正。必须确认分析程序读取了完整模型。Scale 页只负责建立和保存标定，不能保证外部分析脚本自动采用它。

## 9.9 Metric grid 与坐标原点

Metric grid 将厘米间距映射回图像用于检查。Uniform 网格近似等距；射影标定可出现收敛或非均匀间隔；局部场网格表示近似度量。Grid anchor 用于选择网格参考位置，Axis/Hive 原点不改变已输入长度和真实角度。

检查时应将网格与未用于拟合的真实标记比较。视觉整齐不构成精度证据。线条过密时增大物理间距或降低显示密度，不应通过改写真实长度来减少网格数量。

## 9.10 Camera 与 Expanded motion canvas

标定保留其坐标空间。普通画面上的标定使用原图空间；在扩展稳定画布中建立的标定使用相应稳定画布空间。显示时再转换到当前帧的位置，避免把屏幕缩放或相机补偿当成新的测量比例。

如果暂时关闭 Camera，原有稳定画布标定不会因此被重写成原图标定。在缺少必要变换时应恢复正确 Camera 状态再编辑，不能猜测转换。相机大幅变焦、景深变化或目标离开原测量平面时，应重新检查一套固定标定是否仍适用。

## 9.11 典型操作实例

### 9.11.1 一条均匀尺

选择清晰、接近目标平面的尺段，放置两端，输入实际长度，Apply。使用另一段已知长度验证比例，确认后保存。

### 9.11.2 一条尺远近比例变化

在同一直尺多个可识别刻度处设置中间点，对实际已知分段输入长度。检查是否得到沿线变化模型和合理刻度；不要把沿线信息过度解释为完整二维透视。

### 9.11.3 多方向标定

在测量区域分散放置多条已知长度，补充确实已知的真实角度。逐步观察 rank、Condition 和残差。比起在同一小区域增加多条近乎平行线，更应增加独立方向和位置的依据。

### 9.11.4 一段长度填写错误

Changes → 点击该段 → 更正 cm → 确认 → 检查模型和其他残差 → Apply。发现整体结果不合理时取消预览或在 History 撤销，不直接用摘要比例覆盖所有原始输入。

## 9.12 验收与保存规程

逐项确认测量平面、单位、端点位置、中间段长度和真实角度来源；检查模型是否与信息量相符，诊断是否存在明显退化；用未参与拟合的长度检查。Apply 后 Save as，重新载入确认原始线点、约束和模型仍可编辑。仅有 boutlist 摘要不足以重建完整标定。

# 10 Camera 操作说明

[返回总目录](#0-引言)

## 10.1 用途与坐标

Camera 估计背景相对运动，将图像与标注映射到稳定显示坐标。原视频框仍以源图像像素存储；不能把稳定画布上的屏幕坐标直接写入 CSV。Expanded motion canvas 扩大显示范围以容纳变换后画面，空白区不代表可标注的新图像。

## 10.2 人工锚点规程

1. 在静止背景上选择清晰、持续可见的特征；避免蜜蜂、胡蜂、反光或活动物体。
2. 选择锚点数量和活动 Anchor，在参考帧使用 Add 建立关键帧，放置相应背景点。
3. 移动到背景发生位移的帧，设置相同物理特征的新位置。
4. 开启 Enable，检查 HUD、Anchor 标记和表格；在关键帧之间播放检查。
5. 需要保护锚点时 Lock；Delete 删除选中关键帧，Clear 清除整套关键帧，执行前检查确认。

一枚有效锚点主要约束平移；更多分布良好的独立锚点可约束更丰富的变换。锚点聚集、近共线或跟踪错误会使旋转/缩放估计不可靠。HUD 显示关键帧前、两关键帧间和关键帧后的状态，应检查插值与边界延续是否符合实际。

Estimate 使用现有设施估计运动。其结果仍需用固定背景核验；补偿后目标不再移动不一定说明相机稳定，也可能选到了运动物体作为锚点。

## 10.3 Camera Anchor 自动追踪

### 10.3.1 目的与前提

Camera Anchor 追踪把模板识别位置写入选定 Camera 锚点的观测序列，供已有相机运动模型、画面稳定和 Expanded motion canvas 使用。它不生成物体 Track ID，不改变其他个体标注。

用于估计相机运动时，模板应选择静止背景上的可靠特征。若选择运动目标，稳定画面会包含跟随该目标的成分，不能再把补偿解释为纯粹相机运动。

### 10.3.2 操作规程

1. 在 Camera 面板勾选 `Enable`，开启 Camera compensation。
2. 选择要追踪的 Anchor 槽，检查当前帧位置。
3. 点击 `Track`，进入 Tracking → Track Motion；公共区域显示 `Target: Anchor N`。
4. 在已进入的选模板状态下点击背景特征，或使用 Add Template / Alt + Shift + 左键重新取样。
5. 如果已有 Anchor 位置与模板中心不同，检查自动保留的偏移；必要时使用 Mark offset 修正。
6. 调整模板区、搜索区、阈值和方向，点击 Run Auto。
7. 同时检查原始背景特征、锚点位置和稳定画面。
8. 需要人工修正时点击顶部 `Correct`，再点击正确 Anchor 位置；修正后用 Resume Auto 继续。
9. Finish 提交为一次 Camera History 修改，或 Cancel 恢复本次开始前的 Camera 状态。
10. 按 Camera 的保存流程保存锚点数据。

### 10.3.3 与物体 Tracking 的差别

- 一次追踪一个选定槽，多个 Anchor 需分别完成；既有 Camera 模型的锚点数量规则不变。
- 身份显示为 Anchor N；Class 与 Assist 不作为对象检测参数使用，Assist 禁用。
- 活动会话中部分 Camera 槽管理入口锁定，避免修改目标槽结构。
- Alt + 左键不写入物体标注；使用 Correct，或结束 Camera 会话后再操作物体 Tracking。
- 切到 Camera 可检查并使用原生锚点交互；当前锚点修改由同一 Camera 会话处理。
- Ctrl + Z/Y、当前点 Delete 和范围删除使用会话内撤销；删除只影响该槽对应帧观测。
- Finish/Cancel 走 Camera 的 History 与状态恢复，保留其他槽和未修改帧。
- 模板匹配仍在原始视频上执行，避免把已经稳定后的图像再次当作独立原始观测。

Camera 观测合入原有锚点结构时按源图整数像素记录；物体 Tracking 的 x/y 则可保留浮点值。二者保存体系不同。

相机补偿和 Scale 度量校准是不同步骤。Anchor 追踪提供帧间配准观测，不由背景模板自动推导厘米尺度或真实平面几何。


## 10.4 保存与修改边界

Camera 关键帧及开关属于会话元数据。关闭 Enable 可保留锚点数据以便再次启用，不等于清空。自动 Anchor 会话的 Finish 形成一次 Camera 历史操作；Cancel 恢复进入会话前状态。保存 CSV 时保留支持的 Camera 元数据及运动信息，重新载入后核对补偿方向和参考图像。

## 10.5 Camera 参数与锚点表

| 控件 | 含义 |
| --- | --- |
| Enable | 应用相机补偿；关闭不清除已有关键帧 |
| Anchor | 显示背景锚点标记 |
| HUD / HUD scale | 显示控制辅助信息并调整其显示尺度，不改存储坐标 |
| Threshold | 控制记录相机位移更新的像素门槛 |
| Number of anchors | 选择参与描述相机运动的锚点槽数量 |
| Set anchor | 选择当前操作的锚点槽 |
| Lock | 锁定相应锚点交互状态，防止误改 |
| Add / Delete / Clear | 添加当前关键帧、删除相应关键帧或清空运动记录；执行前核对范围 |
| Estimate | 从视频图像变化估计相机位移，结果仍需检查 |
| Track | 使用模板追踪当前背景锚点，预览后提交 |

锚点表按时间组织观测/变化。点击列定位相应帧，编辑数值前核对锚点槽；表格选择删除只应作用于相应单元或关键帧。模型名称随可用锚点与几何变化，不能只由下拉框中设置的数量保证求解稳定。

## 10.6 模型与锚点布局

单个锚点主要支持平移；两个有效分离锚点可描述平移、旋转和统一缩放；更多有效点可支持仿射或射影关系。锚点集中或共线会使复杂变换不稳定，应选择清晰、固定、分布分散且同平面的背景特征。

不要选择会运动的蜜蜂、胡蜂、摇摆枝叶或强烈反光作为静态背景锚点。相机变焦、视角变化、滚动快门和背景深度差异可能不能由单一平面模型完全解释。

## 10.7 Expanded motion canvas

启用扩展画布后，当前原图被变换到容纳相机位移的稳定画布，原图外区域用背景填充。对象标注仍按每帧原图坐标存储，显示和点选通过同一坐标映射转换。

扩展画布尺寸与原视频尺寸可能不同。导出前检查分辨率和可见边界；不能把黑边区域当作实际拍摄到的空间。缩放/平移视图只改变观察，拖动锚点才会影响相机配准。

## 10.8 Estimate 与 Track 的差别

Estimate 使用图像整体位移线索快速生成候选相机记录，容易受大面积前景运动影响；Track 使用指定背景模板逐帧跟踪，可在失败处人工接管。二者结果都要检查固定背景是否稳定，不能以目标轨迹变直为验收标准。

## 10.9 完整实例：手持相机轻微移动

1. 选择目标运动平面上的清晰固定标记，设置首个锚点参考位置。
2. 先用一个锚点检查平移补偿能否满足要求；确有旋转/缩放再增加分散锚点。
3. 对当前槽执行 Track，设置合适模板区与搜索区，Run Auto。
4. 遮挡或错误时暂停并人工修正，确认后继续。
5. Finish 后开启补偿，比较首、中、尾的固定背景位置。
6. 需要容纳较大位移时启用 Expanded motion canvas。
7. 完成稳定后再检查 Scale 的坐标空间与标定适用范围。
8. 保存并重新载入检查 Camera 记录、补偿方向和画布边界。

## 10.10 验收与限制

至少检查背景稳定性、目标框与图像一致性、轨迹点选位置、首尾关键帧、导出短片以及 Scale 显示。Camera 只调整坐标配准，不修复错误对象身份，也不补回缺失视频图片。

# 11 Points 与 Events 操作说明

[返回总目录](#0-引言)

## 11.1 记录目的与存储

Points 记录分析边界、捕获参考帧、主体身份、巢门口和审阅备注；Events 记录行为或数据质量事件区间。它们是人工采集信息，不由轨迹自动推断实验结论。

保存标注 SQLite 时，基础信息写入 `info_points`，事件写入 `info_events`。基础字段可按映射同步到 boutlist；事件区间不因 Sync to 自动逐项展开为 boutlist 列。完整标尺另存于 `scale_calibration`。

## 11.2 Points 的 Set 与 Goto

`set point` 和 `goto point` 为互斥模式。同一个按钮在两种模式下作用不同，操作前先核对当前模式。

| 按钮 | set point | goto point |
| --- | --- | --- |
| Start | 将当前帧设为分析开始 | 定位已存开始帧 |
| End | 将当前帧设为分析结束 | 定位已存结束帧 |
| Capture | 将当前帧设为捕获参考帧 | 定位捕获参考帧 |
| Hive | 进入巢门口位置点选 | 查看已记录参考位置 |
| Captor | 点选得手胡蜂框，记录其 ID | 选中该 ID，必要时定位其最近存在帧 |
| Victim | 点选被捕蜜蜂框，记录其 ID | 选中该 ID，必要时定位其最近存在帧 |

Notes 用于记录影响理解和分析的简短事实，例如遮挡不确定性或特殊片段条件。不要将备注当作已经完成核验的布尔标志。

## 11.3 各信息字段的含义

| 字段 | 定义 |
| --- | --- |
| analysis_start_frame | 本次捕获关联互动纳入分析的第一帧 |
| analysis_end_frame | 纳入分析的最后一帧；应与分析目的和 Capture 核对 |
| capture_frame | 得手胡蜂首次实际接触被捕蜜蜂，并连续导致成功控制和带走的第一帧 |
| captor_id_at_capture | 已核对的得手胡蜂身份 |
| victim_id_at_capture | 已核对的被捕蜜蜂身份 |
| hive_x_px / hive_y_px | 巢门口参考坐标；Camera 模式下应核对所属坐标空间 |
| left_censored | 真正互动起点早于可用分析画面，不能完整观察起点 |
| verified_capture_pair | 已核验得手胡蜂与被捕蜜蜂全过程的身份和轨迹 |
| verified_exposed_bees | 已重点检查低位、外围、孤立蜜蜂的漏检、重复和漂移 |
| verified_other_hornets | 已检查其他胡蜂逐帧存在情况及同类干扰事件 |
| review_notes | 自由文本审阅备注 |

`left_censored` 不根据自动检测的第一帧、胡蜂进入方向或画面边缘位置自动推断。如果能观察实际互动开始，应设置 Start 并记为 false；若开始时互动已进行，则记为 true。分析起点的蜂群状态只是该时刻已存在的状态，不能自动称为未受干扰的“清洁基线”。

## 11.4 Points 标准操作规程

1. 先校正关键主体的身份与轨迹。
2. 切换 set point，定位互动开始帧并点 Start。
3. 定位成功捕获过程，逐帧确定 Capture；按分析范围设置 End。
4. 分别点 Captor、Victim，再在画布选正确框。
5. 点 Hive，在画面指定巢门口参考位置。
6. 切回 goto point，逐项点击验证记录正确。
7. 需要时填写 Notes，并同步 boutlist，最后保存标注文件。

**例：视频开始时胡蜂已持续施压。** Start 使用实际可用分析起点，核验窗口勾选起点左截断；不要虚构一个画面外起点。Capture 仍按真实成功接触帧记录。

## 11.5 Events 的四类事件

| 显示/存储类型 | 标注判据 | 不应据此标注的情况 |
| --- | --- | --- |
| conspecific_interference | 得手胡蜂因其他胡蜂发生追逐、回避、驱赶或停止蜜蜂导向活动 | 仅同框出现 |
| noncaptor_engagement | 非得手胡蜂主动接近、悬停、往复或向蜜蜂群施压 | 单纯飞过而无相关活动 |
| bee_slip | 蜜蜂突然向下移动，形成新的低位/孤立机会 | 仅检测框抖动 |
| loss_or_blur | 严重运动模糊、遮挡或群体检测坍缩，使空间点集明显不可靠 | 个别轻微漏检 |

bee_slip 记录事件时间，不要求确定蜜蜂长期 ID。事件不自动划分诱导型等最终研究分类；这些结论应由后续分析结合客观轨迹推导。

## 11.6 建立、修改与删除事件

### 11.6.1 建立区间

1. 在事件类型下拉框选择类型，清除已有事件选择。
2. 定位起始帧，点击 Start；新事件先以 start=end 建立并被选中。
3. 定位结束帧，点击 End；该事件更新为包含两端的区间，完成后清除选择。
4. 在表格点击事件检查范围；播放区间前后确认边界。

没有选中事件时点击 Start 或 End 都会以当前帧创建点事件。单帧事件使用 start=end，与区间共用结构，例如 `{"type":"bee_slip","start":2301,"end":2301}`。

### 11.6.2 修改既有事件

点击事件列选择它，改变类型下拉框可更新类型；定位新的边界帧后用 Start/End 更新所选事件。双击相应表格内容可编辑类型或范围。多个事件同时选中时，边界或类型修改可能作用于全部所选事件，执行前核对选择。

表格每个事件为一列；当前帧处于某区间时有相应强调。点击用于选择和定位，不能凭列位置推断事件优先级。Delete 删除选中的事件记录，不删除轨迹框或原视频。

## 11.7 Verify 与保存核验

Events 的 Verify 和 Save / Save as 前的核验窗口记录四项独立状态。勾选表示 true，未勾选表示 false；不要求为了允许保存而全部勾选。

Confirm 提交勾选结果并继续相应流程；Back 放弃本次核验操作，在保存流程中会取消继续保存。`Export only the target segment` 仅在 Save as 时控制 SQLite 或 CSV 输出是否限制到 Start–End，不会删除范围外内存数据；Save 始终写回完整工作数据。

### 11.7.1 核验建议

- Capture pair：检查整个分析范围的得手胡蜂和被捕蜜蜂，不只看捕获那一帧。
- Exposed bees：重点检查最容易影响低位/孤立机会统计的框。
- Other hornets：检查逐帧数量与位置，允许无关个体 ID 不连续，但不能因此忽略大量漏帧。
- Left censored：记录是否能观察互动真实起点，与“已经核验”不是同一种含义。

## 11.8 同步和验收

Sync from/to 使用 Display 中配置的 boutlist 字段映射；Hive 在 boutlist 中按程序映射使用 nest 坐标列。同步前核对当前行，空白映射字段不读写。保存后重新载入，检查 Start/End/Capture、Captor/Victim、Hive、四项布尔状态、Notes 和事件区间。

同类干扰区间、其他胡蜂施压区间和 loss_or_blur 可以在时间上重叠；重叠表示不同事实同时成立，不应强制合并成一个排他分类。

# 12 撤销与恢复说明

[返回总目录](#0-引言)

## 12.1 三个不同层次

| 层次 | 内容 | 典型入口 |
| --- | --- | --- |
| 当前交互预览 | 尚未提交的点、曲线或标定修改 | Tracking、Trajectory、Continuous、Scale |
| 工作会话历史 | 已提交到当前工作数据的命令 | History → Undo / Redo |
| 持久保存与恢复 | 磁盘结果 SQLite、自动恢复快照、手工快照 | Save / Save as、Display → Recovery |

撤销一项命令不等于删除保存过的 结果 SQLite；恢复快照不等于自动把结果另存为 结果 SQLite。预览仍在画面上也不代表它已进入 History。

## 12.2 当前交互中的撤销

### 12.2.1 Tracking

提交前 Ctrl＋Z 撤销一个自动/人工位置步骤，Ctrl＋Y 重做；当前点删除和范围删除也在本会话记录。局部栈记录轻量变更，不为每一帧创建完整 History 命令。

Finish 将本次待提交结果作为一个追踪命令提交。之后 History 的一次 Undo 撤销该次提交的整体效果。Cancel 放弃本次会话，回到进入会话前工作数据。

### 12.2.2 Trajectory

编辑锚点、控制柄、重绘、平滑、重分配和变换的预览可逐步撤销。Apply 将确认的轨迹段作为一次整体修改提交；Discard 放弃预览。对同一段反复比较时，先看预览是否完成，再执行 Apply。

### 12.2.3 Change position Continuous

Continuous 会话内按步骤回退位置修改，结束会话后按已提交的会话边界管理历史。取消编辑模式与撤销此前已成功修改的点不同，退出后仍应检查工作数据和 History。

### 12.2.4 输入焦点

当键盘焦点位于文本框时，Ctrl＋Z 可能撤销文本输入。需要撤销轨迹操作时先把焦点移到画布或使用相应 Undo 按钮。Enter、右键和 ESC 的效果由当前交互模式决定，不能把它们统一理解为保存文件。

## 12.3 History 表格

表格列为 `#`、`Time`、`Op`、`IDs`、`Frames`、`Details`，分别用于核对顺序、时间、命令类型、身份、帧范围和参数摘要。点击历史项可辅助检查其涉及对象；表格选择不等于已经执行撤销。

Undo 退回当前命令栈的一步，Redo 恢复已撤销的一步。撤销后执行新的编辑可能建立新的历史分支，旧 Redo 链不能作为永久备份使用。

Save 写回当前 SQLite 后，当前会话的 Undo/Redo 仍可使用。关闭后重新打开 SQLite，其 `history` / `history_commands` 作为只读溯源记录显示，不恢复既往命令的撤销栈；重新打开后产生的新操作仍可撤销。选择 CSV 为输出格式时导出的 `_edit_log.txt` 也只读。恢复快照另行保存会话状态，仍使用现有 `.pkl` 机制。

**规程：** 暂停并结束当前交互 → 查看最近命令的 IDs/Frames → Undo → 核对画布和表格 → 需要恢复时 Redo → 再保存。

## 12.4 Recovery 设置

入口位于 Display 的 Recovery 相关设置。

| 设置/按钮 | 作用 |
| --- | --- |
| Recovery | 启用会话恢复快照机制 |
| Recovery directory / Browse | 指定恢复数据存放目录 |
| Snapshot | 请求立即写一份自动恢复快照 |
| Save as... | 显式保存命名快照，以后手工打开 |
| Open... | 手工载入已保存的恢复快照 |

快照由后台工作完成，不应把点击 Snapshot 的时刻当作磁盘写入必已完成。恢复目录应存在且可写；网络盘断连、空间不足等情况需要检查错误状态。

这里的 Save as... 保存恢复快照；底部 Save / Save as 保存正式结果文件，两处用途不同。底部 Save as 的 CSV 选项仅导出兼容表，既不建立恢复快照，也不清除当前工程的未保存状态。

自动恢复针对非正常结束的会话；正常退出后的自动快照不应作为持久工程库使用。需要长期保留阶段状态时使用命名快照，同时保存正式 结果 SQLite。

## 12.5 异常中断恢复规程

1. 重新启动，查看是否有待恢复会话提示。
2. 核对快照关联的视频和标注来源。
3. 恢复后检查当前帧、工作行、History、关键元数据和待提交编辑。
4. 视频路径变化时先恢复正确来源，确认图片身份对应。
5. 检查最后一段操作，完成必要的 Finish/Apply 或取消。
6. 另存正式结果，避免直接把未经核对的恢复状态覆盖唯一输出。

### 12.5.1 实例：自动追踪途中进程意外退出

恢复内容可能包括已提交数据和记录在快照中的待提交追踪状态。先检查最近帧、模板和缓冲点；不要假设退出前最后看到的一帧必已写入快照。确认后继续追踪或 Finish，再保存 结果 SQLite。

### 12.5.2 实例：希望保留两种编辑方案

在分支前显式保存命名快照和 结果 SQLite。完成第一种方案另存结果，再从明确的起点载入快照做第二种方案。不要仅靠多次 Undo/Redo 代替命名版本。

## 12.6 限制与核对

恢复依赖可读取的视频和源数据；快照不能重建已经丢失的视频图片。图层缓存用于加速显示，不能替代恢复快照；清除或更换显示缓存不应被用作撤销操作。正式输出以保存成功并可重新打开核对的 结果 SQLite 为准。

# 13 Boutlist 制作与使用

## 13.1 用途与一行记录的范围

Boutlist 是普通 CSV 表，每行组织一个需要审阅的 bout：视频、自动标注、人工轨迹及对齐/分析元数据。它便于逐条打开和回写简短信息，不保存全部逐帧框，也不替代标注 SQLite。

同一视频可以有多个分析片段，但应使用明确 bout_id 和范围区分。回写前必须核对当前选中行，不能只凭视频文件名认定某一行就是目标。

## 13.2 文件制作规程

1. 使用支持 UTF-8 的表格工具或文本编辑器新建 CSV，第一行为列名。
2. 每行填写 bout 标识及实际存在的视频路径；逐帧标注和人工文件没有时可以留空。
3. 已知的 Start、End、Capture 和人工对齐信息按对应列填写。
4. 含逗号、引号或换行的文本使用标准 CSV 引号规则；不要手工按逗号切割记录。
5. 保存后，在 Display → Boutlist fields 配置列名映射，再 Open Boutlist。
6. 用一行试开并检查同步结果，确认后批量组织其他记录。

**最小示例：**

```csv
bout_id,origin_video_file,detection_file,analysis_start_frame,analysis_end_frame,capture_frame
trial01,E:/videos/clip01.MTS,E:/results/clip01_review.csv,100,1200,1185
trial02,E:/videos/clip02.MP4,,1,950,930
```

使用绝对路径最容易直接核对。使用相对路径时，需保持 boutlist 和相关目录的位置关系，并实际试开确认路径解析；不要将另一台计算机的盘符路径当作通用路径。

## 13.3 Boutlist fields 映射设置

设置位于 Display 中 Playback 与 Others 之间。左侧项目代表程序内部含义，文本框填写 boutlist 中的实际列名。

- 按列名精确匹配，包括大小写；输入值两端空白会被去除。
- 留空表示停用该项目的读取和回写。
- 两个项目不能指向同一个非空列名；Save settings（All 或 Boutlist fields） 会阻止重复映射。
- 列名输入框为草稿。只有范围选为 All 或 Boutlist fields 并点击 Save settings 后，映射才写入 `settings.ini`，并从本次会话开始生效。保存其他分组不会应用这组草稿。
- 未保存时打开或回写 Boutlist，继续使用上一次保存的映射。恢复为已保存值后，未保存提示自动消失。
- 改映射不会直接重命名或重写 CSV 列。
- 更改后应重新打开当前 boutlist 记录，避免沿用旧映射选行时的快照。

**例：** 表格列名为 `Video`、`Start`、`Capture`，分别填入 origin_video_file、analysis_start_frame、capture_frame 对应文本框。程序仍把它们理解为视频路径、分析开始帧和捕获帧；输出标注 SQLite 的规范字段名不改变。

## 13.5 打开与同步规程

### 13.5.1 读取

Open Boutlist → 选择记录 → 核对 File 中实际路径 → 检查 Points 和 Match 参数 → 播放关键帧。字段映射只改变列名对应，不会修正错误视频配对或错误帧号。

### 13.5.2 回写

1. 在 Points 或 Match 修改相关信息并确认。
2. 执行 Sync to，或在程序提示回写时核对差异。
3. 确认显示的目标行和实际列名。
4. 完成后重新读取这一行验证。

Sync from 会把表中内容重新带入对应元数据。若当前会话有更准确的新值，应先判断是否需要覆盖。取消回写不意味着撤销已经保存到标注 SQLite 的结果。

## 13.6 写入边界与文本保留

回写只更新相应映射字段，其他列和未修改单元格的文本保持原样，例如标识 `001` 和自定义列 `1.2300` 不应因为更新 Capture 而被整体重新格式化。

完整 `scale_calibration` JSON 始终写入输出标注 SQLite。Boutlist fields 中可独立指定 `scale_px_per_cm` 与 `scale_calibration` 列名，二者可以同时启用。另可启用 `info_points`、`info_events` 和 `camera_anchor_keyframes` JSON 列。清空输入框只灰显项目标签，输入框保持可编辑；点击 Save settings（All 或 Boutlist fields） 后该项停止读写，不会清空表中已有内容。默认映射启用现有 tethered boutlist 中的同名列，其他项目为空；已保存的自定义映射优先。Points JSON 与单独标量字段并存时，非空的单独标量字段优先。加载标注 SQLite 时，元数据冲突仍通过原有对话框选择来源。

Events、逐帧位置、模板图像和全部 History 不在此表逐项保存。多人或多个实例同时修改同一个 CSV 时，应避免互相覆盖同一记录，并以写入前差异核对为准。

## 13.7 自动打开对应文件

Boutlist fields 中的 Auto open corresponding file 控制双向关联：打开视频时查找对应标注文件；打开标注文件时查找对应视频。视频查找使用标注来源字段、info_video 中的来源信息、检测 sidecar 和已保存 Boutlist 字段映射；有效来源路径优先。没有有效路径时，按来源文件名或去掉检测结果后缀后的同名视频查找。

查找限定在标注目录、其父目录、项目目录和上次视频目录，不递归扫描整个磁盘。只有一个候选时自动打开；多个候选时弹窗选择，取消不切换视频。没有找到时保留当前状态并在状态栏提示。自动打开视频不会再次打开标注，从而避免循环或替换刚载入的标注。

该选项关闭时，打开标注不自动切换视频。向当前审阅追加另一份标注仍要求来源属于同一视频，不根据追加文件自动切换视频。

## 13.8 典型检查

- 打开错误视频：检查映射列、当前行和路径，不先调整标注坐标。
- 某项未读入：检查映射是否空白、拼写大小写、列是否存在、值是否有效。
- 更换映射后不能直接回写：重新选择 boutlist 记录建立新映射下的行快照。
- 回写后出现新列：确认映射填写的是原有列名，而不是另一个相似名称。
- 需要精确空间分析：读取标注 SQLite 的完整标定，不能只用 boutlist 的平均比例。

## 14.1 设置的作用范围

Display 中的设置主要影响显示、解码、播放和运行资源。部分即时生效，需长期保留时使用 Save settings；程序继续沿用根目录 `settings.ini`。Detection 参数、Tracking 参数、视频导出参数分别有自己的配置和生效时点。

窗口标签悬停显示设置解释；输入框/下拉框悬停显示其当前完整内容。按钮和复选框显示操作含义。输入值不应因普通鼠标滚轮而意外切换。

Box、Axis、Metric grid、Trail 的外观见 [界面与逐段审阅](#2-界面与逐段审阅说明)，Recovery 见 [撤销与恢复](#12-撤销与恢复说明)，字段映射见 [Boutlist](#13-boutlist-制作与使用)。

## 14.2 播放与解码

### 14.2.1 视频呈现与解码后端

Render/Backend 选择视频呈现和解码组合。Qt raster、OpenGL Overlay 与视频解码是不同环节：使用 OpenGL 不表示模型推理在 GPU，使用硬件解码也不表示所有轨迹计算在 GPU。

| 设置 | 含义与调整依据 |
| --- | --- |
| Backend | 选择当前可用的解码实现；更换后核对定位、正反播放和时间轴 |
| HW accel | 请求受支持的硬件解码；实际支持取决于视频编码和运行时 |
| Codec | 限定或选择解码器，自动选项交由后端处理 |
| Threads | 解码线程数量，不是模板匹配或 YOLO Workers |
| Seek | 定位策略；精确图片对应优先于未经核验的快速时间估算 |
| FFmpeg / FFprobe | 解码与媒体信息工具路径 |
| libmpv library / mpv executable | mpv 播放所需动态库/程序路径 |

视频存在 PTS 缺口时，按图片索引处理帧身份。换后端后也应检查同一编号是否显示同一图片，不能仅比较播放时间文本。

### 14.2.2 Playback 的两种约束

No drop 强调逐帧显示；处理能力不足时实际播放速度可能下降。Correct speed 强调时间节奏；应结合当前实现和状态观察是否通过跳过显示帧维持速度。它们不删除标注记录，也不改变识别使用的连续图片编号。

正常播放和自动追踪的性能不同。Tracking 必须按顺序更新预测与模板，不能像纯播放一样只把已计算结果快速显示出来。Speed 也会限制追踪显示节奏；达到限速时 Tracking Rate 才附带 `(limit Nx)`。

## 14.3 Overlay renderer

### 14.3.1 Qt raster 与保留式 OpenGL

Qt raster 在 CPU 路径组织并绘制 Overlay，兼容性较好。保留式 OpenGL 维护绘制数据，适合大量连续线段和渐变 trail；能否使用取决于图形驱动与上下文。

选择后检查状态标签。初始化失败、配置不支持或导出环境不具备相应能力时，程序通过状态/提示说明回退。显示正常不代表请求的 GPU 路径已经生效，需核对实际后端。

Tracking 的少量交互框仍可由 Qt 绘制，与标注/拖尾的 OpenGL 后端共存。手动模板区和搜索区数量少，不应把所有性能问题归因于这几个框。

### 14.3.2 Trail shader

Trail shader 在 GPU 绘制阶段根据点的帧龄计算颜色、宽度和透明度，减少逐帧重新组织渐变外观的工作。它用于支持的播放拖尾、待提交 Tracking trail 及 OpenGL 导出路径，不需要 CUDA。

启用 shader 不会改变轨迹坐标或匹配结果。不支持的样式或绘制配置使用已有渲染路径，状态说明回退原因。波浪线等几何样式与颜色渐变不是同一个计算步骤，不应假定一个 shader 开关加速所有样式。

### 14.3.3 数据包、缓存与并行参数

| 参数组 | 作用 | 过大时的代价 |
| --- | --- | --- |
| Packet workers | 并行准备可由后台处理的 Overlay 数据包 | 调度开销和内存增加 |
| Packet prefetch frames | 提前准备未来显示帧 | 定位/编辑后更多任务可能失效 |
| Packet cache MiB | 数据包缓存内存上限 | 占用内存增加，不保证命中率 |
| Preview workers | CPU 预览绘制/回退工作的并行度 | 与主线程竞争资源 |
| Export workers | CPU 导出绘制并行度 | 编码或解码成为瓶颈时收益有限 |
| Preview batch | 单次预览调度处理的未来帧量 | GUI 工作量过大可能影响交互 |
| Export batch | 每批导出合成帧数 | 内存、显存及响应延迟增加 |
| Export decode queue | 提前解码批次数 | 占用 RAM，取消时积压更多工作 |
| Prefetch frames | 播放时的拖尾预取范围 | 长轨迹和跳转后重算成本增加 |
| Cache layers | 缓存可复用的静态/simple trail 图层 | 动态渐变命中有限，不能无限增长 |

应先保留较小队列，用 Profiler 判断瓶颈后逐项调整。不要同时增大全部参数，再以一个视频的平均倍速判断收益。

### 14.3.4 CUDA Overlay 可选项

GPU overlay 中的 TF32、Trail raster、Geometry、Canvas warp 和 GPU layer cache 是另外一组 CUDA 路径选项，与 OpenGL trail shader 不同。

TF32 控制受支持 CUDA 数学运算的精度/速度取舍；Trail raster 绘制拖尾；Geometry 绘制框/点等几何；Canvas warp 变换扩展画布；Layer cache 限制可驻留 GPU 图层数。较小图像或简单 Overlay 可能因整帧传输开销而不如 CPU。

Alpha/color bucket 控制渐变量化步长：1 保留更细粒度，较大值减少细分但可能出现更明显的分级。选择合适值应比较视觉差异和实际计时，而不是仅观察 GPU 占用百分比。

## 14.4 Tracking 的吞吐设置

Match weights 中 Decode ahead 允许下一图片解码与当前图片匹配重叠；Match workers 并行匹配独立模板。预测、接受结果和 Evolution 仍按帧顺序推进。

模板多、旋转/缩放搜索范围大、搜索区大或启用 Assist 都会增加工作。禁用过时模板可减少匹配次数；仅隐藏 Templates 页不会停止使用勾选模板。小模板上增加线程可能没有收益。

**测试规程：** 使用相同起始帧、模板、阈值和区间；把 Speed 上限调到不会限速的值；先记录基础吞吐，再逐项启用 Decode ahead/增加 Workers，最后分别比较 trail 和 shader。不能在不同模板与不同视频片段之间直接比较倍速。

## 14.5 Others 与缓存目录

| 设置 | 行为 |
| --- | --- |
| Point to Selection | 用箭头帮助定位选中目标 |
| Keep arrow visible | 保留相应选择提示 |
| Idle layer cache | 在空闲时准备可复用图层，减少之后重复绘制 |
| Overlay cache directory | 显示缓存目录，不是正式结果输出目录 |

按钮前的 Unsaved 显示有未保存差异的分组；None 表示与已保存状态相同。内容过长时悬停查看完整列表。将设置改回已保存值会清除该组提示。

页面内所有设置的保存栏位于所有分组外的最下方。范围下拉框默认为 All，也可选择单个分组。Save settings 仅保存该范围，其余草稿保留。Boutlist fields 的列名映射在保存成功后才用于本次和后续读写；其他显示控件保留即时预览行为。无效映射只阻止 All/Boutlist fields 保存，不妨碍保存其他分组。

**例：** 同时修改 Box 线宽和 Boutlist 列名，范围选择 Box 后保存，只持久化线宽。Boutlist 保存仍使用原列名，Unsaved 继续显示 Boutlist fields。之后选择该组并保存，才启用新列名。

恢复目录与显示缓存目录用途不同。不要把缓存文件当作标注 SQLite，也不要因为更改缓存目录就删除原始数据目录。

## 14.6 Profiler

### 14.6.1 采样与解释

Enable frame profiler 开启帧显示阶段计时；关闭时停止采样。Clear 清空当前统计，便于比较两组设置；Copy 将当前记录复制到剪贴板，便于保存或对比。界面展示各阶段耗时、缓存命中和资源相关信息，应结合实际帧显示速率阅读。

Profiler 主要用于定位本程序的阶段开销，不能替代显卡驱动级性能分析。单阶段耗时降低不一定提高总速度，例如解码变快后可能由匹配或编码成为新瓶颈。

### 14.6.2 可重复比较规程

1. 固定视频、区间、窗口大小、显示内容和倍率。
2. 等待首次解码、模型载入等一次性准备结束。
3. Clear 后播放或识别同一段，记录阶段耗时和实际速率。
4. 只改一个设置，再 Clear 并重复。
5. 比较吞吐、交互响应和内存，不只比较平均 GPU 占用。

### 14.6.3 常见瓶颈

- 解码等待高：检查源盘、编码格式、后端和解码预取。
- 匹配计算高：检查模板数、搜索区、姿态搜索范围和 CPU 并行。
- Overlay 高：减少可见长轨迹作对照，再检查实际 OpenGL/shader 路径。
- GUI 响应差但资源占用不高：检查 GUI 线程批量任务、表格刷新和等待链。
- 导出慢：分别比较解码、Overlay 合成、编码和写盘。

### 14.6.4 标注保存与大表开销

Save（Ctrl+S）写回当前 SQLite，普通编辑只冻结变化行及删除 UID，并在一个事务中保存数据、元数据和历史。后台保存完成仅清除本次已保存的变化；保存期间继续产生的编辑仍待下次 Save。多实例同时编辑同一文件时，版本检查会阻止覆盖较新的保存。

首次 CSV 转换、Save as 新库、片段导出及部分批量操作/撤销仍使用全量快照。CSV 兼容导出还需重写整张输出表，不具有 SQLite 的增量性能；raw、审计和完整命令留在 SQLite。内存编辑层仍为 DataFrame，打开全量结果仍需要读取工作表。恢复 `.pkl` 快照的内容寻址去重机制保持原样。

Save 首次选择目标的默认名不带日期时间；Save as 默认带日期时间。Save settings 只保存配置，不能代替标注 Save。操作及 CSV 附属文件要求见 [基础操作](#15-保存标注与导出数据表)，恢复与只读历史见 [撤销与恢复](#12-撤销与恢复说明)。

## 14.7 配置保存与故障复核

记录有效配置和对应视频样本。使用受支持环境启动后，分别验证播放、精确 seek、反向切帧、修改后刷新和短片导出。改变后台或硬件开关后出现问题时，恢复上一组已验证配置，再逐项定位，不修改标注几何来补偿显示错误。

## 15.1 术语

## 15.3 数据字段

### 15.3.1 位置来源

| `position_source` | 含义 |
| --- | --- |
| `manual_point` | 人工指定的点生成位置 |
| `manual_box` | 模板取样、模板区域或偏移等人工确定的框 |
| `template_track` | 普通 Auto 接受的模板匹配位置 |
| `guided_track` | Mouse guided 接受的匹配位置 |
| `edge_assist` | Edge 接受后的细化位置 |
| `yolo_assist` | YOLO 接受后的细化位置 |
| `curve_edit` | 已有位置经轨迹编辑、平滑、重绘、分配或变换修改 |
| `curve_fill` | 曲线工具补充的原本缺失帧位置 |

来源表示最终修改类别，不等于完整的所有处理步骤日志。多个 Trajectory 模式均写为 curve_edit；如分析需要具体算法与参数，应另保留处理记录和编辑前数据。人工失败重试通过时也可能保留人工来源并附有匹配分数，不能仅凭一个字段反推所有交互过程。

### 15.3.2 匹配与辅助字段

| 字段 | 含义与单位 |
| --- | --- |
| `frame` | 从 1 开始的实际解码顺序帧号 |
| `track_id`、`class` | 目标数字身份及类别 |
| `x / y / w / h` | 最终框中心及尺寸，源图像素 |
| `best_score` | 最佳模板匹配分数，保存为 0–1 数值，不是界面百分数字符串 |
| `second_score` | 竞争空间位置的分数 |
| `margin` | best_score − second_score |
| `template_frame` | 本次获胜模板的来源帧 |
| `recognition_x / recognition_y` | 应用 Mark offset 前的识别特征中心 |
| `match_rotation_deg` | 相对模板基准的旋转角度（°） |
| `match_scale` | 相对模板基准的尺度倍率，1 表示不缩放 |
| `assist_confidence` | YOLO 辅助的检测置信度，不等同于模板 Score |

字段只在相应操作产生信息时有意义；人工重写会清除不再适用的匹配数据。最终 x/y 可能包含 Mark offset 和 Assist 调整，而 recognition_x/y 描述识别阶段的位置，二者不同不一定是错误。

已有数据的其他字段按编辑规则保留。Tracking 的位置来源应优先查看 position_source 及 History，不能只用原有 `detected` 或 `confidence` 推断当前位置完全来自哪种算法。

### 15.3.3 Match 与 Detection 来源

Match 还记录 manual_track_name、manual_binding_state、manual_binding_finalized、manual_binding_manual_only、manual_binding_position_source 和相应源身份。绑定来源与 Tracking 的 position_source 不可互换解释。内部 `_...` 字段服务事务和缓存，不应直接作为分析指标。

Detection 的观测与估计必须结合 detected、插值/来源标识及参数快照解释。后处理 R 表示恢复事件，~ 表示估计位置。置信度、匹配 Score、Margin、审核状态是不同量，不能用单一阈值代替全部质量控制。

连续序号确保图片对应，并不保证物理拍摄时钟连续。帧差/FPS 给出标称帧时间；采用此模型做运动分析时，应在分析方法中说明。

### 15.3.4 标注保存 与 boutlist

标注文件为与视频文件对应，内部同时保存 immutable raw、当前 reviewed/final、元数据、修改审计和命令历史（SQLite 是正式工作格式，旧版 csv 格式择不包含 immutable raw、且修改审计和命令历史则记录于同文件名前缀的 _edit_log.txt 中）。`_review_uid` 是工作行的稳定内部标识，不用 DataFrame 行序号定位保存目标；CSV 兼容导出不输出内部列。`raw_track_id` 保留上游身份，`track_id` 表示当前身份；`raw_det_index` 联同 raw 帧号定位原始检测，人工新增和插值不伪造 raw 关联。绑定对齐改变最终 `frame` 时，`raw_frame` 保留原始观测帧；`source_annotation_path` 保留标注来源。

不同 raw 来源的工程不能直接追加到同一库，否则 raw 行索引可能误指另一段检测。另存新工程不能覆盖另一份已有项目；当前文件 Save 可正常更新。无可核验 raw 身份的旧 CSV 追加可保留 `legacy_raw_det_index` / `legacy_raw_frame` 供核对，但不建立与当前 raw 的关联。

CSV 保留为兼容输入/导出。首行 JSON 及 `.metadata.json` 承载元数据，`_edit_log.txt` 保存可读历史；它们不包含 raw 库、完整命令参数或数据库审计。额外列按编辑规则保留，复杂对象导出为 JSON 文本；CSV 的隐式类型推断可能改变前导零、空字符串等，精确类型以 SQLite 为准。完整保存规程见 [基础操作](#15-保存标注与导出数据表)。
