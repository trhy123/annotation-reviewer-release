# 11 Markers 与 Events 操作说明

[返回总目录](00_操作手册.md)

## 11.1 记录目的与存储

**Edit → Markers（标记）** 记录一段视频中纳入分析的帧范围、捕获参考帧、关键个体身份、空间参考点和审阅备注。对同一片段复核时，可以直接回到关键画面，确认选定的个体和位置，并了解哪些帧纳入分析以及存在哪些不确定性。**Events** 则记录有起止帧的行为或质量问题，例如同类干扰和严重模糊。实验判断由审阅人员根据视频作出，程序负责记录、定位和显示。

SQLite 和 CSV 的标注元数据均以 `info_points` 保存标记定义、值、坐标摆放帧和引用，以 `info_events` 保存事件区间，以 `scale_calibration` 保存完整的标尺标定。标记值可按字段映射同步到 Boutlist。事件区间保存在标注文件中，Sync → To 不会将它们逐项展开为 Boutlist 列。

## 11.2 设置与定位

表格每列对应一个标记，**Value** 显示记录值，**Symbol** 显示对应符号或样式。单击表头或 Symbol 格跳到已记录的帧或坐标、选中对应框 ID，或打开文本编辑。双击值可直接输入。在编辑窗口点 **Clear** 或留空后确认，都可清除记录值。滚轮横向浏览各列，双击任一列分隔线可将所有列调整为合适宽度。

| 类型 | 使用 Set | 手动输入 |
| --- | --- | --- |
| Frame（帧数） | 确认将当前帧写入标记 | 大于零的帧号 |
| Coordinate（坐标） | 在视频或扩展画布点选位置，再点 Apply | `x, y (Frame=n)`、`x, y, n` 或坐标引用。省略帧号时使用当前帧 |
| Box ID（框 ID） | 在画面点选对象框，再点 Apply | 整数框 ID |
| Text（文本） | 打开文本编辑窗口 | 自由文本 |

选中值格，点 **Set**，再到画布上点选坐标或框。如果已经选中一个框 ID，Set 会用它作为初始候选。按钮以按下状态显示 **Apply**，表格显示候选值。坐标可放在原视频画面以外，设置 Origin 时坐标轴预览随鼠标移动，点选后固定。点击主窗口中画布和 Markers 以外的空白处可清空候选值。点选框 ID 时，点击画布中的无框处也可清空候选值。按 Esc 放弃点选。设置帧或点 **Apply** 后，在确认窗口点 **Yes** 提交候选值，点 **Clear** 清除已保存值。已提交的修改或清除可在 History 中撤销。若有已启用的 Boutlist 映射，程序会在相应字段值不同时询问是否同步；拒绝同步仍保留标注内的修改。

进度条上的 `【`、`】` 和 `↑` 可跳转到分析边界和捕获帧。在这些帧上，帧标记和同帧事件都按 Events 的 HUD 样式显示。播放预览和启用 HUD 的演示导出使用相同的标签规则。

## 11.3 标记字段类型

| 标记 | 内部字段 | 记录含义 |
| --- | --- | --- |
| Start（分析起点） | `analysis_start_frame` | 当前分析区间内纳入分析的第一帧。能看到实际互动开始时，按研究判据选定起点。录像开头互动已经发生时，记录第一个可用的分析帧，并注明起点左删失。 |
| End（分析终点） | `analysis_end_frame` | 纳入分析的最后一帧，包含该帧。按研究目的选定，逐帧核对与 Capture 的关系。未显式设置第一组 End 时，范围计算可使用 Capture，若 Capture 也为空则使用视频末尾。 |
| Capture（捕获帧） | `capture_frame` | 在成功捕获的连续过程中，得手胡蜂首次实际接触被捕蜜蜂、随后控制并带走它的帧。回看接触后的画面，区分成功捕获的初次接触与先前失败的接近或短暂接触。该帧也可用于 Match 对齐手工轨迹。 |
| Origin（原点） | `origin` | Axis 使用的坐标轴原点，记录原图坐标和摆放帧。可通过 Set 或手动输入修改位置。原点的类型定义固定，在画面中由坐标轴表示。 |
| Hive（蜂巢） | `hive` | 巢门口的空间参考点，供回看及与实验坐标核对。默认引用 Origin 的位置和摆放帧。两者位置不同时，单独设置 Hive；它的符号在 Types 中配置。 |
| Captor（得手胡蜂） | `captor_id_at_capture` | 成功捕获的胡蜂在 Capture 帧所对应的框 ID。提交前沿前后轨迹确认得手个体身份，尤其注意同框胡蜂和 ID 互换。 |
| Victim（被捕蜜蜂） | `victim_id_at_capture` | 实际被捕蜜蜂在 Capture 帧所对应的框 ID。核对接触、控制和带走的连续画面，确认选中的是同一只蜂。 |
| Notes（备注） | `review_notes` | 审阅备注。记录会影响分析或复核的事实，例如起点不可见、遮挡导致身份存疑、轨迹中断或画面质量异常。 |

Hive 的默认值 `${origin}` 会跟随 Origin 的 x、y 和摆放帧。独立设定 Hive 后，双击其值并输入 `${origin}` 可恢复引用。自定义坐标之间也可引用，花括号内使用 **Internal field**。程序会提示不存在的引用目标或循环引用。启用 Camera 运动补偿后，坐标在各帧随同一背景位置移动，在 Expanded motion canvas 中固定在放置时对应的背景位置。

如果项目配置了核验字段 `left_censored`，实际互动起点已完整观察时记为 false，画面开始时互动已在进行则记为 true。该判断依据逐帧观察，不能从首个检测框、进入方向或离画面边缘的距离推导。即使能看到互动起点，也应另行核对是否满足对未受干扰基线的定义。

### 11.3.1 字段、区间和样式

在 **Markers → Types** 中可增删、停用和排序标记，编辑名称和 Tip。内部字段名以字母开头，可含数字和下划线，供坐标引用和 Boutlist 映射使用。Origin 的内部字段、名称、输入类型和样式固定，可调整顺序、Enabled 和 Tip。Origin 的坐标值在主表中设置。其余标记的 Set 和手工编辑方式取决于 Input type。改型时，原值保留，与新类型不兼容时值格显示为空。点 **Save settings** 将定义保存到 settings.ini。打开标注文件时会使用其中保存的定义。

**Add range** 新建一对带编号的 Frame 字段，例如 `analysis_start_frame_2` 与 `analysis_end_frame_2`。同编号两端均启用、类型为 Frame 且填好帧号后，才构成新增区间。两个无后缀的字段组成第 1 对。后续按相同的 `_N` 后缀配对，N 为大于等于 2 且无前导零的整数。程序根据字段名中的 `start` 或 `end` 使用左括号或右括号。第 2 对在进度条显示为 `【2` 和 `2】`，区间数量无固定限制。删除其中一端会移除这对定义。**Target only** 保存和演示导出的 **From Start to End** 使用各分析区间的并集，包含端点，跳过区间之间的空档。

在样式可配置的 Coordinate 或 Box ID 行上点 **Style**，也可双击样式格。坐标符号在两个表格里使用设定的描边色和固定线宽。Style 里的描边宽度用于画布。

- **Coordinate** 可设符号、大小、填充色、描边色和描边宽度。默认是黄色三角形、黑色描边。
- **Box ID** 可设对应框的描边颜色和 **Box line**。留空时分别沿用类别颜色和全局线宽。多个标记为同一 ID 指定样式时，使用 Types 中最靠前的已配置样式。

| 几何形状 | 可输入的单字符 |
| --- | --- |
| 三角形 | `▲` `▼` `◀` `▶`，或 `^` `v` `<` `>` |
| 实心圆、方形、菱形 | `●` `■` `◆`，或 `o` `s` `D` |
| 空心圆、方形、菱形 | `○` `□` `◇` |

其他字符或短文字也可填入 Symbol，例如 `+`、`×`、`★`、`H` 或 `巢口`。这些由系统字体绘制，实际可用字符取决于字体。分析边界和捕获帧的 `【`、`】` 和 `↑` 是进度条固定符号，也会显示在样式预览中。

## 11.4 标准操作规程

1. **校正关键个体。** 先回看完整过程，核对得手胡蜂、被捕蜜蜂及相关个体的框和轨迹。修正漏标、重复和串 ID 后，再记录角色 ID。
2. **确定分析范围和捕获帧。** 在对应画面依次选 Start、Capture、End 的值，点 Set 并确认。Capture 应逐帧核对，End 按实际纳入分析的画面设定。若分段分析，在 Types 中用 **Add range** 建立带相同编号的下一对 Start / End，再分别填写两个值。
3. **记录身份和空间参考。** 停在 Capture，分别选 Captor、Victim 的值，点 Set、点正确的框，再点 Apply 并确认。选用可辨认背景参照的一帧设置 Origin。若巢门口与原点不同，按相同方式在该位置单独设置 Hive。
4. **逐项回看。** 单击各列表头核对跳转、对象和位置。存在相机运动时，在相隔较远的帧检查坐标标记是否仍对准同一背景位置。需要重点复查时，优先检查两只关键个体的身份连贯性、低位或外围孤立蜜蜂的漏标和轨迹漂移，以及其他胡蜂是否存在和是否造成同类干扰。
5. **记录、同步和保存。** 在 Notes 填写影响解释的不确定性和异常。需要结构化核验时使用 Display → Others → Save 的 **Verify**。核对 Boutlist 行后使用 **Sync → To**，最终保存标注文件。保存模式和导出范围见[基础操作说明](01_基础操作说明.md)。

例如录像开始时胡蜂已在施压，Start 取第一个可用的分析帧，在 Notes 或启用的左删失字段记录实际起点不可见。之后仍按成功捕获的实际接触帧记录 Capture。

## 11.5 Events 类型

### 11.5.1 默认研究类型

以下为平台设置模板提供的默认类型，实际类型以 settings.ini 和 Types 设置表为准。

| 显示/存储类型 | 标注判据 | 不应据此标注的情况 |
| --- | --- | --- |
| conspecific_interference | 得手胡蜂暂停蜜蜂导向活动，转而追逐、回避、驱赶其他胡蜂 | 仅同框出现 |
| noncaptor_engagement | 非得手胡蜂主动接近、悬停、往复或向蜜蜂群施压 | 单纯飞过而无相关活动 |
| bee_slip | 蜜蜂突然向下移动，形成新的低位/孤立机会 | 仅检测框抖动 |
| loss_or_blur | 严重运动模糊、遮挡或群体检测坍缩，使空间点集明显不可靠 | 个别轻微漏检 |

bee_slip 记录事件时间，不要求确定蜜蜂长期 ID。事件不自动划分诱导型等最终研究分类；这些结论应由后续分析结合客观轨迹推导。

### 11.5.2 配置类型

1. 在 Edit → Events 点击 Types，打开非模态类型表。
2. Add 新建定义，Delete 移除选中定义；Up／Down 上移或下移选中定义，调整下拉列表顺序。Internal key 是稳定存储标识，只能以字母开头并包含字母、数字和下划线，不能重复。
3. Enabled 控制该类型是否可新增及是否显示其 HUD／条带；Name 控制下拉框、事件表和 HUD 中的名称。Tip 是可编辑的类型说明，显示在类型选项和事件单元格的悬停提示中，按输入原样保存到 INI。双击 Color 选择颜色，表格以十六进制颜色代码 `#RRGGBB` 保存，应用于事件表和条带。
4. Band 为 0 时隐藏该类型条带；1、2、3 分别使用进度条下方的三个条带行。条带隐藏不删除事件，也不禁止 HUD 显示。Priority 控制重叠层次，整数越小越靠上，默认按类型序号填充。事件条带统一使用 0.7 不透明度。
5. 有效修改即时预览名称、颜色和条带。Close 接受修改并供本次运行使用，不写入 INI；Cancel 或窗口 × 放弃本次打开后的修改并恢复原显示。点击 Save settings，或在 Display 的保存范围选择 Event types／All 后保存，才供后续运行使用；保存成功后，Cancel 只放弃此后未保存的修改。

修改名称和颜色不改变已存事件的内部标识或帧区间。停用、删除类型定义不删除已有事件。重新命名 Internal key 不会迁移原标识下的事件，应在事件表明确调整类型。未在本机配置的既有事件仍保留；结果文件中的类型定义可用于显示其名称与颜色。类型配置是程序设置，不属于标注 History；事件区间修改仍进入 History。

**例：** 新建 `camera_obstruction`，Name 为 `Camera obstruction`，颜色选择红色，Band 设为 3。保存 Event types 后，下拉框可以选择该类型并记录区间。将 Band 改为 0 并保存，仅隐藏条带；取消 Enabled 并保存后，该类型的 HUD 和条带均不显示，已有区间仍保存在结果中。

## 11.6 建立、修改与删除事件

### 11.6.1 建立区间

1. 在事件类型下拉框选择类型，清除已有事件选择。
2. 定位起始帧，点击 Start；新事件先以 start=end 建立并被选中。
3. 定位结束帧，点击 End；该事件更新为包含两端的区间，完成后清除选择。
4. 在表格双击事件跳到其范围，播放区间前后确认边界。

没有选中事件时点击 Start 或 End 都会以当前帧创建点事件。单帧事件使用 start=end，与区间共用结构，例如 `{"type":"bee_slip","start":2301,"end":2301}`。

同类干扰区间、其他胡蜂施压区间和 loss_or_blur 可以在时间上重叠；重叠表示不同事实同时成立，不应强制合并成一个排他分类。

### 11.6.2 修改既有事件

单击事件列选中，再次单击取消选择，均不跳转；Ctrl／Shift 支持多选。改变类型下拉框可更新所选事件的类型，定位新边界帧后用 Start／End 更新边界；F2 可直接编辑单元格。多个事件同时选中时，边界或类型修改可能作用于全部所选事件，执行前核对选择。

表格每个事件为一列，各列共用宽度，拖动任一列边界可同步调整全部列；包含当前帧的事件加粗。选中格为黄色底纹，所选事件居中；有选择时切帧不改为跟随当前帧居中。按 Esc 或点击列名／行号取消选择。双击跳到区间内距当前帧最近的一帧；所选事件的条带显示窄反差描边。底部横向滚动条始终显示，直接滚轮横向滚动。条带层次由类型的 Priority 决定。Delete 删除选中的事件记录，不删除轨迹框或原视频。事件编辑在 History 的 Frames 列记录实际变动的帧范围，Details 记录新事件类型或原类型 → 新类型；摘要不包含未改动的事件。

## 11.7 Verify 与保存核验

Display → Others 的 Save 行中的 Verify 按钮，以及 Save / Save as 前的核验窗口，用于记录当前 bout 的人工核验结果。下拉框的 **未核验（Not reviewed）** 保存为空；`1` 表示通过，`0` 表示待处理，二者都表示已经检查。文本框可自由填写。复选框只有勾选／未勾选两态，不能区分“未核验”和“未通过”，因此需要空白状态的项目应使用下拉框。

在核验窗口中按 **Confirm review**，答案立即写入当前 Boutlist 行。保存前弹出的核验窗口在结果文件保存成功后登记答案。可编辑的字段需启用 Sync 并映射到已有列。**Skip review** 继续保存，**Back** 取消保存。核验答案保存在 Boutlist 对应行，核验队列状态保存在队列 CSV。

Display → Boutlist fields 的 **Verify review status before saving** 控制每次 Save／Save as 是否弹出一次核验窗口。关闭文件时选择保存，仍使用同一流程。关闭总开关不改写已有核验状态，仍可通过 Verify 按钮手动打开窗口。

总开关下方的定义表属于设置，不是当前 bout 的核验结果。通过 Save settings 的 Boutlist fields 或 All 范围保存并激活草稿。问题及下拉选项是用户内容，不随界面语言翻译。

| 列 | 填写与行为 |
| --- | --- |
| Internal field | 稳定内部字段，字母开头，可含数字和下划线；不得重复或占用既有 Markers 字段 |
| Enabled | 是否在核验窗口显示；停用后不同步，保留已有结果 |
| Question | 显示给核验者的问题，可填写中文；按输入原样显示 |
| Boutlist field | Boutlist 中对应的实际列名；留空时 Sync 灰显，不读写该列 |
| Sync | 标注保存成功后，登记本次 Confirm review 的结果；要求启用、映射非空且实际存在对应列 |
| Input type | `dropdown`：下拉框，可留空；`text`：文本；`checkbox`：两态复选框，无空白状态 |
| Choices (a\|b\|c) | **只用于 dropdown**。用半角竖线 `\|` 分隔保存值，如 `1\|0` 或 `pass\|fail`；值直接保存，不使用 JSON，也不使用“值:说明”语法。未核验选项自动加入，不要手填空项 |
| Tip | 这项核验的完整检查要求，鼠标悬停时显示；按输入原样保存和显示 |
| Choice labels | 可选的选项显示文字，用半角竖线分隔，与 Choices 的值逐一对应，例如保存 `1\|0`，显示 `通过\|待处理`；留空则显示保存值。数量不一致或含空项时不能保存 |
| Blank label | 空白值的显示文字，例如“未核验”；留空则使用界面语言对应的 Not reviewed |

新增核验项或切换输入类型为 dropdown 时，空的 Choices 会自动填入 `1|0`；需要其他保存值时再修改。下拉选项不得为空、重复或含空段，例如 `1||0` 不合法；保存设置时会提示且保留已有有效配置。选择 text 或 checkbox 会清空并禁用 Choices、Choice labels 和 Blank label。Question 列可手动拖动表头边界调整宽度；输入类型下拉框只显示一份文字。

删除或停用定义不清除结果中已有值；改变内部字段不会迁移旧字段。未映射或缺失的列，也不能通过 Markers JSON 间接更新。

### 11.7.1 核验内容

三个平台模板默认示例包含以下四项，可根据实际数据质量目标需要来更改和设置，QC 项的选项为 `1|0`：

| 字段 | 输入 | 核验含义 |
| --- | --- | --- |
| `response_qc_pass` | 下拉框 `1` 通过、`0` 待处理，空白未核验 | 刺激段开始后检查前2秒，包括程序计数为零的 trial（计数为0也需排除漏计）；无漏计或重复计数，每个计入响应的下移属于同一只蜂。Baseline 检查实际纳入分析的完整基线窗口，区分真实下移与串ID产生的假下移 |
| `spatial_qc_pass` | 下拉框 `1`、`0` 或空白 | 刺激段开始后检查前6秒，提前接触或录像提前结束时看到实际终点；Baseline 检查实际基线窗口。蜂框数量与位置应足以进行群体深度、分散和邻近关系分析；仅当蜂框数量和位置正确时，单纯ID标签交换不影响本项空间核验通过；但这不代表响应身份核验也通过 |
| `reviewer` | text，如 `WTY` | 本次实际核验人的姓名或固定缩写；软件记住最近填写者，换人时修改 |
| `review_date` | text，`YYYY-MM-DD` | 默认当天，可改成实际核验日期 |

QC 任一项选择 `1` 或 `0` 后，确认时会检查已启用的核验人不为空、日期为真实有效的 `YYYY-MM-DD`。未核验保持空白；不要用 `0` 代替未核验。若改用 checkbox，未勾选就是明确的否定值，无法留空，建议这两个 QC 字段保留 dropdown。

## 11.8 同步和验收

**Sync: From / To** 从当前 Boutlist 行读取或向该行写回。先在 Display → Boutlist fields → Edit sync fields 中添加或启用对应映射。自定义标记以 Internal field 作为映射键，坐标列可存坐标与摆放帧或引用。Hive 也支持既有 nest 坐标列和摆放帧列。同步时会列出缺少映射、缺列或内容无效的标记，其余可同步的值仍可更新。保存后重新载入，核对标记和事件。

Markers 的 Boutlist 同步只处理已映射且实际存在的字段，未提供的列不会清除当前身份、核验或 Camera 状态。数值保存精度差异不作为冲突；已有完整 Scale 标定不会被简单 `scale_px_per_cm` 摘要替换。完整标定的来源选择见 [Scale](09_Scale操作说明.md#98-单值范围和完整输出)，字段和比较规则见 [Boutlist](13_Boutlist制作与使用.md#135-打开与同步规程)。
