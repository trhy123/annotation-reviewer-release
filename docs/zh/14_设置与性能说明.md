# 14 设置与性能说明

[返回总目录](00_操作手册.md)

## 14.1 设置的作用范围

Display 中的设置主要影响显示、解码、播放和运行资源。部分即时生效，需长期保留时使用 Save settings；根目录 `settings.ini` 保存显示外观、解码与推理参数、路径偏好、字段映射和编码配置。当前视频的后处理试验缓存及起止帧、视频导出时间范围和画面裁切、保存标注时的 target-only 选项属于会话状态，不写入 INI，切换视频时重新建立。

settings.ini 中的分组及设置项按平台模板定义的逻辑顺序排列，新增自定义项放在已知项目之后。

窗口标签悬停显示设置解释；输入框/下拉框悬停显示其当前完整内容。按钮和复选框显示操作含义。输入值不应因普通鼠标滚轮而意外切换。

Box、Axis、Metric grid、Trail 的外观见 [界面与逐段审阅](02_界面与逐段审阅说明.md)，Recovery 见 [撤销与恢复](12_撤销与恢复说明.md)，字段映射见 [Boutlist](13_Boutlist制作与使用.md)。

## 14.2 播放与解码

### 14.2.1 视频呈现与解码后端

Render/Backend 选择视频呈现和解码组合。Qt raster、OpenGL Overlay 与视频解码是不同环节：使用 OpenGL 不表示模型推理在 GPU，使用硬件解码也不表示所有轨迹计算在 GPU。

| 设置 | 含义与调整依据 |
| --- | --- |
| Backend | 选择当前可用的解码实现；更换后核对定位、正反播放和时间轴 |
| HW accel | 请求受支持的硬件解码；实际支持取决于视频编码和运行时 |
| Codec | 限定或选择解码器，自动选项交由后端处理 |
| Threads | 解码线程数量，不是模板匹配或 YOLO Workers |
| Index workers | 留空／0 从单段起步，根据实测总吞吐和实时可用内存调整到最多 4 路；1–8 为手动并发上限。保留至少 512 MiB 或总内存的 10%，每个新进程按 `宽×高×48 字节＋64 MiB` 估算。Auto 内存不足时暂停派发新段，不中断正在扫描的段。短视频单路扫描；分段须核对重叠图片，不能可靠拼接时改为单路。下次索引任务生效；这是任务调度，不是系统硬内存上限。 |
| Reverse MiB | 倒放帧缓冲预算，允许 0–16384 MiB。留空／0 取 4 GiB 与扣除系统余量后可用内存八分之一中的较小值；手动请求上限为四分之一。播放期间每秒检查内存压力，收缩后续块；已在解码或排队的图片正常消费。至少需要容纳 3 张原尺寸图片。预算是上限，不是必须填满的目标；解码器和显示另占内存。 |
| Seek | 定位策略；精确图片对应优先于未经核验的快速时间估算 |
| FFmpeg / FFprobe | 解码与媒体信息工具路径 |
| libmpv library | mpv_gl 播放所需动态库路径 |

视频存在 PTS 缺口时，按图片索引处理帧身份。换后端后也应检查同一编号是否显示同一图片，不能仅比较播放时间文本。

HW accel、Codec、Preview backend 等自动选项在能够确认实际实现时，会显示为 `auto (实际后端或解码器)`、`cuda_auto (实际解码器)` 等形式；展开列表加宽以显示完整内容。括号是当前运行状态，INI 中的 auto 不带后缀括号。

### 14.2.2 Playback 的两种约束

No drop 强调逐帧显示；处理能力不足时实际播放速度可能下降。Correct speed 强调时间节奏；应结合当前实现和状态观察是否通过跳过显示帧维持速度。它们不删除标注记录，也不改变识别使用的连续图片编号。

正放复用连续解码管线。cpu_frames 和 mpv_gl 的倒放均向前解码成帧块，再逆序显示，显示当前块时准备上一块。帧块是程序的图片缓存单元，不等同于编码 GOP，可以包含部分或多个 GOP。正放队列和待显示缓冲合计不超过 256 MiB；倒放最多三块共享 Reverse MiB 预算。首块最多 8 张，后续 No frame drop 每块最多 64 张，Correct speed 每块最多 12 张，且都受预算限制；合适时对齐关键帧。缓冲不随视频时长增长；增加缓存预算不会要求启动前填满缓存。

FFmpeg 定位到邻近关键帧后核验每张输出图片的时间戳。硬件路径失败时先重试能精确定位的 FFmpeg 软件解码，仍失败才退回从头计数。硬件帧下载同时接受 8 bit 与 10 bit 格式。Decoder Threads 控制输入解码线程；增大线程数也会增加内存，并不保证更快。

FFmpeg 转换 RGB 时使用源视频的色彩矩阵和范围；未标记的高清按 BT.709、标清按 BT.601，和 mpv 的判定一致。OpenCV 后端自身的转换可能有差别；对颜色一致性有要求时使用 FFmpeg。

Correct speed 倒放从首个小块就绪后开始计时，不再等待两个完整块。高倍速正放和倒放都向解码线程合并提交最新目标，跳过过时工作，不反复取消仍在启动的线程；后续缓冲不足时保持时钟，按实际播放时间选择已有画面。解码或显示吞吐不足时仍可能出现间隔，No frame drop 则保持逐帧顺序并允许降速。

正常播放和自动追踪的性能不同。Tracking 必须按顺序更新预测与模板，不能像纯播放一样只把已计算结果快速显示出来。Speed 也会限制追踪显示节奏；达到限速时 Tracking Rate 才附带 `(limit Nx)`。

### 14.2.3 渲染 GPU 与解码设备

Decoder → Render GPU 设置系统渲染偏好。Windows 可选 Auto、Power saving 或 High performance，保存 Decoder 设置并重启后生效。此设置按可执行文件生效，因此源码运行时也会影响使用同一 Python 可执行文件的程序。Linux 的 Primary / Secondary GPU 在创建 Qt 上下文前通过 DRI_PRIME 设置；macOS 保持系统自动选择。Active render 显示实际 OpenGL 渲染器，系统与远程桌面驱动仍可能覆盖偏好。

HW accel 控制 FFmpeg／倒放；Native HW 单独控制 libmpv 正放，默认保持安全的 Auto。FFmpeg device 和 Native device 分别选择各自硬件 API 的设备，也可填写对应的编号或设备路径。更换 API 会将设备恢复为 Auto；点击 Apply 会在当前位置重启预览解码。自动选项以括号显示解析结果，Active 行显示运行时信息；未报告的设备会如实注明。Windows 设备列表会排除间接／虚拟显示适配器，同型号的多张真实显卡仍分别保留。

### 14.2.4 颜色与 HDR 预览

Color 分组位于 Decoder 下方。Source 默认 Auto，读取视频的矩阵、原色、传递函数与范围标记；未标记的标清／高清回退为 BT.601／BT.709，这不能识别没有标记的 HDR 素材。需要时可指定 BT.601、BT.709、BT.2020 SDR、PQ 或 HLG，Range 可单独指定。Auto 的括号显示当前解析的来源、范围和 HDR 模式。信息行依次显示矩阵、原色、传递函数与范围，推断值有相应标记，悬停可查看各项来源；读取元数据失败会明确提示。Apply 会清除旧的解码图片和缩略图；Save settings 选择 Color 或 All 可保存设置。

两种视频模式均预览为 SDR，HDR 转换统一使用 203 尼特参考白。Auto 在 libmpv 正放中保留 GPU 映射，在 CPU／倒放中使用 FFmpeg；SDR (same mapping) 则让 libmpv 也使用相同的 FFmpeg 转换链，进一步保持两条路径一致，但会增加 CPU 开销。Off / clip 直接裁剪高光。Peak nits 留空／0 时使用视频的 HDR 峰值信息，缺失则按 1000 尼特；填写正数可手动覆盖。FFmpeg 在降为 8 位前使用 16 位采样及可复用的高精度色调／色域查找表，小型临时查找表文件在退出时删除，普通 SDR 保留原来的快速路径。OpenCV 无法应用这些设置时，HDR 和手动颜色预览使用 FFmpeg。当前为静态 PQ／HLG 映射，不是原生 HDR 输出，也不处理 Dolby Vision 动态元数据；不会修改原视频、标注坐标或 YOLO 输入。

### 14.2.5 批量预建视频索引

Decoder → Indexes… 打开非模态批量队列。使用 Add videos 或 Add folder 添加视频，选择可写的 PTS 缓存目录后点击 Start。视频之间逐个处理，每个视频内部按当前 Index workers 设置并发；各行显示状态、已索引帧数、估计进度和完成后的缓存体积。Cancel current 停止此队列；已经与主播放器共享的索引会继续。Remove 只移除任务行，不删除视频或缓存。

队列复用已有索引和正在进行的扫描。缓存目录保存为 paths/pts_cache_dir，默认使用程序的临时 PTS 目录（macOS bundle 使用外部缓存目录）；要避免系统清理临时文件，可选择固定目录。完成的 PTS 缓存没有按时间自动删除的机制。建立索引还需要解码器内存，不只保存时间戳；Auto 在实时内存不足时等待，不继续派发新段。

## 14.3 Overlay renderer

### 14.3.1 Qt raster 与保留式 OpenGL

Qt raster 在 CPU 路径组织并绘制 Overlay，兼容性较好。保留式 OpenGL 维护绘制数据，适合大量连续线段和渐变 trail；能否使用取决于图形驱动与上下文。

选择后检查状态标签。初始化失败、配置不支持或导出环境不具备相应能力时，程序通过状态/提示说明回退。显示正常不代表请求的 GPU 路径已经生效，需核对实际后端。

视频导出跟随同一 Overlay renderer 选择，Export backend 为只读状态，不另存独立后端设置。Qt raster 导出不创建 OpenGL 上下文；Grid 与标注使用相同绘制后端，固定 HUD 在最终画面尺寸中绘制。

Tracking 的少量交互框仍可由 Qt 绘制，与标注/拖尾的 OpenGL 后端共存。手动模板区和搜索区数量少，不应把所有性能问题归因于这几个框。

### 14.3.2 Trail shader

Trail shader 在 GPU 绘制阶段根据点的帧龄计算颜色、宽度和透明度，减少逐帧重新组织渐变外观的工作。它用于支持的播放拖尾、待提交 Tracking trail 及 OpenGL 导出路径，不需要 CUDA。

启用 shader 不会改变轨迹坐标或匹配结果。实线、虚线、点线、点划线和波浪线均可由 shader 绘制；线型按轨迹累计距离定位，密集插值段不会在每个细分点重新开始图案。shader 不可用时使用已有渲染路径，状态说明回退原因。

### 14.3.3 数据包、缓存与并行参数

| 参数组 | 作用 | 过大时的代价 |
| --- | --- | --- |
| Packet workers | 并行准备可由后台处理的 Overlay 数据包 | 调度开销和内存增加 |
| Packet prefetch frames | 提前准备未来显示帧 | 定位/编辑后更多任务可能失效 |
| Packet cache MiB | 数据包缓存内存上限 | 占用内存增加，不保证命中率 |
| Preview workers | CPU 预览绘制/回退工作的并行度 | 与主线程竞争资源 |
| Export workers | CPU 导出绘制并行度 | 编码或解码成为瓶颈时收益有限 |
| Preview batch | 单次预览调度处理的未来帧量 | GUI 工作量过大可能影响交互 |
| Export batch | 每批导出合成帧数 | 内存、显存及响应延迟增加 |
| Export decode queue | 提前解码批次数 | 占用 RAM，取消时积压更多工作 |
| Prefetch frames | 播放时的拖尾预取范围 | 长轨迹和跳转后重算成本增加 |
| Cache layers | 缓存可复用的静态/simple trail 图层 | 动态渐变命中有限，不能无限增长 |

应先保留较小队列，用 Profiler 判断瓶颈后逐项调整。不要同时增大全部参数，再以一个视频的平均倍速判断收益。

### 14.3.4 CUDA Overlay 可选项

GPU overlay 中的 TF32、Trail raster、Geometry、Canvas warp 和 GPU layer cache 是另外一组 CUDA 路径选项，与 OpenGL trail shader 不同。

TF32 控制受支持 CUDA 数学运算的精度/速度取舍；Trail raster 绘制拖尾；Geometry 绘制框/点等几何；Canvas warp 变换扩展画布；Layer cache 限制可驻留 GPU 图层数。较小图像或简单 Overlay 可能因整帧传输开销而不如 CPU。

Alpha/color bucket 控制渐变量化步长：1 保留更细粒度，较大值减少细分但可能出现更明显的分级。选择合适值应比较视觉差异和实际计时，而不是仅观察 GPU 占用百分比。

## 14.4 Tracking 的吞吐设置

Weights 中 Decode ahead 允许下一图片解码与当前图片匹配重叠；Match workers 并行匹配独立模板。预测、接受结果和 Evolution 仍按帧顺序推进。Advanced 的 Multi-channel 候选、较大 Budget 和 HSV histogram 会增加每帧匹配工作，应分别比较准确性和耗时；Guard template updates 控制学习条件，不使视频帧独立并行。

模板多、旋转/缩放搜索范围大、搜索区大或启用 Assist 都会增加工作。禁用过时模板可减少匹配次数；仅隐藏 Templates 页不会停止使用勾选模板。小模板上增加线程可能没有收益。

**测试规程：** 使用相同起始帧、模板、阈值和区间；把 Speed 上限调到不会限速的值；先记录基础吞吐，再逐项启用 Decode ahead/增加 Workers，最后分别比较 trail 和 shader。不能在不同模板与不同视频片段之间直接比较倍速。

## 14.5 Others 与缓存目录

### 14.5.1 类别、语言与界面

**Classes** 是横向表格，三行依次为 YOLO 模型类别编号、标注类别名称和说明（Tip），例如 `0 / bee`、`1 / hornet`。说明可留空，按输入原样显示在类别选项的悬停提示中，不随界面语言翻译。点击 **Edit** 开始编辑；**Add / Remove** 增删选中列；点击 **Apply** 校验并立即写入 `settings.ini` 的 `[classes]` 和 `[class_tips]`（说明按模型编号保存），同时更新编辑与追踪的类别选项和 IDs 子表。编号必须是不重复的非负整数，名称不能为空、不能重复，不能含 `, ; |`。这项设置定义类别映射，不会把已有标注的类别批量改名；修改标注请用 Change class。

已有 `[id_groups]` 尽量保留，新类别追加为独立分组。加载 CSV／SQLite 时，在后台从已读入的 `class` 列提取唯一类别并比较，不再读盘、不新增文件字段。缺少类别时询问是否添加；接受后自动分配未占用的模型编号，再载入表格。若模型实际编号不同，请在 Classes 中修正。拒绝添加仍能打开，未知类别显示在 Other 子表。

**Language** 默认 **English**，可选 **简体中文**。切换后立即更新现有窗口、提示和状态文字，保留当前文件、选择和编辑草稿；用 Others 或 All 的 **Save settings** 保存后供下次启动使用。不会翻译或改写用户填写的类别、ID、路径、备注和标注数据。核验列表的标题、按钮、列名及内置状态随同一语言设置显示，CSV 内部值保持不变。

**Theme** 位于 Language 右侧，可选跟随系统（默认）、浅色或深色，仅影响本程序。切换即时生效，用 Others 或 All 保存。Classes 位于 UI size 前；Axis、Metric grid、Camera canvas 依次位于 Trajectory picking 与 HUD 之间。

左下角 **Frame: / Time:（帧／时间）** 同时切换定位输入、总量显示与进度条刻度。此选择随 Others 或 All 保存／重置（`ui/timeline_units`），不改变标注和编辑范围使用的整数帧号。

中文界面文本使用外置 [`translations/zh_CN.json`](../../translations/zh_CN.json)，英文源文案作为键，由统一的 `app.i18n.tr` 入口处理。下拉框和表头仅翻译显示，不改变内部值。实际运行读取 JSON，修改翻译时须保留 `{v0}` 等格式字段。手册按 `docs/zh`、`docs/en` 分目录维护，界面语言不要求翻译手册。合并文档中的此链接仍指向项目根目录下的实际文件；相对路径按合并文件的位置计算，不复制到 assets 目录。

### 14.5.2 预览与缓存

| 设置 | 行为 |
| --- | --- |
| Point to Selection | 用箭头帮助定位选中目标 |
| Keep arrow visible | 保留相应选择提示 |
| Seek preview | 悬停或拖动进度条时显示视频缩略图，不包含标注，不改变主画面 |
| Width px | 缩略图宽度，默认 240，范围 80–999；高度按比例计算 |
| Idle layer cache | 在空闲时准备可复用图层，减少之后重复绘制 |
| Overlay cache directory | 显示缓存目录，不是正式结果输出目录 |

缩略预览分为常驻基础图和细化缓存。文件及索引载入完成后，空闲时按时间轴均匀预载最多 256 张基础图，基础图不参与细化缓存淘汰。滑动立即显示最近的已缓存画面，慢速移动或停留约 90 ms 后请求当前位置的较准确帧，新结果完成后替换。尚无任何缓存时需要等待首次解码。播放、定位、追踪和鼠标预览暂停基础图预载，过期目标会被更新请求取消。索引未完成仍可请求近似图；其他窗口获得焦点时不显示预览。

预览区域的下界为进度条竖直中心，上界保持在控件顶部；移出后立即隐藏，迟到的解码结果不会重新打开预览。滑动优先复用当前位置已有的精细图，否则立即显示最近的基础图，再等待当前位置细化结果。

图像只保存在内存，不写入 recovery 或磁盘缓存。每张最大 240×135，RGB 像素约 95 KiB；256 张基础图约 23.7 MiB。细化缓存额外保留最多 768 张、72 MiB，以先达到的限制为准；两层最多约 95 MiB，不含解码工作内存和 Qt 显示开销。鼠标离开保留已完成缓存，关闭或切换视频时清空。缩略图不用于判定标注帧号，正式定位仍走精确帧通路。两个控件随 Others 或 All 范围的 Save settings 保存。

按住 Ctrl 沿进度条移动，按播放器当前可见区域生成局部缩略图，包括缩放、平移及当前 Camera 坐标变换。局部图不预载，最多保留 64 张，与普通细化图共用上述 768 张／72 MiB 限额，达到容量时优先淘汰局部图。核验过图片身份的预览显示 `Frame N`；基础图、索引未完成或解码时间戳未匹配的图保留近似提示。

Playback 分组先显示 Correct speed，再显示 No frame drop。No frame drop 播放时，右侧显示实际呈现的新画面数／秒及其相对原视频 FPS 的倍率，保留两位小数。相同帧的重复重绘不计数。该行处于可见区域且主窗口活动时才采样，隐藏或暂停后停止并清空显示。

按钮前的 Unsaved 显示有未保存差异的分组；None 表示与已保存状态相同。内容过长时悬停查看完整列表。将设置改回已保存值会清除该组提示。

页面内所有设置的保存栏位于所有分组外的最下方。范围下拉框默认为 All，也可选择单个分组。Events 类型定义使用 Event types 范围；核查定义和字段映射使用 Boutlist fields 范围。Save settings 仅保存该范围，其余草稿保留。Boutlist fields 的列名映射在保存成功后才用于本次和后续读写；其他显示控件保留即时预览行为。两个字段编辑窗口还各自提供独立 Save settings，直接将本窗口定义写入 settings.ini；关闭窗口则放弃未保存修改。另一窗口中的无效草稿不会阻拦。已启用映射出现重复列名时仍须修正；保存其他 Display 分组互不影响。

**例：** 同时修改 Box 线宽和 Boutlist 列名，范围选择 Box 后保存，只持久化线宽。Boutlist 保存仍使用原列名，Unsaved 继续显示 Boutlist fields。之后选择该组并保存，才启用新列名。

恢复目录与显示缓存目录用途不同。不要把缓存文件当作标注 SQLite，也不要因为更改缓存目录就删除原始数据目录。

范围下拉框与 Save settings 之间的 **Reset** 将所选范围恢复为最近已保存的设置，保留其他分组尚未保存的修改。选择 All 恢复全部显示设置；此操作不写入 settings.ini，也不是恢复出厂默认值。

## 14.6 Profiler

### 14.6.1 采样与解释

Enable frame profiler 开启帧显示阶段计时；关闭时停止采样。Clear 清空当前统计，便于比较两组设置；Copy 将当前记录复制到剪贴板，便于保存或对比。界面展示各阶段耗时、缓存命中和资源相关信息，应结合实际帧显示速率阅读。

Profiler 主要用于定位本程序的阶段开销，不能替代显卡驱动级性能分析。单阶段耗时降低不一定提高总速度，例如解码变快后可能由匹配或编码成为新瓶颈。

### 14.6.2 可重复比较规程

1. 固定视频、区间、窗口大小、显示内容和倍率。
2. 等待首次解码、模型载入等一次性准备结束。
3. Clear 后播放或识别同一段，记录阶段耗时和实际速率。
4. 只改一个设置，再 Clear 并重复。
5. 比较吞吐、交互响应和内存，不只比较平均 GPU 占用。

### 14.6.3 常见瓶颈

- 解码等待高：检查源盘、编码格式、后端和解码预取。
- 匹配计算高：检查模板数、搜索区、姿态搜索范围和 CPU 并行。
- Overlay 高：减少可见长轨迹作对照，再检查实际 OpenGL/shader 路径。
- GUI 响应差但资源占用不高：检查 GUI 线程批量任务、表格刷新和等待链。
- 导出慢：分别比较解码、Overlay 合成、编码和写盘。

### 14.6.4 标注保存与大表开销

Save（Ctrl + S）写回当前 SQLite，普通编辑只冻结变化行及删除 UID，并在一个事务中保存数据、元数据和历史。后台保存完成仅清除本次已保存的变化；保存期间继续产生的编辑仍待下次 Save。多实例同时编辑同一文件时，版本检查会阻止覆盖较新的保存。

Save as 到新文件时，若已有可信且版本一致的 SQLite 保存基线，先复制完整数据库，再以增量事务写入变化行、元数据和历史。内置 raw、既有审计和命令历史随库保留，未变化的标注不逐行重新序列化。源库版本改变或目标文件在准备后出现时停止保存，避免覆盖其他修改。

首次 CSV 转换、片段导出、需要补全来源信息的文件及部分批量操作/撤销仍使用全量快照。CSV 兼容导出还需重写整张输出表，不具有 SQLite 的增量性能；raw、审计和完整命令留在 SQLite。内存编辑层仍为 DataFrame，打开全量结果仍需要读取工作表。恢复 `.pkl` 快照的内容寻址去重机制保持原样。

File 页的 Detection 统计以当前选择的磁盘标注文件为准，显示已保存的帧数、行数及身份数量，不包含待保存编辑或内置 raw。进入 File 页时读取并缓存；文件保存或被外部修改后，再次查看时更新。多来源时分别选择所需文件查看，不将各来源的内存工作行误作磁盘文件统计。

IDs 页首次查看时建立身份概况；仅改变选择时复用统计和单元格，只更新高亮。大量多选的右上信息区采用数量汇总，实际选择和批量操作范围不变。拖尾曲线后台批量准备，首次准备与后续逐帧绘制应分别计时。

SQLite 项目在检测或保存事务进行期间可临时使用 `-wal` 和 `-shm` 辅助文件。它们由 SQLite 管理；目录匹配和元数据读取完成后关闭连接，使无其他使用者的辅助文件将自动删除。仍有活动写入者或未完成事务时保留相应文件，不手动删除 WAL。

Save 首次选择目标的默认名不带日期时间；Save as 默认带日期时间。Save settings 只保存配置，不能代替标注 Save。操作及 CSV 附属文件要求见 [基础操作](01_基础操作说明.md#15-保存标注与导出数据表)，恢复与只读历史见 [撤销与恢复](12_撤销与恢复说明.md)。

## 14.7 配置保存与故障复核

记录有效配置和对应视频样本。使用受支持环境启动后，分别验证播放、精确 seek、反向切帧、修改后刷新和短片导出。改变后台或硬件开关后出现问题时，恢复上一组已验证配置，再逐项定位，不修改标注几何来补偿显示错误。
