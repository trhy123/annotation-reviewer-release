# 15 术语、快捷操作与数据约定

[返回总目录](00_操作手册.md)

## 15.1 术语

| 名称 | 定义 |
| --- | --- |
| frame | 按实际解码图片顺序从 1 开始编号 |
| PTS | 容器/码流的呈现时间戳；间隔不必严格等于 1/FPS |
| ID / track_id | 当前结果中的目标身份，不等于类别 |
| raw ID | 上游检测/跟踪器产生的身份 |
| stable ID | 后处理重新关联后的身份；不同试验之间不以数值直接对应 |
| template | 从已知帧截取的外观参考；不是 YOLO 模型权重 |
| keyframe | 具有人工或明确参考状态的帧；模板来源帧和 Camera 关键帧用途不同 |
| candidate | 待判定的匹配或绑定候选 |
| pending | 尚未提交为整段 History 的编辑 |
| preview | 可确认或丢弃的计算/交互结果 |
| commit | 写入当前工作数据；不等同保存文件 |
| raw cache | 上游阈值化检测之后、自定义后处理之前的缓存 |
| sidecar | 与结果配套保存的参数及来源元数据文件 |
| overlay | 叠加在视频上的框、文字、轨迹及辅助图形 |

## 15.2 快捷操作及焦点

| 操作 | 作用范围与行为 |
| --- | --- |
| Space | 播放 / 暂停 |
| ← / D | 上一帧 |
| → / F | 下一帧 |
| Shift + ← / Shift + D | 上一秒（按 round(FPS) 帧步进） |
| Shift + → / Shift + F | 下一秒（按 round(FPS) 帧步进） |
| Ctrl + 左键 | 普通选择中的多选；已有编辑工具可优先处理其交互 |
| Ctrl + 滚轮 | 视频或模板预览缩放 |
| 中键拖动 | 视频或模板预览平移 |
| Ctrl + A | 选择当前帧目标；文本框有焦点时按其文字全选行为处理 |
| Ctrl + O | 打开标注 SQLite 或旧 CSV，不是打开视频 |
| Ctrl + S | 保存标注文件；写回当前标注文件 SQLite；旧 CSV 首次保存需选择 SQLite |
| Ctrl + Shift + S | 另存为；默认名追加日期时间后缀；可另存 SQLite 或兼容导出 CSV |
| Ctrl + ← / Ctrl + D | 在当前帧的目标中向左移动选择，不切帧 |
| Ctrl + → / Ctrl + F | 在当前帧的目标中向右移动选择，不切帧 |
| Ctrl + ↑ | 在当前帧的目标中向上移动选择，不切帧 |
| Ctrl + ↓ | 在当前帧的目标中向下移动选择，不切帧 |
| 无 Ctrl 的方向键 | 选中 Scale 点或 Camera anchor 时按 1 像素微调，优先于普通切帧 |
| Enter | 帧号框确认定位；Scale 的角度/长度编辑器确认输入；选中 Camera anchor 时记录关键帧 |
| Enter / 右键 | Tracking 提交；Edit → Change position 的 Change 模式提交位置编辑，Continuous 按其会话规则处理。Trajectory 使用 Enter/Apply，右键不替代曲线 Apply |
| 右键（Camera 页） | 当前帧已是关键帧时，跳到下一个关键帧；只有一个时提示，不等同 Enter 的关键帧提交 |
| Esc | 取消、放弃未提交的修改；退出 Tracking、丢弃曲线预览；关闭 Scale 编辑器或退出其选择/编辑；其他工具取消当前模式，Continuous 按会话规则结束 |
| Delete | 删除；Tracking 删除当前点；Trajectory 删除曲线锚点；Scale 删除选中点；Camera 删除选中关键帧/差值；普通编辑按当前 ID 和范围删除 |
| Ctrl + Z | 活跃编辑中的局部撤销或提交 History；文本焦点可优先处理文字撤销 |
| Ctrl + Y | 活跃编辑中的局部重做或提交 History；文本焦点可优先处理文字重做 |
| H / B | 有活动目标时改为 hornet / bee 并提交类别命令 |
| M | Edit 的 ID 页中将活动 ID 填入 Merge target；已有 target 时追加至 source 集合 |
| Alt + 左键 | 画面内人工 Tracking 点；会话外临时修正按松键规则结束，会话内不自动提交整段 |
| Alt + Shift + 左键 | 画面内选模板并转到 Track Motion；之后手工 Run Auto |
| 仅按 Alt / Alt + Shift | 不因修饰键本身在画面外建立模板 |

快捷操作受焦点和当前工具影响。输入框/下拉框优先处理文字与选择，画布快捷键需先将焦点移出输入框；只读 Postprocess Lab 会拦截修改用的 Enter / Delete。表格中 Ctrl + C 等按相应表格自身行为处理。Enter、右键、Finish、Apply 仅提交工作数据，不代替 Save；重新打开文件的既往 History 保持只读。

## 15.3 数据字段

### 15.3.1 位置来源

| `position_source` | 含义 |
| --- | --- |
| `manual_point` | 人工指定的点生成位置 |
| `manual_box` | 模板取样、模板区域或偏移等人工确定的框 |
| `template_track` | 普通 Auto 接受的模板匹配位置 |
| `guided_track` | Mouse guided 接受的匹配位置 |
| `edge_assist` | Edge 接受后的细化位置 |
| `yolo_assist` | YOLO 接受后的细化位置 |
| `curve_edit` | 已有位置经轨迹编辑、平滑、重绘、分配或变换修改 |
| `curve_fill` | 曲线工具补充的原本缺失帧位置 |

来源表示最终修改类别，不等于完整的所有处理步骤日志。多个 Trajectory 模式均写为 curve_edit；如分析需要具体算法与参数，应另保留处理记录和编辑前数据。人工失败重试通过时也可能保留人工来源并附有匹配分数，不能仅凭一个字段反推所有交互过程。

### 15.3.2 匹配与辅助字段

| 字段 | 含义与单位 |
| --- | --- |
| `frame` | 从 1 开始的实际解码顺序帧号 |
| `track_id`、`class` | 目标数字身份及类别 |
| `x / y / w / h` | 最终框中心及尺寸，源图像素 |
| `best_score` | 最佳模板匹配分数，保存为 0–1 数值，不是界面百分数字符串 |
| `second_score` | 竞争空间位置的分数 |
| `margin` | best_score − second_score |
| `template_frame` | 本次获胜模板的来源帧 |
| `recognition_x / recognition_y` | 应用 Mark offset 前的识别特征中心 |
| `match_rotation_deg` | 相对模板基准的旋转角度（°） |
| `match_scale` | 相对模板基准的尺度倍率，1 表示不缩放 |
| `assist_confidence` | YOLO 辅助的检测置信度，不等同于模板 Score |

字段只在相应操作产生信息时有意义；人工重写会清除不再适用的匹配数据。最终 x/y 可能包含 Mark offset 和 Assist 调整，而 recognition_x/y 描述识别阶段的位置，二者不同不一定是错误。

已有数据的其他字段按编辑规则保留。Tracking 的位置来源应优先查看 position_source 及 History，不能只用原有 `detected` 或 `confidence` 推断当前位置完全来自哪种算法。

### 15.3.3 Match 与 Detection 来源

Match 还记录 manual_track_name、manual_binding_state、manual_binding_finalized、manual_binding_manual_only、manual_binding_position_source 和相应源身份。绑定来源与 Tracking 的 position_source 不可互换解释。内部 `_...` 字段服务事务和缓存，不应直接作为分析指标。

Detection 的观测与估计必须结合 detected、插值/来源标识及参数快照解释。后处理 R 表示恢复事件，~ 表示估计位置。置信度、匹配 Score、Margin、审核状态是不同量，不能用单一阈值代替全部质量控制。

连续序号确保图片对应，并不保证物理拍摄时钟连续。帧差/FPS 给出标称帧时间；采用此模型做运动分析时，应在分析方法中说明。

### 15.3.4 标注保存 与 boutlist

标注文件为与视频文件对应，内部同时保存 immutable raw、当前 reviewed/final、元数据、修改审计和命令历史（SQLite 是正式工作格式，旧版 csv 格式择不包含 immutable raw、且修改审计和命令历史则记录于同文件名前缀的 _edit_log.txt 中）。`_review_uid` 是工作行的稳定内部标识，不用 DataFrame 行序号定位保存目标；CSV 兼容导出不输出内部列。`raw_track_id` 保留上游身份，`track_id` 表示当前身份；`raw_det_index` 联同 raw 帧号定位原始检测，人工新增和插值不伪造 raw 关联。绑定对齐改变最终 `frame` 时，`raw_frame` 保留原始观测帧；`source_annotation_path` 保留标注来源。

不同 raw 来源的工程不能直接追加到同一库，否则 raw 行索引可能误指另一段检测。另存新工程不能覆盖另一份已有项目；当前文件 Save 可正常更新。无可核验 raw 身份的旧 CSV 追加可保留 `legacy_raw_det_index` / `legacy_raw_frame` 供核对，但不建立与当前 raw 的关联。

CSV 保留为兼容输入/导出。首行 JSON 及 `.metadata.json` 承载元数据，`_edit_log.txt` 保存可读历史；它们不包含 raw 库、完整命令参数或数据库审计。额外列按编辑规则保留，复杂对象导出为 JSON 文本；CSV 的隐式类型推断可能改变前导零、空字符串等，精确类型以 SQLite 为准。完整保存规程见 [基础操作](01_基础操作说明.md#15-保存标注与导出数据表)。
