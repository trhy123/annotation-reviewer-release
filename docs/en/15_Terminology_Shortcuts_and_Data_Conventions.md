# 15 Terminology, Shortcuts, and Data Conventions

[Return to the main index](00_Annotation_Reviewer_User_Manual.md)

## 15.1 Terminology

| Term | Definition |
| --- | --- |
| frame | Numbered from 1 in actual decoded image order |
| PTS | Presentation timestamp in the container/bitstream; intervals need not equal exactly 1/FPS |
| ID / track_id | Target identity in the current results, distinct from class |
| raw ID | Identity generated by the upstream detector/tracker |
| stable ID | Identity after postprocessing reassociation; numeric values do not directly correspond between different tests |
| template | Appearance reference cropped from a known frame; not YOLO model weights |
| keyframe | Frame with a manual or explicit reference state; template source frames and Camera keyframes serve different purposes |
| candidate | Potential match, binding, or identity continuation awaiting a decision |
| pending | Edit not yet committed as a segment-level History operation |
| preview | Computed/interactive result that can be confirmed or discarded |
| commit | Writes to current working data; does not mean saving a file |
| raw cache | Cache after upstream detection thresholding and before custom postprocessing |
| sidecar | Parameter and source metadata file saved alongside results |
| overlay | Boxes, text, trajectories, and auxiliary graphics drawn over the video |

## 15.2 Keyboard and Mouse Shortcuts

| Action | Scope and behavior |
| --- | --- |
| Space | Controls playback during manual marking or before entering a session; controls tracking while automatic tracking is running or paused |
| Mouse wheel / Shift + mouse wheel | Steps backward/forward by 1 frame / 10 frames; Ctrl + wheel still zooms the image |
| ← / D | Previous frame |
| → / F | Next frame |
| Alt + ← / → | Returns to the previous navigation position/restores the next position |
| Shift + ← / Shift + D | Moves back 5 seconds (steps by round(5 × FPS) frames) |
| Shift + → / Shift + F | Moves forward 5 seconds (steps by round(5 × FPS) frames) |
| `,` / `.` | Navigates to the first/last frame of the selected identity's range, or the video if nothing is selected; equivalent to playback bar first/last buttons |
| `[` / `]` | With an automatic ID selected, equivalent to the Selected ID segment start/end buttons |
| Ctrl + left-click | Multiple selection in normal selection mode; active editing tools may take interaction priority |
| Ctrl + wheel | Zooms the video or template preview |
| Middle-button drag | Pans the video or template preview |
| X / C | Decreases/increases Speed by one dropdown preset, stopping at the limits |
| Z | Switches between 1× and the most recent non-1× speed in this run |
| R | Controls playback direction by enabling/disabling overall playback Reverse; does not change Tracking Reverse |
| Backspace / mouse back button | Returns to the previous manual navigation position; Backspace still deletes text in input fields |
| Mouse forward button | Restores the next navigation position |
| Ctrl + Alt + ← / Ctrl + Backspace / Ctrl + mouse back button | Restores the previous object selection and its frame number |
| Ctrl + Alt + → / Ctrl + mouse forward button | Restores the next object selection and its frame number |
| Ctrl + A | Selects all visible rows in the focused table; on IDs, selects only visible IDs in the current class table; in the image, selects current-frame targets; in a text field, selects all text |
| Ctrl + O | Opens annotation SQLite or legacy CSV, not a video |
| Ctrl + S | Saves annotations to the current SQLite annotation file; first save from a legacy CSV requires selecting SQLite |
| Ctrl + Shift + S | Save as; the default name adds a date/time suffix; saves SQLite or exports compatibility CSV |
| Ctrl + ← | Moves selection left among current-frame targets without changing frames |
| Ctrl + → | Moves selection right among current-frame targets without changing frames |
| Ctrl + ↑ | Moves selection upward among current-frame targets without changing frames |
| Ctrl + ↓ | Moves selection downward among current-frame targets without changing frames |
| Arrow keys without Ctrl | Nudges a selected Scale point or Camera anchor by 1 pixel, taking priority over normal frame navigation |
| Hold Ctrl / release Ctrl | Temporarily suspends trajectory hovering and picking / keeps them suspended for 3 seconds before restoring the original Pick trail setting |
| Enter | Confirms navigation in the frame field; confirms Scale angle/length input; records a keyframe when a Camera anchor is selected |
| Enter / right-click | On Tracking, Enter performs Start/Pause/Resume and right-click commits; on other tabs, Enter retains Tracking commit behavior. In Edit → Change position, Change commits position edits, while Continuous follows its session rules. Trajectory uses Enter/Apply; right-click does not replace curve Apply |
| Enter (Tracking tab) | Start/Pause/Resume; text fields retain input confirmation, and Trajectory previews retain Apply |
| Right-click (Camera tab) | If the current frame is already a keyframe, jumps to the next keyframe; reports when only one exists, and does not perform Enter's keyframe commit |
| Esc | First cancels a large ID selection collection task while retaining the original selection; otherwise cancels/discards uncommitted changes, exits Tracking, discards curve previews, closes the Scale editor or exits its selection/editing state; other tools follow their own session rules |
| Delete | Deletes; removes the current Tracking point, a Trajectory curve anchor, a selected Scale point, or a selected Camera keyframe/delta; normal editing deletes within the current ID and range |
| Ctrl + Z | Local undo during active editing or undo of committed History; focused text takes priority for text undo; Boutlist editing uses independent cell undo |
| Ctrl + Y | Local redo during active editing or redo of committed History; focused text takes priority for text redo; Boutlist editing uses independent cell redo |
| Alt + C | Changes selected targets to the next class cyclically, following class editing scope and confirmation rules |
| M | On Edit's ID tab, enters the active ID as Merge target; if a target exists, appends it to the source set |
| N | On Edit's ID tab, removes selected active IDs present in the current frame from Merge Source; does not merge |
| Alt + L | Cycles through the interface languages in list order |
| Alt + left-click | Immediately marks the current frame manually in the image, retaining the session, Track ID, and templates; releasing Alt does not commit the segment |
| Alt + Shift + left-click | Selects a template in the image and switches to Track Motion; Run Auto is then started manually |
| Ctrl + Alt (held) | After entering manual marking, continuously specifies positions from the mouse, stepping frames according to Speed and Tracking Reverse; releasing either key pauses |
| Alt / Alt + Shift alone | Modifier keys alone do not create a template outside the image |

Shortcuts depend on focus and the current tool. Main-window buttons, checkboxes, and non-editable dropdowns do not intercept the Space controls above; clicking a blank area returns focus to the image. Text fields prioritize text, tables retain selection and editing, and independent dialogs retain their own keyboard behavior. Move focus out of input fields before using other canvas shortcuts; read-only Postprocess Lab blocks modification keys Enter / Delete. Table shortcuts such as Ctrl + C follow each table's own behavior. Enter, right-click, Finish, and Apply commit working data only and do not replace Save; prior History in reopened files remains read-only.

## 15.3 Data Fields

### 15.3.1 Position Sources

| Position source marker | Meaning |
| --- | --- |
| `manual_point` | Position generated from a manually specified point |
| `manual_box` | Manually determined box through template sampling, template region, offset, or similar input |
| `template_track` | Template matching position accepted by normal Auto |
| `guided_track` | Matching position accepted by Mouse guided |
| `edge_assist` | Refined position accepted by Edge |
| `yolo_assist` | Refined position accepted by YOLO |
| `curve_edit` | Existing position changed by trajectory editing, smoothing, redrawing, redistribution, or transformation |
| `curve_fill` | Previously missing frame position added by curve tools |

The source indicates the final modification category, not a complete processing log. Multiple Trajectory modes use `curve_edit`; if analysis requires the specific algorithm and parameters, retain separate processing records and pre-edit data. A manual retry accepted after failure may also retain a manual source with a match score; one field cannot reconstruct every interaction step.

### 15.3.2 Matching and Assist Fields

| Field | Meaning and units |
| --- | --- |
| `frame` | Actual decoded-order frame number, starting from 1 |
| `track_id`, `class` | Numeric target identity and class |
| `x / y / w / h` | Final box center and dimensions in source-image pixels |
| `best_score` | Best template match score, stored as a 0–1 value rather than a UI percentage string |
| `second_score` | Score of a competing spatial position |
| `margin` | best_score − second_score |
| `template_frame` | Source frame of the winning template |
| `recognition_x / recognition_y` | Recognized feature center before Mark offset is applied |
| `match_rotation_deg` | Rotation angle relative to the template reference (°) |
| `match_scale` | Scale multiplier relative to the template reference; 1 means no scaling |
| `assist_confidence` | YOLO assist detection confidence, distinct from template Score |

Fields are meaningful only when the corresponding operation produces that information; manual overwriting clears matching data that no longer applies. Final x/y may include Mark offset and Assist adjustments, whereas recognition_x/y describes the recognition-stage position; a difference is not necessarily an error.

Other existing fields are retained according to editing rules. To identify Tracking position sources, prioritize `position_source` and History rather than inferring the algorithm entirely from original `detected` or `confidence` fields.

### 15.3.3 Match and Detection Sources

Match also records manual_track_name, manual_binding_state, manual_binding_finalized, manual_binding_manual_only, manual_binding_position_source, and corresponding source identities. Binding sources and Tracking position_source are not interchangeable. Internal `_...` fields support transactions and caching and should not be used directly as analysis measures.

Interpret Detection observations and estimates together with detected, interpolation/source markers, and parameter snapshots. In postprocessing, R indicates a recovery event and ~ an estimated position. Confidence, matching Score, Margin, and review status are different quantities; one threshold cannot replace all quality control.

Consecutive numbering ensures image correspondence but does not guarantee continuous physical recording time. Frame difference/FPS gives nominal frame time; state this model in the methods when using it for motion analysis.

### 15.3.4 Filter Measurements and Stable Record Identities

Columns beginning with `@` in Filter tables are derived measurements or statistics, such as @speed, @direction, @acceleration, and @curvature; they support the current query and preview and are not written to SQLite as new raw annotation fields. Metrics… determines their units and calculation conditions; see [Filter motion measurements](02_Interface_and_Segment-by-Segment_Review.md#2114-motion-measurement-settings-and-definitions) for definitions.

Precise filtered editing locates records by automatic row `_review_uid` or by manual trajectory name, aligned frame, and sample index. ID identifies an object; UID identifies a specific row, and they are not interchangeable. Duplicate rows with the same ID and frame remain separate records, and only actually matched rows enter the precise scope. Undefined derivatives, overall direction, and tortuosity indicate missing valid measurement conditions and should not automatically become zero.

### 15.3.5 Saving Annotations and Boutlist

SQLite is the working annotation format. It stores the current annotations, metadata, and available raw data, with audits and undo state depending on the save mode. Saves identify working rows by the stable internal `_review_uid`. CSV exports the public columns. `raw_track_id` retains the upstream identity, while `track_id` denotes the current identity. `raw_det_index` together with the raw frame number locates the original detection. Manual additions and interpolation leave raw links empty. If binding alignment changes the final `frame`, `raw_frame` retains the original observation frame. `source_annotation_path` retains the annotation source.

Projects with different raw sources cannot be appended directly into one database, as raw row indices could then refer to detections from another sequence. Saving a new project under a new name cannot overwrite another existing project; Save can update the current file normally. Appending legacy CSV without verifiable raw identity may retain `legacy_raw_det_index` / `legacy_raw_frame` for checking, but does not establish links to the current raw data.

CSV export is compact. First-row JSON and `.metadata.json` carry metadata. Complex objects export as JSON text, and CSV type inference may change leading zeros or empty strings. Use SQLite for exact types and working history. [Saving annotations](01_Basic_Operations.md#15-saving-annotations-and-exporting-data-tables)
