# 1 基础操作说明

[返回总目录](00_操作手册.md)

## 1.1 使用范围与输入准备

Annotation Reviewer 用于查看视频与逐帧标注，修正身份、位置和轨迹，并记录片段事件和空间标定。视频、自动标注 SQLite、Tracker 人工轨迹、raw detection cache 是不同来源；打开某一项不表示其他项已经匹配或对齐。

准备文件时，应保留原视频和标注文件。为人工审阅结果使用单独文件名；通过 File 核对实际载入路径，不仅依据窗口中相似的文件名判断片段。

| 输入 | 用途 | 核对项目 |
| --- | --- | --- |
| 视频 | 提供逐帧图像 | 拍摄片段、分辨率、首尾画面、解码帧数 |
| 标注文件（SQLite / CSV） | 储存标注信息（框、类别、ID等）、元数据和编辑记录 | 帧号、视频对应关系、坐标单位 |
| 人工轨迹（Tracker 工程文件 .trk / 转换的CSV） | Match 的人工身份与位置依据 | 原视频是否倒放、人工轨迹帧率、对齐帧 |
| raw SQLite 缓存 | Detection 后处理重放 | 原视频路径、已提交帧范围、上游推理参数 |
| Boutlist CSV | 成批组织片段和元数据 | 字段映射、路径、记录是否唯一 |

## 1.2 启动与窗口识别

### 1.2.1 源码运行

在项目根目录打开终端，使用安装了项目依赖的 Python 环境执行 `python -m app.launch`。Windows 可使用 `start_annotation_reviewer.bat`；它切换到项目根目录并优先调用 PATH 中的 `pythonw.exe`，没有该程序时调用 `python.exe`。调试启动错误时使用带控制台的 `python`。

该启动脚本设置有运行缓存路径 `PYTHONPYCACHEPREFIX`，支持相对路径，主进程和继承环境的 Python Worker 将字节码缓存集中写入当前项目的 `PYTHONPYCACHEPREFIX`，当前在目录外的 `.pycache/`。移动整个项目后从新位置运行脚本，缓存也随新项目位置生成，但已有的缓存目录 `__pycache__` 仍需手动删除。直接从终端启动并希望采用相同策略时，在项目根目录设置该环境变量后运行程序。

源码窗口标题包含进程 PID，例如 `Annotation Reviewer GUI [12540]`，可用于区分多个同时打开的实例。加载视频或 bout 后，标题增加显示文件/bout 信息；星号表示工作数据有尚未保存修改。

### 1.2.2 发布包运行

运行发布包中的主程序。检测任务由独立 DetectionWorker 执行；不要仅复制主 EXE 后丢弃其依赖目录、预设、媒体运行时和检测子程序。发布包根目录的 `presets_detection/` 是 GUI 与 Worker 共用的预设来源。

## 1.3 打开文件的操作规程

### 1.3.1 直接打开视频与标注

1. 使用底部 Open 菜单打开视频。
2. 检查首帧、末帧和当前帧总数；索引仍在建立时留意状态提示。
3. 打开对应标注 SQLite。出现导入处理选项时核对其来源和导入方式，再执行。
4. 在 File 核对视频和各标注来源路径，在 Current frame 核对框位置与画面。
5. 至少在开头、中间、末尾三个位置检查图像和标注对应关系。

`Auto open corresponding file` 会尝试在同一文件夹下和 Boutlist 中寻找对应文件，匹配到多个相关文件时会提示选择。除了确定文件是否为所需要的文件或文件版本，在载入多个来源时，来源列表与框颜色/ID 都应检查。

### 1.3.2 从 Boutlist 打开

1. 先在 Display → Boutlist fields 配好列名映射。
2. 点击 Open Boutlist，选择记录。
3. 核对视频、检测文件和人工轨迹路径；没有的来源可保持为空。
4. 检查 Start、End、Capture、人工轨迹对齐和标尺摘要。
5. 对同一文件存在多个候选记录的情形，明确选择当前 bout；不要把另一行的元数据同步到当前片段。

字段格式、示例表格及同步规程见 [Boutlist 制作与使用](13_Boutlist制作与使用.md)。

### 1.3.3 关闭或更换源文件

File 的文件选择框用于指定待操作的来源，Select 更换文件，Close 移除当前会话中对应来源的数据；它不删除磁盘原文件。关闭 raw 缓存只解除缓存关联。关闭视频或使用底部 Close 时，处理未保存提示后清空本次视频的数据、选中身份、输入范围、端点、事件、模板、Camera anchors、暂存草稿及预览；参数阈值、渲染方式和其他应用设置保留。更换视频或关闭会话前，先结束未提交编辑并处理未保存结果提示。

### 1.3.4 视频索引与画面身份

打开视频时，程序在后台建立或读取视频索引，将真实解码画面按顺序编号。索引任务启动不等于立即完成；首次建立的耗时取决于画面数量、编码、存储速度及处理器负载。来源未变化且索引缓存适用时可直接复用。

已有标注使用解码顺序帧号，不要求每一行都保存临时画面引用。临时引用用于记录索引协调完成前编辑所对应的实际画面；空引用并不表示该帧尚未索引。视频中出现时间戳缺口时，程序通过画面身份协调相关编辑，不按缺口时长插入虚构帧。

Save / Save as 等待尚未完成的索引和编辑协调。完成后继续保存；索引失败或画面身份无法唯一确认时，保留编辑并报告原因。等待期间更换标注文件后，原文件的排队保存和 Boutlist 同步请求不再作用于新文件。

索引使用实际可解码画面数量，不将容器数据包数量直接作为帧数。无法可靠按时间戳定位时，从视频开头计数解码。结果核验与恢复规程见 [撤销与恢复](12_撤销与恢复说明.md#1253-画面身份核验尚未完成时保存)。

## 1.4 定位、播放与视图操作

| 操作 | 效果 | 对标注的影响 |
| --- | --- | --- |
| 输入帧号并执行 Goto | 定位指定图片编号 | 不修改位置 |
| 前/后一帧 | 暂停后逐帧查看 | 不生成中间标注 |
| Alt + ← / → | 返回上一浏览位置／恢复下一浏览位置 | 不修改标注 |
| Shift + ← / → | 向前或向后定位 5 秒，按 round(5 × FPS) 帧步进 | 不修改标注 |
| 滚轮 / Shift + 滚轮 | 每次分别前后切换 1 / 10 帧 | 滚轮幅度不放大单次步长；快速操作累计目标并取消过期解码 |
| 首/尾帧 | 定位视频边界 | 不改变分析 Start/End |
| 播放/暂停 | 连续显示或停止 | 不提交编辑 |
| Reverse | 反向播放 | 与 Tracking 的 Reverse 分别设置 |
| Loop | 在有效播放范围边界循环 | 不复制轨迹 |
| Speed | 设置播放倍速；也是 Auto Tracking 的速度上限 | 不改变视频 FPS 或 CSV 帧号 |
| 点击或拖动进度条 | 按点击位置横坐标定位指定帧 | 进行中的 Auto Tracking 暂停并保留待提交点 |
| 点击进度条下方条带或符号标记 | 定位可见范围内的帧或对应标记帧 | 邻近端点可吸附；远处空白不切帧 |
| Ctrl + 滚轮 | 以指针附近为中心缩放 | 不改原图坐标 |
| 中键拖动 | 平移视图；中键按住期间不响应滚轮切帧 | 不平移标注数据 |
| Zoom − / + / R | 缩小、放大、重置视图 | 只改变观察方式 |

悬停进度条或轨迹可以显示定位提示；悬停本身不应作为已切帧的依据。核对画面上的当前帧号。

Display → Others → Accessibility 的 **Seek preview** 控制视频缩略预览。文件及索引载入完成后，程序空闲时预载最多 256 张基础图，在当前视频期间保留。鼠标沿进度条移动时立即显示最近的缓存图；慢速移动或停留约 90 ms 后补充更准确的帧。预览不包含标注，不切换主画面，不改变当前选择。Width px 设置显示宽度，默认 240，允许 80–640；缓存图始终不超过 240×135，按比例显示。索引未完成仍可请求近似画面。鼠标离开、完成拖动、切换视频或主窗口失去活动状态时隐藏预览；操作 Select bout 等其他窗口时，经过进度条不会弹出预览或激活主窗口。

按住 Ctrl 在进度条上移动时，预览当前播放器缩放、平移后的可见画面区域。局部图按需生成，不参与基础图预载；改变视图范围后使用对应范围的缓存。已通过图片身份核验的缩略图显示 `Frame N`，基础取样或尚未核验的图仍显示近似提示。

倒放时在内存中分块正向解码，再按相反顺序呈现，不生成整条倒放视频；首次进入或跳到未缓存位置时需要先准备一块画面。`cpu_frames` 与 `mpv_gl` 均支持 Reverse。`mpv_gl` 保持原渲染选择，由 GPU 显示这些解码帧。普通滚轮的连续事件按短周期累计目标，保留可复用的解码管线。

进度条的自由拖动须从进度条区域开始；按住后可移出该区继续拖动。进度条下方的标记区域仅用于点选，按下时确定目标，松开时完成定位；不能从底部空白开始拖动。完整吸附规则见[进度条、条带与悬停](02_界面与逐段审阅说明.md#25-进度条条带与悬停)。

### 1.4.1 时间戳缺口与图片编号

识别和标注按真实解码顺序连续编号，第一张图片为第 1 帧。容器时间戳在相邻图片间跳变，不会凭空插入标注帧。例如相邻图片时间戳相差 0.756 秒，只要解码图片连续，它们仍是相邻编号。

图片索引异步建立。暂停定位在目标图片尚未确认时保留已确认画面，避免旧图像配上新标注。`Frame mapping pending` 表示图片身份仍待核验；最终保存不能用估算时间替代正式图片身份。已有 CSV 不会因打开而被猜测重编号。

mpv_gl 使用播放器时间原点与图片索引相互映射。容器秒数、播放器秒数、连续图片编号是不同概念；不能直接用任意一项秒数乘 FPS 推断另一项。后续分析若采用帧差/FPS，应明确使用连续图片时间，而不是含时间戳间隔的采集时长。

### 1.4.2 浏览位置与对象选择的回退和恢复

Browse Back / Browse Forward 用于返回审阅位置，不撤销或重做标注修改。程序分别维护帧位置记录和对象选择记录，两者不写入结果数据库。

| 操作 | 快捷键 | 效果 |
| --- | --- | --- |
| 位置回退 | Alt + ←、Backspace、鼠标后退键 | 返回上一浏览位置 |
| 位置前进 | Alt + →、鼠标前进键 | 恢复下一浏览位置 |
| 选择回退 | Ctrl + Alt + ←、Ctrl + Backspace、Ctrl + 鼠标后退键 | 恢复上一对象选择及当时帧号 |
| 选择前进 | Ctrl + Alt + →、Ctrl + 鼠标前进键 | 恢复下一对象选择及当时帧号 |

位置记录包括进度条定位、帧号输入、表格与轨迹点定位、段首尾跳转。一次拖动仅形成起点和终点记录；间隔不超过 500 ms 的连续逐帧操作合为一次。播放、自动追踪和自动下一帧不会逐帧增加记录。播放后使用后退时，当前播放位置可作为前进返回点。

选择恢复作用于 ID、具体框和人工轨迹选择，包含活动对象。已删除的行或轨迹点不恢复，也不重新创建数据。恢复后同步画面、表格高亮和进度条条带；浏览恢复会暂停播放和自动追踪，保留尚未提交的编辑。

**操作示例：** 在第 100 帧检查目标后定位到第 800 帧，再定位到第 1200 帧。按 Backspace 返回第 800 帧，再按一次返回第 100 帧；鼠标前进键向前恢复。返回第 800 帧后另行定位到第 900 帧，将建立新的位置分支，原先通向第 1200 帧的前进分支不再保留。

**选择示例：** 在第 200 帧选择 ID 12，再在第 650 帧选择 ID 19。Ctrl + Alt + ← 恢复第 200 帧及 ID 12 的选择；该操作不修改两个 ID 的标注内容。

每套记录最多保留 500 项，退出程序后清除。切换视频时重建两套记录；同视频重新载入标注时重建选择记录。输入编辑器获得焦点时，Backspace 保留删除文字行为。Alt + 左右方向键访问位置浏览历史；同时按 Ctrl 则访问对象选择历史。

主窗口按钮、复选框和非编辑下拉框不占用空格键；点击视频或主窗口空白区将键盘焦点交回播放。文本输入框和独立弹窗保留自身键盘操作。X／C 在 Speed 的预设档位中减速／加速，Z 切换 1× 与最近一次非 1× 倍速；倍速记忆仅保留在本次运行中。类别循环切换改用 Alt + C。

## 1.5 保存标注与导出数据表

### 1.5.1 提交与保存的区别

Tracking 的 Finish、Trajectory 的 Apply、Scale 的 Apply 将本次操作提交到工作数据；它们不会直接完成 SQLite 保存。History 记录已提交操作；恢复快照用于中断恢复，也不替代正式输出。

### 1.5.2 保存规程

1. 完成当前编辑：Tracking 用 Finish/Cancel，Trajectory 用 Apply/Discard，Scale 用 Apply 或取消；结束 Continuous 编辑。
2. 检查关键帧、轨迹两端、身份交接和元数据。
3. 点击 Save（Ctrl + S）写回当前 SQLite，文件名保持原样，不追加日期时间。旧 CSV 首次正式保存时选择 SQLite 目标，默认文件名不带日期时间。
4. 保留阶段版本或导出旧格式时使用 Save as（Ctrl + Shift + S）。默认文件名带 `YYYYMMDD_HHMMSS` 后缀；格式可选 SQLite result 或 Legacy CSV。Edit → Points 的 `Save only the target segment` 同时作用于两个保存入口；不勾选时保存完整工作标注，勾选时仅保存 Start–End 内的最终标注。该选项独立于保存核验开关。
5. 启用保存核验时，在窗口中逐项记录实际核验状态；窗口仅显示 Display → Boutlist fields 中启用的询问项目。未完成的项目可以不勾选，不应为了保存而虚报核验。Confirm 后等待后台成功提示；Back 会取消保存。CSV 仅作兼容导出，详见 1.5.5。
6. 若提示回写 Boutlist，核对记录和字段后选择；这与保存标注 SQLite 是不同写入。
7. 重新打开输出，抽查关键帧与元数据。

### 1.5.3 SQLite 输出范围与内容

完整保存输出工作标注及其元数据。仅输出 Start–End 时包含两端，保留原视频帧号，例如 1000–1200 的输出仍从 frame=1000 开始；范围外工作数据不因此从会话删除。

勾选片段输出后，Save 将当前结果库的最终标注同步为指定范围；Save as 将片段输出到独立文件，不覆盖当前全量库。raw 原始检测及溯源历史仍保留原来源覆盖范围，不能以 raw 表或历史中的最大帧号判断最终标注的输出范围。重新打开后，`reviewed_detections` 只包含本次保存范围内的标注，视频本身仍可定位到范围外。

**示例：** Start=1、End=112、视频共 248 帧时，勾选该选项并点击 Save，当前库的最终标注只保留 frame=1–112；第 113–248 帧的标注仍在当前内存会话中。若在关闭前取消该选项并再次 Save，将按当前内存完整工作表保存；重新打开片段库后，不能通过取消该选项恢复未载入的范围外标注。原始检测和行级保存历史用于溯源，不自动注入工作标注。

数据区表格是查看和选择界面，Save / Save as 保存的是当前工作标注，不等于把正在高亮的表格单元格导出。工作表与 raw 原始数据分表保存，不将 raw 行混入工作标注。已载入的工程或当前同一视频的检测缓存随 SQLite 保存一并纳入结果库；需要后处理结果时先在 Detection 明确 Load result。

`info_points`、`info_events`、`scale_calibration` 等承载分析元数据；完整 Scale JSON 保存在标注文件，Boutlist 可按字段映射同时回写简短比例摘要和完整 JSON。不要仅保留 x/y 后删除身份和来源字段，再把文件当作完整审阅工程。

### 1.5.4 结果数据库与增量保存

每个视频使用一个 SQLite 结果文件，保存 final 工作标注、元数据和操作记录；有 raw 原始检测时，将其嵌入同一文件。没有 raw 也可完整保存和编辑工作标注，但不能据此重新执行 Detection 后处理。工程中已内置 raw 时，另存或移动结果不需要携带外部 raw cache、结果 JSON 或 `_edit_log.txt`。

| 表 | 保存内容 |
| --- | --- |
| `frames` / `raw_detections` | 按解码顺序记录全部 raw 帧（含空帧）及上游检测，不受人工修改影响 |
| `raw_metadata` | 上游模型参数、视频指纹、类别与 raw 完成状态 |
| `reviewed_detections` | 当前逐帧工作标注、来源字段及稳定行 UID，可直接 SQL 查询 |
| `raw_sources` | 库内 raw 的来源标识与来源元数据，不依赖外部缓存文件 |
| `manual_edits` | 每次保存新增、修改、删除行的前后内容与事务编号 |
| `save_transactions` | 保存时间、事务类型及增删改数量 |
| `events` | 有序事件记录 |
| `metadata` | 视频信息、Points、完整 Scale、Camera、参数和来源信息 |
| `history` | 可显示的操作历史 |
| `history_commands` | 命令类型、完整参数、时间、说明及撤销状态；复杂参数使用 JSON 类型编码 |

内存中的 DataFrame 和编辑/撤销行为不变。Save / Save as 冻结本次保存所需的数据，由后台线程以事务同步数据库；尚未执行保存的编辑不会提前写入正式结果。数据库不会额外生成 `_edit_log.txt` 或结果元数据 sidecar。SQLite 写入期间可能存在临时 `-wal`、`-shm` 文件，由 SQLite 管理；不要在写入期间只复制主文件作为完整备份。

普通编辑再次保存到当前文件时，按稳定 UID 仅冻结新增、修改行和删除 UID，不深拷贝或暂存整张工作表；事件、元数据、命令归档和历史与工作行在同一事务提交，失败时回滚。保存期间的新编辑保留为未保存状态。首次转换、另存新库、片段导出及部分批量修改/撤销仍可能需要全量快照和比较。另一个实例已更新文件时会拒绝覆盖其新版本。

首次保存或另存时，程序先在目标目录构建并提交临时数据库，成功后再发布到所选文件名。Save as 选择已有文件并确认覆盖后，会完整替换该目标，不保留目标中无关的旧工作标注或元数据；片段输出也允许在确认后覆盖当前文件。失败时保留原目标和当前内存编辑。普通 Save 继续使用 SQLite 事务与版本检查；保存过程中目标又被其他程序改动时停止覆盖并提示重新核对。

保存优先保留项目已内嵌的 raw。关联 raw 文件不可用时，保存前显示三种选择：**Locate raw...** 指定原始缓存或内置相同 raw 的结果库，并核验已记录的来源身份；**Save without raw** 仅保存工作标注、元数据和操作历史；**Cancel** 取消本次保存，保留未保存编辑。选择文件后取消文件窗口同样取消本次保存。此前没有关联 raw 的工程直接保存，不重复询问；明确舍弃 raw 并保存成功后，后续保存也不再要求恢复该外部文件。

写入期间可出现 `.sqlite-wal` 事务日志与 `.sqlite-shm` 共享索引。完成标注保存后，程序尝试将已提交日志归并到主库并转回普通日志模式；无其他连接占用时只保留结果文件。Detection 或其他连接仍在使用该数据库时保留 WAL，以保证并发读写。不得在使用期间手工删除这些辅助文件。

正常退出时，程序也尝试对已打开的结果库执行上述安全收尾；其他实例仍在使用、目录不可写或数据库不可用时保留辅助文件，不强行删除。辅助文件的存在不等于整个结果被独占锁定，普通日志模式同样保留 SQLite 的事务和文件锁机制。

结果文件在打开期间被移走或删除时，内存中的工作标注不会因此清空。退出检查发现已保存文件缺失时，会将当前数据视为需要重新保存并提示保存；取消退出可继续操作，明确放弃后退出才丢弃内存会话。重新保存时按 raw 来源可用性选择恢复来源或仅保存标注。

删除恢复快照仅删除所选快照。程序只允许对自行管理的恢复会话目录作目录清理；外部手动快照旁的标注、视频及其他文件不参与清理。恢复目录包含 SQLite 或其他非恢复文件时，保留该目录。

完整命令归档用于溯源；重新打开文件后，既往 History / history_commands 保持只读，不重新注入当前会话撤销栈。当前会话内保存不清空其撤销能力；`.pkl` 恢复仍沿用原机制。

旧 CSV 可打开、追加或作为来源替换。导入后另存 `.sqlite` 完成转换；原 CSV 保留。需要同时保留全量库与片段时，使用 Save as 输出独立数据库；片段始终保留原帧号。

### 1.5.5 旧版 CSV 兼容导出

Save as 的 Legacy CSV 输出 UTF-8 BOM 编码的逐帧结果表，保留公开的身份、类别、来源、置信度、审核、位置、人工绑定及额外字段。视频信息、Points、Events、Scale 和 Camera JSON 写在首行对应单元格；同时生成同名 `.metadata.json`，空表也能保留这些元数据，以及 `_edit_log.txt` 可读历史。移动 CSV 时一并保留两个附属文件；范围导出包含两端并保持原帧号。

CSV 不包含 raw 检测库、行级审计和完整 history_commands，不能代替 SQLite 工程。导出后当前工作文件路径和未保存状态保持原样，不把 Boutlist 自动切换到 CSV。还需保留完整修改时执行 Save。CSV 可重新导入，但未知额外列中的复杂对象会变成 JSON 文本，旧 CSV 的类型推断也可能改变前导零或空值；需要精确类型与完整溯源时使用 SQLite。

## 1.6 带标注视频导出

### 1.6.1 参数

| 设置 | 含义 |
| --- | --- |
| Export Range | 包含两端的帧区间，支持 `1-2990`、`-2990`、`1-` |
| From Start to End | 使用 Points 的分析边界；取消后恢复手工范围 |
| Picture range | Left X 为选区左边界的横坐标，Top Y 为上边界的纵坐标，均以完整输出画布左上角为原点、单位为像素；W/H 为选区宽高。默认完整画面；启用 Expanded motion canvas 时使用扩展画布坐标 |
| Select area | 在主画面绘制并调整导出选区；再次点击完成，暗色遮罩区域不输出 |
| FFmpeg / Browse | 指定具备所需编码器的 FFmpeg 程序 |
| Encoder | 视频编码器，如 libx264 或可用的硬件编码器 |
| Preset | 对应编码器的速度、压缩效率取舍 |
| Quality | 对应编码器的质量参数；不是检测置信度，不宜在不同编码器间直接比较数值 |
| Render workers | 导出 Overlay 的 CPU 工作并行度，不是 Detection 的推理并行度 |

### 1.6.2 导出规程与检查

1. 保存工作标注，设置希望显示的框、ID、trail、Axis、Scale/网格和 Camera 补偿。
2. 点击 File 的 Export，先在非模态 Export settings 窗口确认时间范围、画面范围和编码参数；也可用 Settings 单独调整。该窗口不锁定主界面，显示时不主动抢占焦点，点击输入框后可正常编辑。
3. 需要裁切时点击 Select area，在画面拖动建立选区；拖动边缘或角部控制点调整尺寸，拖动选区内部平移。再次点击 Select area 完成。File 页显示选区预览，进度条下方红色条带标示导出时间范围。确认 Export 后选择输出文件，在独立进度窗口查看完成或失败信息。
4. 检查输出分辨率、帧序、颜色、拖尾方向、文字和补偿画布。
5. 确认后再导出完整范围。

时间范围和画面选区仅属于当前视频会话，不写入 settings.ini。关闭 Export settings 或按 Cancel 均保留已填写的范围，不启动导出；再次打开时恢复当前输入。只要 File 页面位于前台，画面选区遮罩和进度条下方的范围红色条带继续显示；切换视频时清除范围。视频导出跟随 Display 的 Overlay renderer：Qt raster 使用 Qt 绘制且不创建 OpenGL 上下文，OpenGL 使用保留式绘制。标注元素使用 Dispaly 中的当前显示设置；裁切在画布合成之后执行，HUD 在最终画面内重新布局。YUV 4:2:0 编码要求偶数尺寸，奇数宽高在右侧或底部补一个像素。

取消导出不撤销标注编辑，但取消生成的中间输出不能作为成功文件。视频编码器与 Overlay 绘制后端分别工作：使用硬件编码器不意味着框和轨迹已经由 GPU 绘制。

## 1.7 典型问题的检查顺序

- **框与图像似乎错位：** 先逐帧核对图片身份、视频与 CSV 配对及索引状态，再检查 Camera 坐标变换；不要先整体平移所有框。
- **打开后没有框：** 检查当前帧是否有数据、来源是否载入、显示/类别过滤和试验图层 View 是否正确。
- **另存后帧号没有从 1 开始：** 局部输出保留原视频帧号，这是预期行为。
- **导出比播放慢：** 导出需要解码、绘制和编码；速度不受播放器实时性保证。用短片段分别检查绘制与编码配置。
