# 13 Boutlist 制作与使用

[返回总目录](00_操作手册.md)

## 13.1 用途与一行记录的范围

Boutlist 是普通 CSV 表，每行组织一个需要审阅的 bout：视频、自动标注、人工轨迹及对齐/分析元数据。它便于逐条打开和回写简短信息，不保存全部逐帧框，也不替代标注 SQLite。

同一视频可以有多个分析片段，但应使用明确 bout_id 和范围区分。回写前必须核对当前选中行，不能只凭视频文件名认定某一行就是目标。

## 13.2 文件制作规程

1. 使用支持 UTF-8 的表格工具或文本编辑器新建 CSV，第一行为列名。
2. 每行填写 bout 标识及实际存在的视频路径；逐帧标注和人工文件没有时可以留空。
3. 已知的 Start、End、Capture 和人工对齐信息按对应列填写。
4. 含逗号、引号或换行的文本使用标准 CSV 引号规则；不要手工按逗号切割记录。
5. 保存后，在 Display → Boutlist fields 配置列名映射，再 Open Boutlist。
6. 用一行试开并检查同步结果，确认后批量组织其他记录。

**示例：**

```csv
bout_id,origin_video_file,detection_file,analysis_start_frame,analysis_end_frame,capture_frame
trial01,E:/videos/clip01.MTS,E:/results/clip01_review.csv,100,1200,1185
trial02,E:/videos/clip02.MP4,,1,950,930
```

使用绝对路径最容易直接核对。使用相对路径时，需保持 Boutlist 和相关目录的位置关系。

相对路径优先按程序目录解析；该位置不存在时，再按 Boutlist 所在目录查找。启动终端的工作目录不参与解析。移动程序与数据时，应保持相应目录关系，并实际试开确认；另一台计算机的盘符路径不能直接作为通用路径。

## 13.3 Boutlist fields 映射设置

设置位于 Display 中 Playback 与 Others 之间。左侧项目代表程序内部含义，文本框填写 Boutlist 中的实际列名。

- 按列名精确匹配，包括大小写；输入值两端空白会被去除。
- 留空表示停用该项目的读取和回写。
- 两个项目不能指向同一个非空列名；Save settings（All 或 Boutlist fields） 会阻止重复映射。
- 列名输入框为草稿。只有范围选为 All 或 Boutlist fields 并点击 Save settings 后，映射才写入 `settings.ini`，并从本次会话开始生效。保存其他分组不会应用这组草稿。
- 未保存时打开或回写 Boutlist，继续使用上一次保存的映射。恢复为已保存值后，未保存提示自动消失。
- 改映射不会直接重命名或重写 CSV 列。
- Open Boutlist 选择窗口按 CSV 原始列名和原始列顺序显示，包括未映射的自定义列；内部规范字段只用于读取和回写，不额外显示一份。`setting.ini` 中的 `column_widths` 仅控制列宽，不控制列顺序。
- 更改后应重新打开当前 Boutlist 记录，避免沿用旧映射选行时的快照。
- 直接打开标注文件时，元数据查找沿用已选 Boutlist；未选记录时使用当前配置的 Boutlist 路径，不沿用启动时的旧默认路径。

**例：** 如果视频路径、分析开始帧和捕获帧这三个字段在表格中的列名分别为 `Video`、`Start`、`Capture`，将它们分别填入 origin_video_file、analysis_start_frame、capture_frame 对应的文本框，则程序会将其理解为视频路径、分析开始帧和捕获帧，选择窗口显示实际列名，并在回写时只更新映射的新列而不会补出旧列；程序内部使用的变量名称和输出标注 SQLite 的规范字段名不改变。

## 13.4 可映射字段

### 13.4.1 标识与来源

| 项目 | 含义 |
| --- | --- |
| bout_id | 片段标识，建议稳定且可区分 |
| trial_id | 实验/试次标识 |
| phase | 阶段信息 |
| origin_video_file | 视频文件 |
| detection_file | 自动或审阅标注 SQLite |
| manual_track_file | 人工轨迹文件 |
| trk_file | Tracker 工程来源 |

### 13.4.2 分析范围与主体

| 项目 | 含义 |
| --- | --- |
| analysis_start_frame / analysis_end_frame | 包含两端的视频分析范围 |
| capture_frame | 成功捕获参考帧 |
| nest_x_px / nest_y_px | 巢门口像素坐标摘要，与程序的 Hive 信息对应 |
| scale_px_per_cm | 简短的代表性 px/cm |
| victim_id_at_capture / captor_id_at_capture | 被捕蜜蜂与得手胡蜂的已核对身份 |
| left_censored | 真实互动起点早于可用分析画面 |
| verified_capture_pair | 捕获主体轨迹已核验 |
| verified_exposed_bees | 低位和外围蜜蜂已核验 |
| verified_other_hornets | 其他胡蜂及同类干扰已核验 |
| review_notes | 审阅备注 |
| camera_motion | Camera 相关摘要标志，不能代替完整锚点观测 |

### 13.4.3 人工轨迹对齐与视频属性

| 项目 | 含义 |
| --- | --- |
| trk_capture_frame | Tracker 时间轴中的对应参考帧 |
| trk_align_first_frame / trk_align_last_frame | 使用的 Tracker 帧范围 |
| trk_reverse | 是否来自倒放人工标注 |
| trk_fps | 人工标注视频帧率 |
| frame_offset | 额外视频帧偏移 |
| x_offset / y_offset | 人工点在原图中的位置偏移 |
| fps | 视频帧率摘要 |
| resolution_width / resolution_height | 分辨率字段 |
| video_width / video_height | 视频宽高字段 |

字段存在不代表已填写且有效。帧号和身份应为合理整数；布尔项目使用一致、可识别的表示；文件路径必须能够访问。不要把 Excel 的自动日期转换、科学计数法或浮点显示当作 ID 的真实值。

## 13.5 打开与同步规程

### 13.5.1 读取

Open Boutlist → 选择记录 → 核对 File 中实际路径 → 检查 Points 和 Match 参数 → 播放关键帧。字段映射只改变列名对应，不会修正错误视频配对或错误帧号。

### 13.5.2 回写

1. 在 Points 或 Match 修改相关信息并确认。
2. 执行 Sync to，或在程序提示回写时核对差异。
3. 确认显示的目标行和实际列名。
4. 完成后重新读取这一行验证。

Sync from 会把表中内容重新带入对应元数据。若当前会话有更准确的新值，应先判断是否需要覆盖。取消回写不意味着撤销已经保存到标注 SQLite 的结果。

读取冲突、Sync from 和 Sync to 共用数值比较：普通浮点数允许保存舍入误差（相对容差 `1e-7`、绝对容差 `5e-7`）；JSON 内浮点使用相对 `1e-7`、绝对 `1e-12`，JSON 键顺序不影响一致性。帧号、身份等整数仍精确比较；缺失或停用的映射不会在同步时清除现有值。精度差异一致时保留标注文件原有精度，不提示覆盖，也不为此重写 Boutlist。

`scale_px_per_cm` 只代表固定比例或完整标定的近似平均摘要。标注已含标定线、局部场或矩阵模型时，Boutlist 的简单比例不会触发替换完整标定的提示，Sync from 也不把它变成固定比例。

Boutlist 配置并提供有效完整 `scale_calibration` 时，可以与标注完整标定比较；真正不一致时再选择来源，默认保留标注。只有固定单值标尺时，选择新比例会同时更新比例和对应单值标定。

### 13.5.3 窗口与当前行定位

Select bout 使用独立的非模态窗口，可通过任务栏选择，并使用系统的最小化、最大化及关闭按钮。保持表格打开时，可以在主窗口播放、拖动进度条和核对标注。

再次按下 Open Boutlist 会激活现有窗口；能够可靠识别当前 Bout 时，当前行自动居中并选中。表格排序不会改变源文件行顺序，也不会改变当前行身份。

底部按钮从左到右为 Edit、↶、↷、Browse、Open。选中行并双击或按 Open 按钮打开当前选中行对应的 Bout 并切换到主窗口。选定的已经是当前打开的 Bout 时，不重新加载文件，仅切换到主窗口。非编辑状态下双击单元格也可打开该行。

首次打开该 Boutlist 后，在本次程序运行期间持续检查文件变动；关闭或隐藏 Select bout 不暂停该文件的检查，重新打开时保留变更标色。主窗口同步 Boutlist 后，相应单元格使用系统强调色；外部程序修改的单元格使用红褐色。刷新时按源行身份重新定位当前打开的 Bout，保留选中和高亮；文件排序或其他行的修改不改变该身份。身份不再能唯一确定时不猜测其他行。单元格正在编辑时暂缓外部刷新，避免覆盖尚未提交的输入。

### 13.5.4 单元格编辑规程

1. 打开 Select bout，核对正在编辑的 Boutlist 文件和记录。
2. 按 Edit。按钮保持按下状态，表格进入可编辑状态。
3. 双击目标单元格，修改文字；文件路径也可通过 Browse 按钮选择。编辑状态下双击不会打开该 Bout。
4. 点击其他单元格、切回主窗口或按 Enter，提交当前输入。内容与原始文本完全相同时不写文件、不增加撤销记录。Esc 放弃编辑器中尚未提交的输入。
5. 核对修改后的单元格。与本次程序运行中该文件编辑基准不同的单元格以系统强调色文字显示，选中时仍保留该颜色。
6. 需要继续核对时保持窗口打开。完成编辑后再次按 Edit 退出编辑状态；正在输入的内容先提交。

提交会立即写回原 Boutlist，不需要按主窗口 Save settings 或保存标注 SQLite。直接编辑保留输入的原始文本，不执行数值格式化或列名转换；其他单元格的文字、前导零和 JSON 文本保持不变。文件写入失败或检测到外部冲突时显示错误，不产生成功的撤销记录。

Browse 按钮用于通过可视化选定文件而实现路径的便捷准确录入，支持绝对和相对路径，相对路径按 Boutlist 所在目录解析。当前单元格内容为有效路径时将其作为起始位置，否则使用 Boutlist 所在目录作为起始位置。点击 Browse 时，当前单元格中已修改的内容会先按离开单元格的规则提交；取消选择文件不会更新单元格内容，但也不会撤销点击 Browse 前已提交的文字修改。所选路径与原文本完全相同时，不增加文件写入或撤销记录。文件选择期间发生外部修改时，仍执行原有的写入冲突检查。

**操作示例：** 将某行 review_notes 从空白改为 `Capture pair checked`，点击主窗口后该单元格已保存并以系统强调色显示。关闭 Select bout 不会丢失此修改。重新打开并开启 Edit 后，按 ↶ 可恢复空白并写回文件；回到基准值后文字恢复正常颜色。

修改当前 Bout 的元数据单元格只更新 Boutlist 及当前行定位快照，不会覆盖主窗口已载入的 Points、对齐或标定。需要读取新元数据时，执行对应的 Sync from。Open 当前行不会重新加载文件。

### 13.5.5 单元格拖拽填充

1. 开启 Edit，并单击要作为来源的单元格。
2. 将指针移到该单元格内，在右下角显示的控制点上按住左键。
3. 沿同一列上下拖动，或沿同一行左右拖动，核对预览框覆盖的目标单元格。
4. 松开后选择 Copy fill 或 Fill series；不选择则不执行填充。
5. 检查填充内容。整次填充立即保存，并可用一次 ↶ 撤销或一次 ↷ 重做。

Copy fill 将来源单元格的原始文本复制到目标格，包括前导零、浮点格式、路径和 JSON 字符串。Fill series 对普通数字按步长 1 生成序列：向下或向右递增，向上或向左递减，保留来源的前导零宽度和小数位数。其他文本按复制处理，不推断日期、文件名编号或公式规律。

**例：编号递增。** 从内容为 `003` 的单元格向下拖动两格，选择 Fill series，目标格分别写入 `004`、`005`；向上拖动则依次为 `002`、`001`。从 `1.50` 向右填充两格时，结果为 `2.50`、`3.50`。需要所有格均为 `003` 时选择 Copy fill。

当前填充使用单个来源单元格，沿行或列执行，来源本身不变。表格排序后仍按源文件行身份写入。目标内容全部相同时不写文件、不产生撤销记录；写入失败或发生外部文件冲突时不提交部分填充，也不移动撤销记录。一次成功填充只写入一次文件，并作为一项独立 Boutlist 撤销记录，不进入主窗口 History。

### 13.5.6 独立撤销与文件冲突

底部 ↶／↷ 分别表示 Undo／Redo。只有 Edit 开启且对应记录可用时按钮才启用；Ctrl + Z／Ctrl + Y 使用相同规则。正在编辑文字时，快捷键先作用于输入文字。

每个 Boutlist 文件分别保存轻量单元格记录，关闭窗口或切换 Bout 不清除；切换 Boutlist 文件时使用该文件自己的记录。退出程序后不恢复可执行撤销栈。撤销后提交新修改会清除该文件原有的重做分支。

写入前检查磁盘内容，防止依据过期行号覆盖其他程序的修改。窗口空闲时会自动读取外部变更；有未完成单元格输入时暂缓刷新。出现冲突提示后，应先结束当前输入并核对刷新后的内容，也可重新打开 Select bout 主动刷新。读取外部变更会清除过期撤销记录。撤销、重做写入失败时，记录保持原位置，不跳过失败操作。

## 13.6 写入边界与文本保留

回写只更新相应映射字段，其他列和未修改单元格的文本保持原样，例如标识 `001` 和自定义列 `1.2300` 不应因为更新 Capture 而被整体重新格式化。

完整 `scale_calibration` JSON 始终写入输出标注 SQLite。Boutlist fields 中可独立指定 `scale_px_per_cm` 与 `scale_calibration` 列名，二者可以同时启用。另可启用 `info_points`、`info_events` 和 `camera_anchor_keyframes` JSON 列。清空输入框只灰显项目标签，输入框保持可编辑；点击 Save settings（All 或 Boutlist fields） 后该项停止读写，不会清空表中已有内容。默认映射启用现有 Boutlist 中的同名列，其他项目为空；已保存的自定义映射优先。Points JSON 与单独标量字段并存时，非空的单独标量字段优先。加载标注 SQLite 时，元数据冲突仍通过原有对话框选择来源。

Events、逐帧位置、模板图像和全部 History 不在此表逐项保存。多人或多个实例同时修改同一个 CSV 时，应避免互相覆盖同一记录，并以写入前差异核对为准。

## 13.7 自动打开对应文件

Boutlist fields 中的 Auto open corresponding file 控制双向关联：打开视频时查找对应标注文件；打开标注文件时查找对应视频。视频查找使用标注来源字段、info_video 中的来源信息、检测 sidecar 和已保存 Boutlist 字段映射；有效来源路径优先。没有有效路径时，按来源文件名或去掉检测结果后缀后的同名视频查找。

查找限定在标注目录、其父目录、项目目录和上次视频目录，不递归扫描整个磁盘。只有一个候选时自动打开；多个候选时弹窗选择，取消不切换视频。没有找到时保留当前状态并在状态栏提示。自动打开视频不会再次打开标注，从而避免循环或替换刚载入的标注。

该选项关闭时，打开标注不自动切换视频。向当前审阅追加另一份标注仍要求来源属于同一视频，不根据追加文件自动切换视频。

## 13.8 典型检查

- 打开错误视频：检查映射列、当前行和路径，不先调整标注坐标。
- 某项未读入：检查映射是否空白、拼写大小写、列是否存在、值是否有效。
- 更换映射后不能直接回写：重新选择 Boutlist 记录建立新映射下的行快照。
- 回写后出现新列：确认映射填写的是原有列名，而不是另一个相似名称。
- 需要精确空间分析：读取标注 SQLite 的完整标定，不能只用 Boutlist 的平均比例。
