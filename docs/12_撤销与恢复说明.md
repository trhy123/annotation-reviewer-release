# 12 撤销与恢复说明

[返回总目录](00_操作手册.md)

## 12.1 三个不同层次

| 层次 | 内容 | 典型入口 |
| --- | --- | --- |
| 当前交互预览 | 尚未提交的点、曲线或标定修改 | Tracking、Trajectory、Continuous、Scale |
| 工作会话历史 | 已提交到当前工作数据的命令 | History → Undo / Redo |
| 持久保存与恢复 | 磁盘上标注文件、自动恢复快照、手工快照 | Save / Save as、Display → Recovery |

撤销一项命令不等于删除保存过的标注文件；恢复快照不等于自动把结果另存为标注文件。预览仍在画面上也不代表它已进入 History。

## 12.2 当前交互中的撤销

### 12.2.1 Tracking

提交前 Ctrl + Z 撤销一个自动/人工位置步骤，Ctrl + Y 重做；当前点删除和范围删除也在本会话记录。局部栈记录轻量变更，不为每一帧创建完整 History 命令。

Finish 将本次待提交结果作为一个追踪命令提交。之后 History 的一次 Undo 撤销该次提交的整体效果。Cancel 放弃本次会话，回到进入会话前工作数据。

### 12.2.2 Trajectory

编辑锚点、控制柄、重绘、平滑、重分配和变换的预览可逐步撤销。Apply 将确认的轨迹段作为一次整体修改提交；Discard 放弃预览。对同一段反复比较时，先看预览是否完成，再执行 Apply。

### 12.2.3 Change position Continuous

Continuous 会话内按步骤回退位置修改，结束会话后按已提交的会话边界管理历史。取消编辑模式与撤销此前已成功修改的点不同，退出后仍应检查工作数据和 History。

恢复快照能保存在 Change position Continuous 状态已执行的轻量操作记录及局部重做分支。恢复后仍可逐步撤销、重做；结束 Continuous 会话后按整体提交边界进入 History。尚未执行的位置输入不作为已完成的标注保存。

### 12.2.4 输入焦点

当键盘焦点位于文本框时，Ctrl + Z 可能撤销文本输入。需要撤销轨迹操作时先把焦点移到画布或使用相应 Undo 按钮。Enter、右键和 ESC 的效果由当前交互模式决定，不能把它们统一理解为保存文件。

### 12.2.5 Boutlist 编辑

Select bout 的单元格编辑使用独立撤销记录，不进入标注 History。窗口获得焦点且 Edit 开启时，↶ 或 Ctrl + Z 撤销最近一次单元格提交，↷ 或 Ctrl + Y 重做；撤销、重做均立即写回 Boutlist 文件。Edit 关闭时两个按钮灰显，单元格撤销快捷键不执行。

正在输入单元格文字时，Ctrl + Z／Ctrl + Y 优先操作编辑器内的文字。离开单元格提交后，快捷键才作用于已经保存的单元格修改。主窗口获得焦点时，仍使用主窗口原有的局部撤销和 History。

记录按 Boutlist 文件分别维护。关闭选择窗口、切换 Bout 后仍保留至退出程序；不保存到标注文件 或恢复快照。外部修改造成记录失效时须重新读取文件，过期的单元格记录不再用于覆盖新内容。浏览位置的后退、前进与上述两类编辑撤销均独立。

### 12.2.6 筛选与操作暂存

Filter 条件应用、开关及结果预览不产生标注 History。Use matched rows 仅建立精确作用域；执行 Delete 或 Change class 后，才生成一次对应修改。自动与导入人工记录混合修改时，一次撤销恢复双方，一次重做重新应用双方，不按隐藏表格行号或当前 ID／Range 重新寻找目标。

Operation stash 中建立、改名、选择、移除和恢复草稿均不修改标注，不进入标注撤销栈。Send 只填写工具输入；真正的 Interpolate、Swap、Trajectory Apply 仍遵循各自提交与撤销规则。暂存草稿及筛选状态为本次运行中的辅助状态，不替代 Recovery 或正式结果保存。

## 12.3 History 表格

表格列为 `#`、`Time`、`Op`、`IDs`、`Frames`、`Details`，分别用于核对顺序、时间、命令类型、身份、帧范围和参数摘要。点击历史项可辅助检查其涉及对象；表格选择不等于已经执行撤销。

Undo 退回当前命令栈的一步，Redo 恢复已撤销的一步。撤销后执行新的编辑可能建立新的历史分支，旧 Redo 链不能作为永久备份使用。

Save 写回当前标注文件后，当前会话的 Undo/Redo 仍可使用。关闭后重新打开标注文件，其 `history` / `history_commands` 作为只读溯源记录显示，不恢复既往命令的撤销栈；重新打开后产生的新操作仍可撤销。选择 CSV 为输出格式时导出的 `_edit_log.txt` 也只读。恢复快照另行保存会话状态，仍使用现有 `.pkl` 机制。

**规程：** 暂停并结束当前交互 → 查看最近命令的 IDs/Frames → Undo → 核对画布和表格 → 需要恢复时 Redo → 再保存。

## 12.4 Recovery 设置

入口位于 Display 的 Recovery 相关设置。

| 设置/按钮 | 作用 |
| --- | --- |
| Recovery | 启用会话恢复快照机制 |
| Recovery directory / Browse | 指定恢复数据存放目录 |
| Snapshot | 请求立即写一份自动恢复快照 |
| Save as... | 显式保存命名快照，以后手工打开 |
| Open... | 手工载入已保存的恢复快照 |

快照由后台工作完成，不应把点击 Snapshot 的时刻当作磁盘写入必已完成。恢复目录应存在且可写；网络盘断连、空间不足等情况需要检查错误状态。

这里的 Save as... 保存恢复快照；底部 Save / Save as 保存正式结果文件，两处用途不同。底部 Save as 的 CSV 选项仅导出兼容表，既不建立恢复快照，也不清除当前工程的未保存状态。

自动恢复针对非正常结束的会话；正常退出后的自动快照不应作为持久工程库使用。需要长期保留阶段状态时使用命名快照，同时保存正式标注文件。

## 12.5 异常中断恢复规程

1. 重新启动，查看是否有待恢复会话提示。
2. 核对快照关联的视频和标注来源。
3. 恢复后检查当前帧、工作行、History、关键元数据和待提交编辑。
4. 视频路径变化时先恢复正确来源，确认图片身份对应。
5. 检查最后一段操作，完成必要的 Finish/Apply 或取消。
6. 另存正式结果，避免直接把未经核对的恢复状态覆盖唯一输出。

### 12.5.1 实例：自动追踪途中进程意外退出

恢复内容可能包括已提交数据和记录在快照中的待提交追踪状态。先检查最近帧、模板和缓冲点；不要假设退出前最后看到的一帧必已写入快照。确认后继续追踪或 Finish，再保存标注文件。

### 12.5.2 实例：希望保留两种编辑方案

在分支前显式保存命名快照和标注文件。完成第一种方案另存结果，再从明确的起点载入快照做第二种方案。不要仅靠多次 Undo/Redo 代替命名版本。

### 12.5.3 画面身份核验尚未完成时保存

正式输出使用真实解码顺序的帧号。视频索引尚未完成或编辑仍带有待核验的画面引用时，Save / Save as 会等待索引与编辑记录协调完成，再继续保存；等待本身不表示文件已写入。恢复快照后的旧画面引用也必须完成这一检查。

出现 `Frame mapping pending` 时，检查提示中的错误及 Display → Decoder 的 FFprobe 路径。修正后再次点击 Save / Save as 可重试失败的索引任务；不能通过另选输出文件名跳过画面身份核验。

需要在问题解决前保留工作时，先暂停自动追踪；轨迹曲线预览应先 Apply，或者明确放弃。随后使用 Display → Others → Manual snapshot → Save as... 保存命名 `.pkl`，等待 `Snapshot saved`。Continuous 已执行的步骤和局部撤销记录可以随快照保留，不必仅为备份而结束会话。该操作不要求启用 Recovery，也不生成正式的标注文件。恢复快照后仍应完成索引协调、核对数据并保存正式结果。

## 12.6 限制与核对

恢复依赖可读取的视频和源数据；快照不能重建已经丢失的视频图片。图层缓存用于加速显示，不能替代恢复快照；清除或更换显示缓存不应被用作撤销操作。正式输出以保存成功并可重新打开核对的标注文件为准。
